当爬虫学会“思考”：2026 数据采集的 AI 觉醒与工程突围

Posted on 2026-11-26

2026 年的 Web 生态已和五年前不是同一个物种：AIGC 让页面结构越来越“非标”，反爬从 IP 封禁升级到硬件级指纹与行为建模，改版速度远超选择器的寿命。硬编码规则的爬虫正集体陷入维护泥潭，而 LLM 与 Agent 又在重构采集的底层逻辑。本文不谈概念，只谈落地：哪些活该交给模型，哪些活必须留在工程底座上。

一、范式转移：为什么旧脚本集体失效

爬虫技术的每一次迭代，都对应 Web 侧的一次“反制”。今天的压力来自三处：

  1. 页面结构不再稳定。模板化站点大量减少，同一业务的不同页面可能由不同框架渲染，甚至由 AI 动态生成布局，CSS/XPath 的路径假设随时作废。
  2. 风控进入硬件级。TLS、Canvas/WebGL、字体指纹构成环境画像，鼠标轨迹、滚动节奏构成行为画像，“改个 UA”早已没有意义。
  3. 维护成本指数上升。中等规模项目里，选择器维护常占全部工作量的 60% 以上，每次改版都是一次线上事故。

传统爬虫的本质是把对页面结构的假设写死在代码里，假设一变，代码即失效。AI 带来的变化，是把这份假设从“代码”搬进了“模型”——由模型在运行时理解语义，而不是由开发者预先猜测 DOM。

二、AI 觉醒：让模型承担决策

2.1 LLM 语义化提取

最直接的做法：不再写选择器，而是把精简后的 HTML（或页面截图）交给大模型，用结构化 Prompt 让它输出 JSON。它对 DOM 微调有极强鲁棒性，因为模型看的是“这是一张商品卡，标题在这、价格在那”，而不是 div.list > div:nth-child(3) > span。

三个必须正视的代价：Token 成本（先做 HTML 清洗，去 script/style/注释、只留有文本的节点，通常能压到原始体积的 10%~20%）、延迟（单页百毫秒到数秒，不适合高频采集）、幻觉（实测约 5% 的字段会“编造”或错位）。所以生产环境必须用 Pydantic 做类型与范围校验，校验失败的记录进人工复核队列，而不是直接入库。

2.2 智能体与代码自动生成

第二层变化发生在“写代码”本身。给出目标 URL 与字段需求，AI 编程助手即可产出含请求头、选择器、重试与反爬处理的完整脚本，报错后再自行定位、修改、重跑，一次性任务的效率提升是数量级的。

更进一步的是 AI 原生浏览器框架（Stagehand、Lightpanda）——只需声明意图，例如“登录后导出近 30 天订单”，浏览器结合 DOM 快照与视觉信息自主决定等待、滚动、点击、翻页，几十行交互脚本被压缩成一句话。

2.3 边界：什么时候不该用 AI

AI 不是万能药。高频、结构稳定、字段明确的页面用 LLM 提取属于高射炮打蚊子：成本高、延迟大、还不如 lxml 稳定。它真正的甜区是高价值低频的定向数据、频繁改版的长期维护型站点、一次性抓取与原型验证，以及长文这类非结构化内容的字段化。判断标准只有一句：当规则维护成本大于模型调用成本时，才轮到语义提取上场。

三、工程突围：工业级底座仍是基石

在大规模、高并发、严苛反爬的工业场景，传统框架不但没被取代，反而形成了更清晰的分层技术栈。

3.1 基础层：轻量静态抓取

requests/httpx + lxml 是性能天花板最高的一层，lxml 的解析速度通常比 BeautifulSoup 快 5 倍以上，能用 lxml 就别用 bs4，适用于结构稳定的静态 HTML、已逆向成功的接口与小批量数据。关键实践：显式设置 timeout 与重试退避；请求头按真实浏览器的顺序构造（User-Agent、Accept、Accept-Language、Sec-Fetch-* 的顺序本身也是指纹）。

3.2 渲染层：动态渲染与复杂交互

Playwright 已全面替代 Selenium：多内核（Chromium/Firefox/WebKit）、内置自动等待、内存占用更低，配合 playwright-stealth 还能隐藏 navigator.webdriver 等自动化特征，适用于 SPA、强反爬站点与需要模拟登录/表单/点击翻页的复杂交互。关键实践：默认不渲染，只在必要请求上显式开启；上下文池化复用，避免每请求新建带来的内存泄漏。

3.3 调度层：规模化与分布式

Scrapy 仍是批量采集的主流选择：内置异步并发、请求队列、自动去重与 Item Pipeline，配合 scrapy-redis 把调度器与去重集合外置即可多机分布式。追求极致吞吐时，Go 的 Colly 单机每分钟可处理 2~3 万静态页面，静态编译、内存占用低，已是企业级采集的常见底座。

3.4 混合架构：让快任务别等慢任务

最实用的生产形态是“Scrapy 管调度与存储 + Playwright 管渲染”：

要点是把两类请求拆成两条队列：HTTP 请求走高优先级、高并发；渲染请求走独立低并发队列，并限制单域名的浏览器上下文数量，防止慢任务把快任务堵死。

四、对抗与合规：成本已经工程化

今天的反爬已是“网络层—环境层—行为层—业务层”的四层矩阵：TLS 指纹能识别绝大多数未打补丁的客户端，数据中心 IP 被系统性封禁，鼠标轨迹与停留时长被用于机器人判定。对抗侧同样是体系化应对：

  • 网络层：curl-impersonate 在 TLS/HTTP2 层模拟 Chrome/Firefox 特征；高隐匿场景可选 Camoufox（Firefox 内核的反检测补丁版）；代理必须走住宅或移动出口，并用粘性会话保证多步骤流程中的身份一致。
  • 环境层：完整随机化浏览器指纹（Canvas、WebGL、时区、语言、字体），而不是只伪装 UA。
  • 行为层：模拟人类行为序列——非匀速滚动、随机停顿、合理的点击热区分布。

但技术能做的，不等于可以做的。合规底线要写进工程规范：只采集公开可访问数据、遵守 robots.txt、控制频率不影响对方服务、绝不绕过身份验证与付费墙、严禁采集个人敏感信息；并建立采集白名单与日志审计，把合规做成可追溯的流程，而不是口头承诺。

五、技术选型决策矩阵

业务场景 推荐技术栈 核心理由
静态页面、小批量 requests/httpx + lxml 轻量、快速、性能天花板最高
大规模、中等反爬 Scrapy（+ scrapy-redis） 工业级并发、内置去重与管道、易分布式
强反爬、动态渲染 Playwright + stealth 插件 JS 渲染完备、多内核、特征伪装
复杂交互、多步流程 Playwright + 住宅/移动代理 模拟真实用户行为、突破 IP 封锁
页面频繁变动、非结构化 LLM 语义提取 / AI Agent 语义理解、抗 DOM 结构变化
快速开发、低代码 AI 编程助手（Claude Code 等） 自然语言生成代码、报错自愈
超大规模、极致性能 Go Colly / Rust reqwest 高并发、低内存、静态编译部署

选型只需记住三句话：能用接口解决的绝不开浏览器；能用传统解析的绝不碰 AI；只有当规则维护成本超过模型调用成本时，才考虑语义提取。

结语：爬虫工程师的能力重构

2026 年的爬虫工程师，正从“规则编写者”转型为“对抗体系搭建者 + AI 采集架构师 + 合规风控负责人”，技能重心从“选择器怎么写”迁移到“Prompt 怎么设计、系统怎么分层、风险怎么兜底”。

两者不是替代关系，而是分层互补：高频稳定的核心数据继续跑在 Scrapy/Playwright 底座上，长尾多变的边缘数据交给 LLM 与 Agent。真正的分水岭不在用了什么模型，而在是否把“采集”当成有 SLO、有可观测性、有合规边界的工程系统来建设。落地路径也很清楚：先补齐监控、重试与校验，再把 AI 提取以旁路接入、只处理失败样本，最后才放大语义提取的流量占比。先稳住，再智能——这是 2026 年最务实的采集哲学。
