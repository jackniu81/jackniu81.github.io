设计模式 常见面试题（附答案）

设计模式基础

1. 什么是设计模式？有哪些分类？

答案： 设计模式是针对软件设计中常见问题的可复用解决方案，由 GoF（Gang of Four）整理为 23 种。三大分类：① 创建型（对象创建方式）：单例、工厂、抽象工厂、建造者、原型；② 结构型（类和对象的组合方式）：适配器、装饰器、代理、外观、桥接、组合、享元；③ 行为型（对象间的通信和职责分配）：观察者、策略、命令、迭代器、状态、模板方法、责任链、中介者、备忘录、访问者、解释器。

2. 什么是 SOLID 原则？

答案：

  • S（单一职责）：每个类只有一个引起变化的原因
  • O（开闭原则）：对扩展开放，对修改关闭（新功能通过扩展而非修改实现）
  • L（里氏替换）：子类可以替换父类使用而不改变程序正确性
  • I（接口隔离）：接口应细化，客户端不应依赖不需要的接口
  • D（依赖倒置）：高层模块不依赖低层模块，都依赖抽象；抽象不依赖细节，细节依赖抽象

创建型模式

3. 什么是单例模式？前端有哪些应用？

答案： 保证一个类只有一个实例，提供全局访问点。实现：

class Singleton {
  static #instance = null;
  constructor() {
    if (Singleton.#instance) return Singleton.#instance;
    Singleton.#instance = this;
  }
  static getInstance() {
    return Singleton.#instance ?? new Singleton();
  }
}

// 模块级单例（更 JS 化的方式）
let instance = null;
export function createStore() {
  if (!instance) instance = { state: {}, ...methods };
  return instance;
}

前端应用：全局状态管理（Vuex/Pinia store）、事件总线、日志记录器、WebSocket 连接管理。

4. 什么是工厂模式？

答案： 工厂模式封装对象创建逻辑，调用方不需要知道具体创建细节。简单工厂：

function createButton(type) {
  const types = {
    primary: PrimaryButton,
    danger: DangerButton,
    ghost: GhostButton,
  };
  const Constructor = types[type];
  if (!Constructor) throw new Error(`Unknown type: ${type}`);
  return new Constructor();
}

工厂方法模式：将创建方法定义在父类中，子类决定实例化哪个类。抽象工厂：创建一系列相关对象（如 UI 主题工厂，同时创建按钮、输入框等配套组件）。

5. 什么是建造者模式（Builder）？

答案： 分步骤构建复杂对象，将构建过程与表示分离。常见形式是链式调用：

class QueryBuilder {
  #query = { table: '', conditions: [], limit: null };

  from(table) { this.#query.table = table; return this; }
  where(condition) { this.#query.conditions.push(condition); return this; }
  limitTo(n) { this.#query.limit = n; return this; }
  build() { return { ...this.#query }; }
}

const query = new QueryBuilder().from('users').where('age > 18').limitTo(10).build();

前端应用：复杂表单配置、查询参数构建、测试数据 Builder、Axios 请求封装。

结构型模式

6. 什么是代理模式？前端有哪些应用？

答案： 代理对象控制对真实对象的访问，可以在访问前后添加额外逻辑（权限、缓存、日志）。

// ES6 Proxy 实现
function createProxy(target) {
  return new Proxy(target, {
    get(obj, key) {
      console.log(`Getting ${key}`);
      return obj[key];
    },
    set(obj, key, value) {
      console.log(`Setting ${key} = ${value}`);
      obj[key] = value;
      return true;
    }
  });
}

前端应用：Vue 3 响应式系统（Proxy 追踪依赖）、图片懒加载代理、接口缓存代理（同参数请求复用）、权限控制代理。

7. 什么是装饰器模式？和继承的区别？

答案： 装饰器在不修改原类的情况下，通过包装对象添加新功能，运行时动态增强，可叠加多个装饰器：

// 函数装饰器（高阶函数）
function withLogging(fn) {
  return function(...args) {
    console.log(`Calling ${fn.name} with`, args);
    const result = fn.apply(this, args);
    console.log(`Result:`, result);
    return result;
  };
}

function withCache(fn) {
  const cache = new Map();
  return function(...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

const enhanced = withLogging(withCache(fetchUser));

区别：继承是编译期静态的，装饰器是运行时动态的，更灵活（可组合、可选择）。

8. 什么是适配器模式？

答案： 适配器将一个接口转换为客户端期望的另一个接口，解决接口不兼容问题：

// 旧的 XML API 适配为新的 JSON API
class XMLDataAdapter {
  constructor(xmlDataSource) {
    this.xmlDataSource = xmlDataSource;
  }
  getData() {
    const xmlData = this.xmlDataSource.fetchXML();
    return this.parseXMLToJSON(xmlData); // 转换格式
  }
  parseXMLToJSON(xml) { /* ... */ }
}

// 前端常见：第三方 SDK 封装（统一接口，底层可切换）
class AnalyticsAdapter {
  track(event, data) {
    if (isGoogleAnalytics) ga('send', event, data);
    else if (isMixpanel) mixpanel.track(event, data);
  }
}

9. 什么是外观模式（Facade）？

答案： 外观模式为复杂子系统提供简化的统一接口，隐藏内部复杂性。前端常见示例：

// 封装复杂的浏览器存储逻辑
class StorageFacade {
  get(key) {
    try {
      return JSON.parse(localStorage.getItem(key));
    } catch {
      return null;
    }
  }
  set(key, value, ttl) {
    localStorage.setItem(key, JSON.stringify({ value, expires: Date.now() + ttl }));
  }
  clear() { localStorage.clear(); }
}

前端应用：SDK 对外 API 设计、复杂工具库的简化封装（如封装 Axios 的请求工厂）。

行为型模式

10. 什么是观察者模式？和发布订阅的区别？

答案： 观察者模式：Subject（主题）直接持有 Observer 列表，状态变化时直接通知：

class EventEmitter {
  #listeners = new Map();
  on(event, fn) {
    if (!this.#listeners.has(event)) this.#listeners.set(event, []);
    this.#listeners.get(event).push(fn);
    return () => this.off(event, fn); // 返回取消订阅函数
  }
  emit(event, data) { this.#listeners.get(event)?.forEach(fn => fn(data)); }
  off(event, fn) {
    this.#listeners.set(event, this.#listeners.get(event)?.filter(f => f !== fn) ?? []);
  }
}

发布订阅模式：引入事件总线（Message Broker），发布者和订阅者完全解耦，互不知晓对方。观察者模式耦合度更高，发布订阅解耦更彻底（跨模块通信用发布订阅）。

11. 什么是策略模式？

答案： 策略模式定义一系列算法，将它们封装为独立对象，可以互换使用，消除大量 if-else：

const validators = {
  required: (value) => !!value || '必填',
  email: (value) => /\S+@\S+\.\S+/.test(value) || '邮箱格式错误',
  minLength: (min) => (value) => value.length >= min || `最少 ${min} 个字符`,
};

function validate(value, rules) {
  return rules.map(rule => {
    const fn = typeof rule === 'function' ? rule : validators[rule];
    return fn(value);
  }).filter(result => result !== true);
}

// 使用
const errors = validate('abc', ['required', validators.email, validators.minLength(8)]);

前端应用：表单验证策略、排序策略、权限策略、动画缓动函数。

12. 什么是命令模式？

答案： 将操作封装为对象，支持排队执行、撤销（undo）/重做（redo）、宏命令：

class CommandManager {
  #history = [];
  #future = [];

  execute(command) {
    command.execute();
    this.#history.push(command);
    this.#future = []; // 执行新命令清空重做栈
  }
  undo() {
    const command = this.#history.pop();
    if (command) { command.undo(); this.#future.push(command); }
  }
  redo() {
    const command = this.#future.pop();
    if (command) { command.execute(); this.#history.push(command); }
  }
}

前端应用：富文本编辑器（撤销/重做）、表单多步操作、Canvas 绘图工具。

13. 什么是迭代器模式？

答案： 提供一种统一方式顺序访问集合元素，不暴露内部结构。ES6 的 Iterator 协议是该模式的标准实现：

class Range {
  constructor(start, end) { this.start = start; this.end = end; }
  [Symbol.iterator]() {
    let current = this.start;
    return {
      next: () => current <= this.end
        ? { value: current++, done: false }
        : { value: undefined, done: true }
    };
  }
}

for (const n of new Range(1, 5)) console.log(n); // 1 2 3 4 5
// Generator 是创建迭代器的语法糖
function* range(start, end) {
  for (let i = start; i <= end; i++) yield i;
}

14. 什么是状态模式？

答案： 将对象在不同状态下的行为封装到独立状态类中，状态切换时改变行为，消除大量状态判断：

// 订单状态机
const OrderStates = {
  pending: {
    pay: (order) => { order.setState('paid'); },
    cancel: (order) => { order.setState('cancelled'); },
  },
  paid: {
    ship: (order) => { order.setState('shipped'); },
    refund: (order) => { order.setState('refunding'); },
  },
  shipped: {
    complete: (order) => { order.setState('completed'); },
  },
};

class Order {
  #state = 'pending';
  setState(state) { this.#state = state; }
  do(action) { OrderStates[this.#state]?.[action]?.(this) ?? console.log('非法操作'); }
}

15. 什么是模板方法模式？

答案： 在父类中定义算法骨架（步骤顺序），子类实现具体步骤，不改变整体结构：

class DataProcessor {
  // 模板方法
  process(data) {
    const parsed = this.parse(data);    // 步骤1：解析
    const filtered = this.filter(parsed); // 步骤2：过滤
    return this.format(filtered);         // 步骤3：格式化
  }
  parse(data) { return data; }          // 默认实现
  filter(data) { return data; }
  format(data) { throw new Error('必须实现 format'); } // 抽象方法
}

class CSVProcessor extends DataProcessor {
  parse(data) { return data.split('\n').map(row => row.split(',')); }
  format(data) { return data.map(row => ({ name: row[0], value: row[1] })); }
}

前端特有模式

16. 什么是 Flux / Redux 模式？

答案： Flux 是单向数据流架构模式：Action → Dispatcher → Store → View → Action...。Redux 是 Flux 的改进实现：单一 Store，纯函数 Reducer（(state, action) => newState），不可变数据。核心价值：状态变化可预测、可追踪（时间旅行调试）、易于测试。适合复杂状态管理，简单应用过度设计。

17. 什么是高阶组件（HOC）模式？

答案： 高阶组件是接收组件、返回新组件的函数，用于复用组件逻辑（横切关注点）：

function withAuth(WrappedComponent) {
  return function AuthWrapper(props) {
    const { isLoggedIn } = useAuth();
    if (!isLoggedIn) return <Redirect to="/login" />;
    return <WrappedComponent {...props} />;
  };
}

function withLoading(WrappedComponent) {
  return function LoadingWrapper({ isLoading, ...props }) {
    if (isLoading) return <Spinner />;
    return <WrappedComponent {...props} />;
  };
}

const ProtectedPage = withAuth(withLoading(UserDashboard));

现代 React 中 Hook 可替代大部分 HOC 场景，但 HOC 在错误边界等场景仍有用。

18. 什么是 Render Props 模式？

答案： 通过 prop 传入一个函数（返回 JSX），让组件可以共享内部状态：

function Mouse({ render }) {
  const [position, setPosition] = useState({ x: 0, y: 0 });
  return (
    <div onMouseMove={e => setPosition({ x: e.clientX, y: e.clientY })}>
      {render(position)}
    </div>
  );
}

// 使用
<Mouse render={({ x, y }) => <Cursor x={x} y={y} />} />

现代 React 中大部分 Render Props 场景可用自定义 Hook 代替，更简洁。

19. 什么是组合（Composition）优于继承？

答案： 继承的问题：深层继承链脆弱（修改父类影响所有子类）、多重继承困难、功能绑定死板。组合通过将行为组合进对象（注入或混入），更灵活：

// 继承方式
class FlightAnimal extends Animal { fly() {} }
class SwimmingAnimal extends Animal { swim() {} }
// 问题：会飞又会游泳的动物怎么继承？

// 组合方式
const canFly = { fly: () => '飞翔' };
const canSwim = { swim: () => 游泳 };
const duck = { ...canFly, ...canSwim, name: '鸭子' }; // 自由组合

React Hook 就是"功能组合"的最佳体现：useAuth() + useForm() + useDebounce() 按需组合，而非深层继承。

20. 什么是依赖注入（DI）？

答案： 依赖注入是控制反转（IoC）的一种实现：对象不自己创建依赖，而是由外部注入。好处：解耦、易于测试（注入 Mock）、易于替换实现。

// 不好：硬依赖
class UserService {
  private db = new MySQLDatabase(); // 无法测试/替换
}

// 好：依赖注入
class UserService {
  constructor(private db: IDatabase) {} // 注入接口，可替换
}

// 测试时注入 Mock
const service = new UserService(new MockDatabase());
// NestJS 中由 IoC 容器自动注入

总结

这些设计模式题目覆盖了 SOLID 原则、创建型/结构型/行为型经典模式，以及前端特有的 HOC、Render Props、组合模式和依赖注入，注重与实际前端框架的关联，适合面试系统复习。
