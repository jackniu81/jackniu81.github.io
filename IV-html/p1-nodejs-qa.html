Node.js 常见面试题（附答案）

基础与运行原理

1. Node.js 是什么？核心特点有哪些？

答案： Node.js 是基于 Chrome V8 引擎的 JavaScript 运行时，让 JS 能在服务端运行。核心特点：① 单线程 + 事件驱动；② 非阻塞 I/O（异步）；③ 高并发处理能力（适合 I/O 密集型）；④ npm 生态极其丰富；⑤ 前后端同语言，利于全栈开发。不适合 CPU 密集型任务（会阻塞事件循环）。

2. Node.js 的事件循环与浏览器有什么区别？

答案： Node.js 事件循环（基于 libuv）有多个阶段（按顺序）：① timers（setTimeout/setInterval 回调）；② pending callbacks（I/O 错误回调）；③ idle/prepare（内部使用）；④ poll（等待 I/O 事件）；⑤ check（setImmediate 回调）；⑥ close callbacks（关闭事件）。特有 API：process.nextTick（优先级最高，在当前操作完成后、下一阶段前执行）；setImmediate（check 阶段，晚于 setTimeout(fn, 0)）。

3. process.nextTick 和 setImmediate 的区别？

答案： process.nextTick 在当前事件循环阶段结束时立即执行（在所有 I/O 和微任务之前），优先级最高，滥用可能饿死 I/O；setImmediate 在事件循环的 check 阶段执行，在 I/O 回调之后。执行顺序：process.nextTick > Promise 微任务 > setImmediate > setTimeout(fn, 0)（在 I/O 回调中 setImmediate 总是先于 setTimeout）。

4. Node.js 如何处理高并发？

答案： Node.js 用单线程 + 非阻塞 I/O + 事件循环处理并发：I/O 操作（文件、网络、数据库）交由 libuv 线程池或操作系统异步处理，主线程继续处理其他请求；I/O 完成后将回调加入事件队列。因此大量并发 I/O 请求不会互相阻塞。但 CPU 密集操作会阻塞事件循环，需用 worker_threads 或子进程处理。

5. Node.js 的模块系统有哪些？有什么区别？

答案： ① CommonJS（默认，.js 文件）：require/module.exports，同步加载，运行时解析，require 有缓存（首次加载后缓存）；② ES Module（.mjs 或 package.json 中 "type": "module"）：import/export，异步静态分析，支持 Tree Shaking，是未来标准。现代 Node.js（16+）支持 ESM，但与 CJS 互操作有限制（不能在 CJS 中 require ESM）。

6. CommonJS 的模块缓存机制是什么？

答案： Node.js 在首次 require 一个模块时，将其导出对象缓存在 require.cache 中。后续 require 同一模块路径直接返回缓存，不重新执行模块代码。这意味着模块中的状态（变量、连接）是单例的，单元测试时可能需要清除缓存（delete require.cache[modulePath]）。循环依赖时会返回部分加载的对象。

核心模块

7. fs 模块有哪些常用 API？同步和异步如何选择？

答案： 常用 API：fs.readFile/writeFile/appendFile/unlink/mkdir/stat/readdir（异步回调版），加 Sync 后缀为同步版，fs.promises.* 为 Promise 版。选择原则：服务端代码用异步（避免阻塞事件循环）；脚本/CLI 工具可用同步（代码更简洁，无并发压力）。推荐 fs.promises + async/await 组合。

8. path 模块的常用方法有哪些？

答案：

  • path.join(...segments)：拼接路径（自动处理斜杠）
  • path.resolve(...segments)：解析为绝对路径（从右向左解析）
  • path.dirname(p)：获取目录部分
  • path.basename(p, ext)：获取文件名部分
  • path.extname(p)：获取扩展名
  • path.parse(p) / path.format(obj)：路径字符串与对象互转
  • __dirname（CJS）/ import.meta.dirname（ESM）：当前文件目录

9. stream 流有哪些类型？什么场景使用？

答案： 四种类型：① Readable（可读流，如 fs.createReadStream）；② Writable（可写流，如 fs.createWriteStream）；③ Duplex（双工流，如 TCP socket）；④ Transform（转换流，如 zlib 压缩/解密）。适用场景：处理大文件（避免一次性加载进内存）、HTTP 请求/响应、管道数据处理（readable.pipe(transform).pipe(writable)）。stream.pipeline 比 pipe 更安全（自动处理错误和清理）。

10. EventEmitter 的使用和注意事项？

答案：

const EventEmitter = require('events');
const emitter = new EventEmitter();
emitter.on('data', handler);
emitter.emit('data', payload);
emitter.once('close', handler); // 只触发一次
emitter.off('data', handler);  // 移除监听

注意：① 默认最多 10 个监听器（超出警告，用 setMaxListeners 调整）；② 必须监听 error 事件，否则会抛出未捕获异常；③ 同步触发（emit 时同步执行所有监听器）；④ 内存泄漏常见原因：监听器未移除。

11. http 模块如何创建服务器？

答案：

const http = require('http');
const server = http.createServer((req, res) => {
  const { method, url, headers } = req;
  let body = '';
  req.on('data', chunk => body += chunk);
  req.on('end', () => {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ method, url, body }));
  });
});
server.listen(3000, () => console.log('Server running on port 3000'));

实际项目通常用 Express/Fastify/Koa 封装，而非直接使用原生 http。

12. 什么是 Buffer？什么时候用？

答案： Buffer 是 Node.js 处理二进制数据的核心类，类似 Uint8Array。用于处理 TCP 流、文件系统操作、加密、图片处理等二进制场景。常用：Buffer.from('hello', 'utf8')（字符串转 Buffer）、buf.toString('utf8')（Buffer 转字符串）、Buffer.alloc(size)（创建指定大小的零填充 Buffer）。注意 Buffer.allocUnsafe 速度快但不清零，不安全用于密码学。

框架与工程

13. Express 的中间件机制是什么？

答案： Express 中间件是函数，签名 (req, res, next) => void。请求到达时按注册顺序依次执行，每个中间件通过调用 next() 传递控制权，或直接发送响应终止链。错误中间件签名为 (err, req, res, next)，next(err) 触发。常见中间件：日志（morgan）、解析请求体（express.json）、鉴权、CORS、静态文件。洋葱模型：Koa 使用 async/await 的"洋葱圈"模型（中间件可以在请求前后执行代码）。

14. Express 和 Koa 的区别是什么？

答案： Express：同步中间件（回调风格），内置路由和多种功能，生态最成熟，入门简单；错误处理需传 next(err)。Koa：由 Express 原班人马创作，精简内核（无内置路由等），中间件基于 async/await，洋葱模型（await next() 后可执行后续逻辑），错误处理更优雅（try/catch + ctx.app.emit('error')）。NestJS 是在 Express/Fastify 上的完整框架，提供 IoC、模块化、装饰器等能力，适合大型项目。

15. 什么是 NestJS？它的核心概念有哪些？

答案： NestJS 是基于 TypeScript 的渐进式 Node.js 框架，深受 Angular 启发。核心概念：① Module（模块，组织代码边界）；② Controller（路由处理，@Get/@Post 等装饰器）；③ Service（业务逻辑，通过 DI 注入）；④ Provider（注入的任何服务/仓库）；⑤ Guard（权限守卫）；⑥ Interceptor（拦截器，类似 Axios 拦截器）；⑦ Pipe（数据转换和验证，class-validator）；⑧ Middleware（与 Express 中间件兼容）。

16. 如何在 Node.js 中进行错误处理？

答案： ① 同步代码：try/catch；② 异步回调：回调第一个参数约定为 err；③ Promise：.catch() 或 async/await + try/catch；④ 全局未捕获：process.on('uncaughtException', handler)（严重错误，记录日志后应退出进程）；process.on('unhandledRejection', handler)（Promise 未捕获）；⑤ Express 错误中间件：(err, req, res, next)；⑥ 生产建议：用 PM2/cluster + 进程守护，异常时自动重启。

17. Node.js 中如何使用环境变量？

答案： 通过 process.env.VAR_NAME 访问。开发时使用 .env 文件配合 dotenv 库（require('dotenv').config()）加载。生产环境通过系统环境变量、Docker ENV、Kubernetes ConfigMap 注入，不应将 .env 提交到版本库（加入 .gitignore）。@nestjs/config 封装了 NestJS 中的配置管理。

性能与部署

18. 如何利用多核 CPU？

答案： Node.js 单进程单线程，默认只用一个 CPU 核。利用多核方案：① cluster 模块：主进程 fork 多个子进程（一般等于 CPU 核数），共享端口，各自处理请求；② worker_threads：在同一进程内创建线程，共享内存（SharedArrayBuffer），适合 CPU 密集任务；③ PM2：生产环境常用进程管理器，pm2 start app.js -i max 自动按 CPU 核数启动集群。

19. 如何排查 Node.js 内存泄漏？

答案： ① 监控内存：process.memoryUsage() 或 PM2 监控面板；② 生成堆快照：v8.writeHeapSnapshot() 或 Chrome DevTools（连接 --inspect）；③ 对比多次堆快照，找到持续增长的对象；④ 常见原因：全局变量积累、闭包引用、事件监听器未移除、定时器未清理、缓存无限增长；⑤ 工具：clinic.js（诊断）、heapdump、memwatch-next。

20. PM2 有哪些常用命令和特性？

答案：

pm2 start app.js --name myapp   # 启动
pm2 start app.js -i max         # 集群模式（按 CPU 核数）
pm2 list                         # 查看进程
pm2 logs myapp                   # 查看日志
pm2 restart/stop/delete myapp    # 重启/停止/删除
pm2 monit                        # 实时监控
pm2 startup                      # 设置开机自启
pm2 save                         # 保存当前进程列表

特性：进程守护（崩溃自动重启）、日志管理、集群管理、热重载（pm2 reload，零停机更新）、监控面板。

21. 什么是 Node.js 的 --inspect 调试模式？

答案： 启动时加 --inspect 或 --inspect-brk（在第一行暂停）开启调试端口（默认 9229）。然后可以用 Chrome DevTools（chrome://inspect）或 VSCode 连接，进行断点调试、内存分析、CPU 性能分析。--inspect-brk 适合调试启动时的问题。生产环境谨慎开启，注意端口安全。

22. 如何实现 Node.js 的优雅退出（Graceful Shutdown）？

答案：

process.on('SIGTERM', async () => {
  console.log('Received SIGTERM, graceful shutdown...');
  server.close(async () => {      // 停止接受新连接
    await db.disconnect();         // 关闭数据库连接
    await redis.quit();            // 关闭 Redis 连接
    process.exit(0);
  });
  // 超时强制退出
  setTimeout(() => process.exit(1), 30000);
});

优雅退出：收到信号后停止接受新请求，等待进行中的请求完成，清理资源（DB 连接、消息队列），然后退出。Kubernetes 部署时 SIGTERM 是 Pod 终止信号，必须处理。

生态与工具

23. npm、yarn、pnpm 的区别？

答案： npm：Node.js 官方包管理器，v7+ 支持 workspaces，但 node_modules 扁平化有幽灵依赖问题；yarn（v1）：并行下载更快，有 yarn.lock，目前维护模式；yarn（v2/3/4）：PnP（Plug'n'Play）模式，无 node_modules，启动极快；pnpm：硬链接 + 符号链接共享依赖，节省磁盘，严格依赖隔离（无幽灵依赖），monorepo 支持好，现代项目首选。

24. 什么是 Monorepo？常用工具有哪些？

答案： Monorepo 是将多个项目/包放在同一 Git 仓库的管理方式。优点：跨包共享代码、统一构建流程、原子化提交（多包联动修改一次提交）、便于重构。常用工具：① pnpm workspaces（包管理）；② Turborepo（任务编排、构建缓存，最快）；③ Nx（功能更丰富，有代码生成器、依赖图分析）；④ Lerna（较老，现配合 nx 使用）。

25. Node.js 中如何处理大文件上传？

答案： ① 流式处理：直接 pipe 到存储，不在内存中积累完整文件（multer 的 diskStorage、或自定义 busboy 流处理）；② 分片上传：前端将文件切分为小块（File.slice()）分别上传，服务端接收后合并，支持断点续传；③ 直传云存储：服务端生成预签名 URL，前端直接上传到 OSS/S3，减轻服务器压力。注意设置请求体大小限制（express.json({ limit: '10mb' })）。
