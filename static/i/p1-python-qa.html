Python 基础

1. 什么是 Python？

答案： Python 是一种高级、解释型、通用的编程语言，以简洁易读、生态丰富和强大的社区支持著称。

2. Python 是解释型语言还是编译型语言？

答案： Python 是解释型语言，源代码首先被编译为字节码，然后由 Python 虚拟机（PVM）解释执行。

3. Python 的 GIL 是什么？

答案： GIL 是全局解释器锁（Global Interpreter Lock），是 CPython 解释器的特性，用于保证同一时刻只有一个线程执行 Python 字节码，因此多线程无法充分利用多核 CPU。

  • CPU 密集型任务：多线程无法并行，只有一个核在跑，推荐用多进程（multiprocessing）绕过 GIL；
  • IO 密集型任务：线程在等待 IO（网络、磁盘）时会主动释放 GIL，其他线程可以继续执行，所以多线程依然能明显提升效率。

4. 什么是 Python 的浅拷贝和深拷贝？

答案：

  • 浅拷贝 copy.copy()：只复制最外层对象，内部的子对象仍然共用同一个引用，修改子对象会互相影响；
  • 深拷贝 copy.deepcopy()：递归复制所有层级的对象，新旧对象完全独立、互不影响。

列表的 list.copy()、切片 a[:]、a * 2 都只是浅拷贝。

5. is 和 == 有什么区别？

答案： == 比较值是否相等，is 比较对象在内存中的身份标识是否相同。

6. Python 中可变类型和不可变类型有哪些？

答案： 可变类型：list、dict、set；不可变类型：int、float、str、tuple、bool、frozenset。

7. 列表和元组的区别是什么？

答案：

对比项 list tuple
可变性 可变，支持增删改 不可变，创建后不能修改元素
语法 [] ()
作为 dict 的 key 不行（不可哈希） 可以（元素均可哈希时）
内存/性能 较大，需预留扩容空间 更小，遍历更快，有缓存复用优化
语义 一组「可能会变」的同类数据 一组「固定不变」的结构化数据，如坐标、数据库一行记录

函数 return a, b 底层其实就是返回一个元组。

8. 什么是列表推导式？

答案： 列表推导式是简洁创建列表的语法，例如 [x*2 for x in range(10) if x % 2 == 0]。

9. *args 和 **kwargs 的作用是什么？

答案：

  • *args：接收不定数量的位置参数，在函数内部打包成元组；
  • **kwargs：接收不定数量的关键字参数，在函数内部打包成字典。

常用于函数封装和装饰器透传参数，兼容数量不确定的入参；调用时用 *、** 对序列/字典做解包。

10. 什么是 Python 的装饰器？

答案： 装饰器是一种高阶函数，用于在不修改原函数代码的前提下，扩展函数的功能（如日志、计时、缓存、权限校验、重试）。本质是 func = decorator(func) 的语法糖。

import time

def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        res = func(*args, **kwargs)
        print(f"耗时：{time.time() - start:.2f}s")
        return res
    return wrapper

@timer
def test():
    time.sleep(0.1)

11. 什么是 Lambda 表达式？

答案： Lambda 表达式是匿名函数，语法为 lambda x: x + 1，适用于简单的临时函数场景。

12. Python 中如何实现闭包？

答案： 闭包是指内部函数引用了外部函数的变量，并且外部函数返回了内部函数，内部函数保留对外部变量的引用。

13. map()、filter() 和 reduce() 有什么区别？

答案： map() 对可迭代对象每个元素执行函数，filter() 按条件过滤，reduce() 对序列累积计算。

14. 什么是 Python 的迭代器和生成器？

答案： 迭代器实现 __iter__ 和 __next__ 方法；生成器使用 yield 关键字，可惰性生成值，节省内存。

15. yield 和 return 的区别是什么？

答案： return 一次性返回结果并结束函数；yield 会暂停函数，保留状态，可多次返回结果。

16. 什么是生成器表达式？

答案： 生成器表达式与列表推导式类似，但使用圆括号，返回生成器对象，例如 (x*2 for x in range(10))。

17. Python 中 __init__ 和 __new__ 有什么区别？

答案： __new__ 负责创建实例，__init__ 负责初始化实例属性，通常 __init__ 更常用。

18. 什么是 Python 的魔术方法？

答案： 魔术方法是以双下划线开头和结尾的方法，如 __str__、__repr__、__add__，用于自定义对象行为。

19. __str__ 和 __repr__ 的区别是什么？

答案： __str__ 面向用户，返回可读字符串；__repr__ 面向开发者，返回可重新创建对象的无歧义字符串。

20. 什么是 Python 的面向对象编程三大特性？

答案： 封装、继承、多态。Python 支持多继承，通过 super() 调用父类方法。

Python 进阶

21. 什么是 Python 的 MRO？

答案： MRO 是方法解析顺序，Python 使用 C3 线性化算法确定多继承中方法的查找顺序。

22. 什么是描述符（Descriptor）？

答案： 描述符是实现了 __get__、__set__ 或 __delete__ 方法的类，用于控制属性访问。

23. @property 装饰器的作用是什么？

答案： @property 可以将方法转换为属性访问，实现 getter、setter 和 deleter 的封装。

24. 什么是 Python 的元类（Metaclass）？

答案： 元类是创建类的类，默认是 type。通过自定义元类可以控制类的创建过程。

25. 什么是 Python 的鸭子类型？

答案： 鸭子类型指不关注对象类型，只关注对象是否具有所需的方法或属性，即“如果它像鸭子一样叫，那它就是鸭子”。

26. Python 中的 try...except...finally 如何使用？

答案： try 捕获异常，except 处理异常类型，finally 无论是否异常都会执行，常用于资源释放。

27. 什么是上下文管理器（Context Manager）？

答案： 上下文管理器用于自动管理资源，使用 with 语句，典型实现是 __enter__ 和 __exit__。

28. with open() 的原理是什么？

答案： with open() 调用文件的 __enter__ 打开文件，__exit__ 关闭文件，确保资源释放。

29. 什么是 Python 的 zip() 函数？

答案： zip() 将多个可迭代对象的元素按位置打包成元组，返回迭代器，长度以最短序列为准。

30. 如何合并两个字典？

答案： Python 3.9+ 支持 dict1 | dict2，旧版本可用 {**dict1, **dict2} 或 dict1.update(dict2)。

31. Python 中如何排序？

答案： 列表使用 sort() 或 sorted()，可通过 key 参数指定排序规则，如 sorted(list, key=lambda x: x['age'])。

32. 什么是 Python 的 enumerate()？

答案： enumerate() 用于同时获取索引和值，例如 for i, v in enumerate(list):。

33. 什么是 Python 的 defaultdict？

答案： defaultdict 是 collections 模块提供的字典，访问不存在的键时会自动返回默认值。

34. 什么是 Python 的 Counter？

答案： Counter 是 collections 模块提供的计数器，用于快速统计可哈希对象的出现次数。

35. deque 和列表有什么区别？

答案： deque 是双端队列，两端插入和删除的时间复杂度为 O(1)，列表尾部插入 O(1)、头部插入 O(n)。

Python 高级与工程

36. 什么是 Python 的内存管理？

答案： Python 使用引用计数和垃圾回收机制管理内存，循环引用由分代垃圾回收器处理。

37. 什么是 Python 的 __slots__？

答案： __slots__ 用于限制类实例可拥有的属性，减少内存占用并加速属性访问。

38. 什么是 Python 的反射和自省？

答案： 自省是运行时检查对象类型的能力，如 type()、dir()、hasattr()、getattr()；反射是动态调用或修改对象成员。

39. 什么是 Python 的 monkey patch？

答案： Monkey patch 指在运行时动态修改模块、类或函数的行为，常用于测试和临时修复。

40. 如何实现 Python 单例模式？

答案： 可通过重写 __new__ 方法、使用元类或装饰器实现，确保类只有一个实例。

41. Python 中多线程和多进程如何选择？

答案： CPU 密集型任务用多进程绕过 GIL；IO 密集型任务用多线程或协程提高效率。

42. 什么是 Python 的 asyncio 和协程？

答案： asyncio 是异步 IO 库，协程使用 async 和 await 关键字实现非阻塞并发。

43. async 和 await 的作用是什么？

答案： async 定义异步函数，await 挂起当前协程等待异步操作完成，不阻塞事件循环。

44. 什么是 Python 的虚拟环境？

答案： 虚拟环境是隔离的 Python 运行环境，用于管理不同项目的依赖，避免版本冲突。

45. 如何管理 Python 依赖？

答案： 使用 requirements.txt 或 pyproject.toml，通过 pip 安装，工具可选 venv、poetry、pipenv。

46. 什么是 Python 的 WSGI 和 ASGI？

答案： WSGI 是同步 Web 服务器网关接口，ASGI 支持异步通信，是现代异步框架（如 FastAPI）的基础。

47. 什么是 Python 的 Gunicorn 和 Uvicorn？

答案： Gunicorn 是 WSGI HTTP 服务器，Uvicorn 是 ASGI 服务器，常与 FastAPI 配合使用。

48. Python 中如何进行单元测试？

答案： 使用 unittest 或 pytest 编写测试用例，通过断言验证函数行为和输出。

49. 什么是 Python 的 Pytest fixture？

答案： Fixture 是 pytest 的测试前置和后置处理机制，用于准备测试环境、共享测试数据。

50. 什么是 Python 的 PEP 8？

答案： PEP 8 是 Python 代码风格指南，涵盖命名规范、缩进、行长、导入顺序等，旨在提高代码可读性。

Python 高频补充问题

51. Python 2 和 Python 3 的主要区别？

答案：

  • print 从语句变为函数；input() 统一返回 str；
  • 除法：Python 3 中 / 为真除法，// 为整除；
  • Python 3 默认 Unicode 字符串，bytes 与 str 严格分离；
  • 字典 .keys()/.items() 返回视图对象而非列表；
  • 异常语法 except E as e；xrange 被合并进 range；
  • Python 3 强制统一了 class 定义，不再区分经典类与新式类。

52. 什么是类型注解（Type Hints）？会做类型检查吗？

答案： 类型注解是 Python 3.5+（PEP 484）引入的语法，如 def f(x: int) -> str: ...，变量声明 name: str = "a"。 重要：解释器运行时不会强制检查类型，它只给阅读者和 IDE 提示；真正的校验需要 mypy、pyright 等静态检查工具。常见类型有 Optional[X]、Union[A, B]、list[int]、Any。

53. @dataclass 是什么？相比普通类有什么好处？

答案： dataclass（Python 3.7+）是自动生成 __init__、__repr__、__eq__ 等样板代码的装饰器，只需声明字段：

from dataclasses import dataclass, field

@dataclass
class User:
    name: str
    age: int = 0
    tags: list[str] = field(default_factory=list)

frozen=True 可生成不可变对象（可哈希）；order=True 自动生成比较方法。相比 namedtuple，它支持可变字段和默认值。

54. isinstance() 和 type() 有什么区别？

答案： isinstance(obj, cls) 会考虑继承关系（子类也算），并支持传入元组一次判断多个类型；type(obj) == cls 是严格类型相等比较，不考虑继承。推荐优先用 isinstance()，更符Python 鸭子类型和里氏替换原则。

55. 什么是可哈希（hashable）？为什么 dict 的 key 必须是可哈希的？

答案： 一个对象是可哈希的，当它的 hash() 在其生命周期内不变，且能与其它对象做相等比较。不可变内置类型（int、str、tuple）可哈希，list、dict、set 不可哈希。 字典基于哈希表实现，key 需要经哈希值定位桶位置，如果 key 可变则哈希值会变化，导致查询结果不一致，所以只能使用可哈希对象作 key。

56. Python 的引用计数机制有什么缺点？

答案： 优点是实时性好、简单直观；缺点：

  • 循环引用无法靠引用计数释放（A→B→A），需要分代垃圾回收器兼顶；
  • 引用计数维护开销大，每次赋值/传参都要增减计数；
  • 不是真正的“并行安全”机制，多线程下需要额外加锁。

57. Python 的分代垃圾回收（GC）是怎么工作的？

答案： GC 采用“分代回收 + 标记-清除”：对象根据存活时长分为 0、1、2 三代，新对象在第 0 代；当某代分配量超过阈值（默认 700/10/10）时触发该代扫描，存活对象升到下一代。代数越高回收越少，体现了“对象越老越不容易死”的经验假设。可用 gc.disable()、gc.collect() 手动干预。

58. 模块（module）和包（package）有什么区别？__init__.py 的作用？

答案： 模块是一个 .py 文件；包是含模块的目录。传统上包目录下需要 __init__.py 标记为包（Python 3.3+ 支持不含该文件的 namespace package）。__init__.py 在导入包时执行，可定义 __all__ 控制 from x import * 的内容，也可做子模块预导入与初始化。

59. if __name__ == "__main__": 是什么原理？

答案： 每个模块都有一个 __name__ 属性：直接运行时其为 "__main__"；被其它模块导入时其为模块名。因此该判断能让代码“本身运行则执行、被导入则不执行”，常用于写测试代码和脚本入口。

60. import 的背后发生了什么？__pycache__ 是什么？

答案： 导入时 Python 先查 sys.modules 缓存，命中则直接返回；未命中则由 import finder 在 sys.path 上定位文件，编译为字节码并执行模块代码。__pycache__ 目录存放 .pyc 字节码缓存，源文件未变化时可跳过重复编译，加快启动（注意：它不会让程序运行更快，只是省编译）。

61. 什么是海象运算符 :=？

答案： Python 3.8 引入的赋值表达式，在表达式内部完成赋值并返回右值，减少重复计算：

if (n := len(data)) > 10:
    print(f"太长：{n}")
while (chunk := f.read(8192)):
    process(chunk)

常见于条件、循环和推导式中需要复用中间结果的地方。

62. Python 3.10 的 match...case 是什么？

答案： 结构化模式匹配（PEP 634），不只是 switch，还能对序列、字典、对象属性做解构匹配，并可用 | 组合模式、用 if 加 guard：

match point:
    case (0, 0):
        print("原点")
    case (x, y) if x == y:
        print("对角线")
    case {"name": name, **rest}:
        print(name, rest)
    case _:
        print("其它")

63. f-string、str.format() 和 % 格式化有何区别？性能上呢？

答案： 三者都能做字符串插值：f-string 是表达式级别的语法，最易读、最快；format() 可延迟求值、能作为模板重复使用；% 是老式写法，不推荐。f-string 在 Python 3.12 后支持内部使用同种引号，调试更方便。大量拼接时应用 "".join(list) 而不是循环 +=，后者会反复创建新对象。

64. functools.wraps 的作用是什么？不写会怎样？

答案： 装饰器包裹原函数后，__name__、__doc__ 等元信息会丢失。@functools.wraps(func) 能把原函数的元信息拷贝到 wrapper 上。不写会影响文档生成、日志、序列化、依赖函数名的框架（如 Flask 路由、pytest 参数化）。functools 常用还有 lru_cache（缓存）、partial（部分调用）、singledispatch。

65. 如何写一个带参数的装饰器？

答案： 带参数的装饰器需要再嵌套一层，返回真正的装饰器：

import functools

def retry(times=3, delay=1):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for i in range(times):
                try:
                    return func(*args, **kwargs)
                except Exception:
                    if i == times - 1:
                        raise
                    time.sleep(delay)
        return wrapper
    return decorator

@retry(times=3, delay=0.5)
def fetch(): ...

66. lru_cache 和手动用 dict 缓存有什么区别？

答案： @functools.lru_cache(maxsize=128) 自动按参数（必须可哈希）缓存返回值，默认淘汰最近最少使用项，带 cache_info()、cache_clear()；适用子纯函数、递归、重复计算开销大的场景。手写 dict 缓存需要自己管理淘汰策略和线程安全，且无法自动处理参数错误、内存泄漏问题。

67. @staticmethod 和 @classmethod 有什么区别？

答案：

  • @staticmethod：不接收隐式参数，不能访问类或实例，相当于放在类命名空间里的普通函数；
  • @classmethod：第一个参数是类本身 cls，能访问/修改类状态，常用于定义工厂方法，且对子类友好（cls 指向实际子类）。

68. 什么是抽象类（ABC）？和接口有什么区别？

答案： Python 没有 interface 关键字，用 abc.ABC 和 @abstractmethod 实现：抽象类不能直接实例化，子类必须实现所有抽象方法。还可用 @abstractproperty、register() 做“虚拟子类”。与鸭子类型相比，ABC 能提供显式约束和 isinstance 检查。

69. 自定义异常怎么设计更合理？

答案： 继承 Exception 而非 BaseException（后者包含 KeyboardInterrupt、SystemExit）；建议为库定义一个基异常，各具体异常继承它，方便调用方一次性捕获：

class AppError(Exception): ...
class NotFoundError(AppError): ...
raise NotFoundError(f"user {uid}") from original  # 保留异常链

只捕获能处理的异常，不要写空的 except: 吞掉错误；try...except...else...finally 中 else 只在没抛异常时执行。

70. 生成器的 send()、throw()、close() 分别做什么？

答案： next()/__next__() 相当于 send(None)；send(value) 恢复执行并把值作为当前 yield 表达式的结果，可实现双向通信（协程维形）；throw(exc) 在 yield 处抛出异常；close() 触发 GeneratorExit，可用 try/finally 做资源释放。PEP 380 的 yield from 能把控制权委派给子生成器，并自动透传 send/throw。

71. 写一个“读取超大文件”的高效方案

答案： 不要 f.read() 一次读入内存。常见做法：

with open(path, encoding="utf-8") as f:
    for line in f:          # 文件对象本身是迭代器，按行惰性读
            process(line)

二进制大文件用固定块 while chunk := f.read(8 * 1024 * 1024)；JSON 大文件用 ijson 流式解析；CSV 用 csv 模块逐行处理。

72. threading.Lock 能解决什么问题？GIL 能保证线程安全吗？

答案： GIL 只保证单条字节码不会被打断，不保证复合操作（读-改-写）原子性，count += 1 仍会丢数据。需要用 Lock/RLock，或用 with lock: 自动释放；queue.Queue 本身就是线程安全的，优先用队列而不是自己加锁。另外 multiprocessing 下各进程内存不共享，需 multiprocessing.Lock 或共享内存。

73. concurrent.futures 怎么用？相比 threading 有什么优势？

答案： ThreadPoolExecutor / ProcessPoolExecutor 提供统一接口，只需 submit() 提交任务或 map() 批量执行，通过 Future 拿结果和异常，无需自己管理线程创建、回收与队列。可用 as_completed() 按完成顺序取结果，适合并发请求、批量计算场景。

74. 多进程间如何通信？

答案： 常用 multiprocessing.Queue（跨进程安全队列）、Pipe（双向管道）、共享内存 Value/Array、Manager() 代理对象，业务上更推荐用 Redis/RMQ 等外部中间件。进程内存不共享，传入的参数和返回值靠 pickle 序列化，因此不能传递不可序列化对象（如打开的文件句柄、lambda）。

75. asyncio.gather() 和 ensure_future() 有什么区别？

答案： gather(*aws) 并发调度多个协程，按传入顺序返回列表，一个抛异常会传递到 return_exceptions=True 控制下收集结果；ensure_future()（旧版 asyncio.async）只包装单个对象返回 Task，需自己 await 或 wait()。Task 是 Future 的子类，代表已被调度器执行的协程。

76. 异步代码中不小心写了同步阻塞调用会怎样？

答案： 整个事件循环被阻塞，所有协程一起卡住（常见错误：在 async 函数里用 requests.get、time.sleep、重型 CPU 计算）。应改用 aiohttp/httpx、asyncio.sleep；无法避免的阻塞调用用 await asyncio.to_thread(...) 或 run_in_executor() 丢到线程/进程池。

77. 如何使用 logging 而非 print？

答案： logging 支持日志级别（DEBUG/INFO/WARNING/ERROR/CRITICAL）、格式化输出、多 Handler（控制台+文件+远程）、按大小/日期切分、模块层级控制。典型写法：模块内 logger = logging.getLogger(__name__)，入口用 logging.basicConfig(level=..., format=..., handlers=[...]) 配置；日志用 logger.info("user=%s", uid) 惰性格式化，避免字符串拼接开销，也不要 except: logger.error(str(e)) 而丢掉 traceback（用 logger.exception）。

78. Python 性能分析和优化思路？

答案： 先测量再优化：cProfile/pstats、timeit 模块定位热点，memory_profiler、objgraph 查内存；也可用 py-spy、scalene 做采样分析。优化手段：选对数据结构（集合查找 O(1) vs 列表 O(n)）、避免重复计算和属性查找、用推导式/内置函数代替手写循环、lru_cache 缓存、批量代替逐条 IO、并行（多进程/异步）、必要环节用 NumPy/Cython/Rust 扩展。

79. 什么是常见内存泄漏原因？如何排查？

答案： 常见原因：全局容器只增不减、循环引用带 __del__、缓存未限长、异常 Traceback 持有对象、信号/回调注册未注销、线程未回收。排查：gc.get_objects() 统计对象数量、tracemalloc 追踪分配源头、objgraph 看引用链、配合 sentry/周期性重启定位。

80. Flask、Django、FastAPI 如何选型？

答案：

  • Django：全家桶，自带 ORM、Admin、表单、认证、中间件，适合业务复杂、需快速搭建后台的系统；
  • Flask：微型框架，自由选组件，适合小型服务、脚本型接口、教学示例；
  • FastAPI：基于 ASGI + Pydantic 类型注解，自动 Swagger 文档，异步高并发友好，适合 AI/推理接口、微服务。部署：Django/Flask 用 Gunicorn（WSGI），FastAPI 用 Uvicorn/Granian（ASGI）。

81. Python 做 AI/数据方向的常用库有哪些？

答案： 数值计算：NumPy（向量化、广播）、Pandas（DataFrame、数据清洗）；可视化：Matplotlib、Seaborn；机器学习：scikit-learn、XGBoost；深度学习：PyTorch、TensorFlow/Keras；模型服务：FastAPI、vLLM；数据获取：requests、BeautifulSoup、Scrapy；工具：Jupyter、pytest、poetry。高频追问：Pandas 如何处理缺失值（isna/fillna/dropna）、如何避免 SettingWithCopyWarning（用 .loc 显式赋值）。

Django 基础

分级：Python 基础 → Django 基础 → Django 进阶 → 工程/源码/性能难题

82. Django 的 MTV 架构，和 MVC 什么区别？

答案： MTV：Model、Template、View

  • Model：模型，ORM，映射数据库表；
  • Template：模板，负责页面渲染；
  • View：视图，接收请求、处理业务、返回响应。

MVC 中的 Controller 负责路由分发，Django 把路由放到 urls.py，View 承担了业务处理职责，所以称为 MTV。

83. Django 一次 HTTP 请求的完整生命周期？

答案：

  1. WSGI 服务器接收 HTTP 请求；
  2. 请求依次经过中间件的 process_request；
  3. urls.py 路由匹配，找到对应视图；
  4. 执行视图（ORM 操作、业务逻辑）；
  5. 可选：渲染模板；
  6. 响应逆序经过中间件 process_response；
  7. 返回响应给客户端。

84. ORM 是什么？Django ORM 的优缺点？

答案： ORM（对象关系映射）把面向对象的模型操作自动转换成 SQL。

  • 优点：不用手写原生 SQL，开发快，切换数据库成本低，防 SQL 注入；
  • 缺点：复杂 SQL 场景性能较差，部分数据库特有语法不好表达，容易写出 N+1 查询。

85. Model 中 null 和 blank 的区别？

答案：

  • null：数据库层面控制，字段是否允许存入 NULL；
  • blank：表单/序列化校验层面控制，是否允许提交空值。

CharField/TextField 一般只设 blank=True，不要设 null=True，避免数据库同时存在 NULL 和空字符串两种“空”。

86. path() 和 re_path() 的区别？

答案：

  • path()：Django 2+ 推荐，支持内置路径转换器（int/str/slug/uuid 等）；
  • re_path()：用正则表达式匹配 URL，用于复杂路由，等价于旧版 url()。

87. 模板中 {{ }} 和 {% %} 的作用？什么是模板继承？

答案：

  • {{ 变量 }}：渲染变量输出（自动转义，防 XSS）；
  • {% 标签 %}：执行模板标签，如 if、for、block、url。

模板继承：子模板 {% extends "base.html" %}，用 {% block xxx %} 覆盖父模板挖好的块，复用公共页面骨架。

88. Django Form 的作用？

答案：

  1. 自动渲染前端表单；
  2. 做数据校验，支持自定义 clean_<字段>() / clean() 校验；
  3. 返回结构化错误提示；
  4. 自带基础防 XSS 能力，配合 CSRF 防护。

Django 进阶

89. Django 中间件有哪 5 个钩子？执行顺序？

答案：

  1. process_request：请求进入，路由匹配之前；
  2. process_view：路由匹配完成，视图执行前；
  3. process_template_response：视图返回 TemplateResponse 对象时触发；
  4. process_response：生成响应返回客户端前；
  5. process_exception：视图抛出异常时触发。

执行特点：洋葱模型，请求阶段从上到下依次进入，响应阶段从下到上依次返回；任一 process_request 直接返回 HttpResponse 会短路后续视图。

90. select_related 和 prefetch_related 的区别？解决什么问题？

答案： 两者都用于解决 ORM 的 N+1 查询问题。

  • select_related：针对外键/一对一关联，用 SQL JOIN 一次查出，只一条 SQL；只能“正向”关联；
  • prefetch_related：针对多对多、反向外键（related_name），先查主表再用子查询 IN 取关联表，多条 SQL，不能在 SQL 层 JOIN 过滤。

91. CSRF 是什么？原理？什么时候可以关闭？

答案： CSRF（跨站请求伪造）：诱导已登录用户的浏览器携带 Cookie 向目标站点发起非预期请求。 Django 原理：生成 csrf_token，同时写入 Cookie 和表单隐藏字段，POST 时校验两者是否一致（攻击者读不到目标域 Cookie，无法伪造）。 前后端分离 API 使用 JWT/Token 认证、不依赖 Cookie 会话时，可用 @csrf_exempt 装饰器（或全局中间件配置）关闭 CSRF 校验。

92. Django 常用信号、使用场景与坑？

答案： 常用信号：pre_save/post_save、pre_delete/post_delete、m2m_changed、request_started 等。 作用：模型事件触发回调，将副作用业务（发邮件、写日志、同步索引）与主流程解耦。 坑：信号默认同步执行，拖慢主请求；bulk_create、bulk_update 不会触发 post_save；执行顺序不可控、容易循环调用、调试困难，项目复杂后建议改用显式服务层调用或消息队列。

93. Django 缓存有哪些后端？缓存粒度？

答案： 后端：本地内存缓存（LocMemCache）、文件缓存、数据库缓存、Redis / Memcached（django-redis）。 粒度：全站缓存（中间件）、视图级缓存（@cache_page）、模板片段缓存（{% cache %}）、底层对象缓存（直接操作 cache API）；支持多别名配置分别读写。

94. DRF 序列化器的作用？serializer.save() 的内部逻辑？

答案： 序列化器两大核心：序列化（模型对象 → JSON）与反序列化（JSON → 校验 → 模型对象）。 save()：前提是先调过 is_valid()；内部根据是否传入 instance 自动判断调用 create() 还是 update()，并把 validated_data 以及 save() 额外传入的关键字参数（如 owner=request.user）一并传给这两个方法。

95. DRF 的认证、权限、限流分别是什么？

答案：

  • 认证 Authentication：识别请求“是谁”（Session、Token、JWT、OAuth）；
  • 权限 Permission：判断已认证用户“能不能访问”（IsAdminUser、自定义 BasePermission）；
  • 限流 Throttle：限制访问频率，防接口被刷（用户级/IP 级，滑动窗口或令牌桶）。 三者依次在 initial() 中执行，先认证后权限再限流。

Django 工程化 / 源码 / 性能调优

96. ORM 的 N+1 查询怎么产生？如何排查和优化？

答案： 产生：查询主表数据后，循环遍历每条记录时单独查询关联表，形成 1 次主查询 + N 次关联查询。 排查：打开 Django django.db.backends 日志打印 SQL，看查询次数；用 django-debug-toolbar、nplusone 库自动检测。 优化：select_related、prefetch_related；only()/defer() 减少查询字段；values()/values_list() 避开模型实例化；exists() 代替 len()>0；批量 bulk_create；极致场景下用原生 SQL 或自定义 Manager。

97. Django QuerySet 惰性查询是什么意思？

答案： QuerySet 是惰性加载：创建时不会执行 SQL，只有迭代、切片、list()、bool()、first() 等操作触发求值时才真正访库，结果缓存在 _result_cache 中。注意过滤链会生成新的 QuerySet，重复遍历时可先 list(qs) 避免重复查库。

98. Django 事务怎么使用？什么场景必须用事务？

答案： 使用 from django.db import transaction：

  • 装饰器 @transaction.atomic
  • 上下文管理器 with transaction.atomic():（可做更细粒度控制，内部配合 savepoint）
  • transaction.on_commit() 注册提交后才执行的副作用（发通知、推消息） 场景：多表数据必须同时成功或同时回滚，如订单创建 + 扣减库存；并发更新用 select_for_update() 加行锁。注意 MySQL 需 InnoDB 引擎，且事务内不要做耗时 IO。

99. DRF 的 ViewSet 和普通 APIView 有什么区别？

答案：

  • APIView：基础视图类，自己写 get/post 方法并逐个绑定 URL；
  • ViewSet：把一组相关接口（list/retrieve/create/update/partial_update/destroy）封装到一个类，配合 DefaultRouter 自动生成 URL 与 HTTP 方法映射，并用 @action 定义自定义路由，显著减少重复代码。

100. Django 项目部署常见问题？

答案：

  • DEBUG=True 不能上线，会泄露代码和敏感信息；ALLOWED_HOSTS 要配置；
  • 静态文件需要 collectstatic，由 Nginx 托管，应用不服务静态资源；
  • 使用 Gunicorn/uWSGI 作为 WSGI 服务器（异步用 Daphne/Uvicorn），不能用 runserver 部署；
  • SECRET_KEY、数据库密码等配置到环境变量，不硬编码进代码仓库；
  • 数据库连接池与超时配置（CONN_MAX_AGE、CONN_HEALTH_CHECKS），避免长连接失效；
  • 迁移上线前检查，大表加字段/索引要考虑锁表与 SELECT FOR UPDATE 影响；
  • 反向代理后需 SECURE_PROXY_SSL_HEADER，并开启 GZip、缓存、监控（Sentry）。

101. Django 多线程下模型实例有什么坑？

答案：

  • Model 实例属于线程内对象，不能在线程间共享；
  • 数据库连接是线程隔离的，每个线程各一份连接，线程泄漏会导致数据库连接数暴涨；
  • 多线程修改同一个模型数据会出现并发脏读/丢失更新，需要事务 + select_for_update() 或 F() 表达式做数据库侧原子更新；
  • 在子线程里执行 ORM 后忘记 connection.close() 会残留连接。

🟢 102. Python 的优缺点是什么？

答案： 优点：语法简洁易读、开发效率高、生态丰富（AI/数据/Web/自动化）、跨平台、社区活跃、胶水语言（可调用 C/C++）。 缺点：执行速度比编译型语言慢（GIL 限制多线程并行）、移动端和游戏开发较弱、运行时错误较多（动态类型）、打包体积大。

🟢 103. Python 是动态类型还是静态类型？强类型还是弱类型？

答案： Python 是动态强类型语言。

  • 动态类型：变量类型在运行时确定，可随时赋值不同类型（a = 1; a = "x"）；
  • 强类型：类型检查严格，不同类型不会隐式转换（"1" + 1 会报错，而 JS/PHP 会隐式转换）。 对比：C/Java 是静态强类型，JS 是动态弱类型。

🟢 104. Python 的作用域 LEGB 规则是什么？

答案： 变量查找顺序：Local（局部）→ Enclosing（嵌套函数外层）→ Global（全局）→ Built-in（内置）。

x = "global"
def outer():
    x = "enclosing"
    def inner():
        x = "local"  # 先找 local，找到就用
        print(x)
    inner()

在函数内赋值默认创建局部变量，要修改外层需 global（改全局）或 nonlocal（改嵌套层）。

🟢 105. global 和 nonlocal 的区别是什么？

答案：

  • global：声明变量来自全局作用域，用于在函数内修改全局变量；
  • nonlocal：声明变量来自最近的外层嵌套函数作用域（不能是全局），用于闭包中修改外层函数变量。
def outer():
    count = 0
    def inner():
        nonlocal count  # 引用 outer 的 count
        count += 1
    return inner

🟢 106. 函数默认参数用可变对象有什么陷阱？

答案： 默认参数在函数定义时只计算一次，之后所有调用共享同一个对象。如果默认参数是可变对象（list/dict），多次调用会累积修改：

def append(item, lst=[]):
    lst.append(item)
    return lst
append(1)  # [1]
append(2)  # [1, 2]  ← 不是预期的 [2]

正确做法：用 None 作默认值，函数内创建新对象：

def append(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst

🟢 107. Python 函数参数传递是传值还是传引用？

答案： 都不是，Python 是传对象引用（Pass by Object Reference）。

  • 传入不可变对象（int/str/tuple）：函数内修改会创建新对象，外部不受影响（表现像传值）；
  • 传入可变对象（list/dict）：函数内修改对象内容，外部也会变化（表现像传引用）；
  • 但如果在函数内重新赋值变量（lst = [1,2]），只是让局部变量指向新对象，不影响外部。

🟢 108. 字典（dict）的底层实现是什么？

答案： Python 3.6+ 的 dict 底层是哈希表 + 稀疏索引数组 + 紧凑数组：

  1. 对 key 做 hash() 得到哈希值；
  2. 哈希值对索引数组取模定位槽位；
  3. 索引数组存实际数据在紧凑数组中的位置；
  4. 紧凑数组按插入顺序存储 (hash, key, value)。 这样既保持了 O(1) 查找，又实现了插入有序（3.7+ 正式特性），还节省了内存。哈希冲突用开放寻址法（探测下一个槽位）解决。

🟢 109. list、dict、set 常见操作的时间复杂度？

答案：

操作 list dict set
访问（按索引/key） O(1) O(1) 平均 O(1) 平均
插入末尾 O(1) 均摊 O(1) 平均 O(1) 平均
插入中间/头部 O(n) — —
删除 O(n)（后续元素前移） O(1) 平均 O(1) 平均
查找（in） O(n) O(1) 平均 O(1) 平均
排序 O(n log n) — —

dict/set 的 O(1) 是平均情况，最坏 O(n)（哈希冲突严重时）。

🟢 110. Python 3.7+ 的 dict 为什么是有序的？

答案： Python 3.6 重新实现了 dict 底层（PyPy 的方案），用"稀疏索引 + 紧凑数组"结构，紧凑数组按插入顺序存储，因此天然保持插入顺序。3.7 将其定为语言规范。有序 dict 节省了约 25% 内存，且迭代、popitem 等操作都按插入顺序。注意：有序指插入顺序，不是排序。

🟢 111. 类变量和实例变量的区别是什么？

答案：

  • 类变量：定义在类中、方法外，所有实例共享一份，通过 类名.变量 或 实例.变量 访问；
  • 实例变量：在 __init__ 中通过 self.xxx 定义，每个实例独立一份。
class A:
    count = 0  # 类变量
    def __init__(self):
        self.name = ""  # 实例变量

坑：通过实例修改类变量（a.count = 1）实际是创建了同名实例变量，不影响类变量和其他实例；要改类变量须用 A.count = 1。

🟡 112. Python 私有属性的名称改写（name mangling）是什么？

答案： Python 没有真正的私有，双下划线开头的属性（如 __name）会被解释器自动改名为 _类名__name，防止子类意外覆盖。这只是一种约定和保护机制，并非强制隐藏——外部仍可通过 obj._类名__name 访问。单下划线开头（_name）只是约定"内部使用"，不做任何改写。

🟡 113. super() 在多继承中是如何工作的？

答案： super() 不是简单调用"父类"，而是按 MRO（方法解析顺序） 调用下一个类。MRO 由 C3 线性化算法确定，保证每个类只调用一次、遵循继承拓扑顺序。

class A:
    def hello(self): print("A")
class B(A):
    def hello(self):
        super().hello()  # 按 MRO 调用下一个，不一定是 A
        print("B")

可用 类名.__mro__ 查看解析顺序。多继承中 super() 配合 MRO 实现了协作式多继承（如 __init__ 链）。

🟡 114. 多个装饰器叠加时的执行顺序是什么？

答案： 装饰器是自底向上应用（包装），自顶向下执行（调用时）。

@decorator1
@decorator2
def func():
    pass
# 等价于 func = decorator1(decorator2(func))

调用 func() 时：先进入 decorator1 的 wrapper → 再进入 decorator2 的 wrapper → 执行原函数 → 从 decorator2 返回 → 从 decorator1 返回。即"先装饰的后执行，后装饰的先执行"。

🟡 115. 上下文管理器有哪两种实现方式？

答案：

  1. 类实现：定义 __enter__（进入 with 时执行，返回值赋给 as 变量）和 __exit__（退出时执行，可捕获异常，返回 True 抑制异常）；
  2. 生成器 + @contextmanager：用 yield 分割进入和退出逻辑：
from contextlib import contextmanager
@contextmanager
def my_open(path):
    f = open(path)
    try:
        yield f       # yield 之前 = __enter__，之后 = __exit__
    finally:
        f.close()

第二种更简洁，适合简单场景。

🟡 116. 描述符（Descriptor）的实际应用场景有哪些？

答案： 描述符是实现了 __get__/__set__/__delete__ 的类，用于控制属性访问。实际应用：

  • @property 底层就是描述符；
  • @classmethod、@staticmethod 是描述符；
  • ORM 框架（Django/SQLAlchemy）的字段类型（IntegerField）用描述符实现类型校验和数据库映射；
  • 自定义校验、懒加载、类型转换。
class Positive:
    def __get__(self, obj, cls): return obj.__dict__.get(self.name, 0)
    def __set__(self, obj, val):
        if val < 0: raise ValueError
        obj.__dict__[self.name] = val

🟡 117. Python 垃圾回收的完整机制是什么？

答案： Python GC 由三部分组成：

  1. 引用计数（主）：每个对象维护引用计数，归零时立即释放。实时性好，但无法处理循环引用；
  2. 标记-清除（辅助）：从根对象出发标记可达对象，清除不可达对象，专门解决循环引用；
  3. 分代回收（优化）：对象按存活时间分 0/1/2 三代，新对象在 0 代，存活则升代；代数越高回收频率越低，基于"对象越老越不容易死"的假设。 可用 gc 模块手动控制（gc.collect()、gc.disable()）。

🟡 118. 循环引用是如何被回收的？

答案： 引用计数无法回收循环引用（A→B→A，计数永远不为 0）。分代 GC 的标记-清除阶段处理：

  1. 从根对象（全局变量、栈上引用）出发，标记所有可达对象；
  2. 未被标记的对象（包括循环引用组）被判定为垃圾，执行回收。 但如果循环引用中的对象定义了 __del__（终结器），GC 无法安全判断调用顺序，会将其放入 gc.garbage 列表而不自动回收，造成内存泄漏——这是 __del__ 的经典坑。

🟡 119. 进程、线程、协程的区别和适用场景？

答案：

维度 进程 线程 协程
资源 独立内存空间，开销大 共享进程内存，开销小 用户态，开销极小
切换 操作系统调度，开销大 操作系统调度，开销中 程序自行调度，开销极小
并行 可利用多核 受 GIL 限制，CPU 密集不并行 单线程内并发，不并行
通信 IPC（队列/管道/共享内存） 共享内存，需锁 直接共享，无需锁
适用 CPU 密集、需隔离 IO 密集、轻量并发 高并发 IO、异步框架

Python 中：CPU 密集用多进程，IO 密集用多线程或协程（asyncio）。

🔴 120. 如何绕过 GIL？

答案： GIL 是 CPython 解释器的全局锁，同一时刻只允许一个线程执行 Python 字节码。绕过方式：

  1. 多进程（multiprocessing）：每个进程有独立 GIL，可真正并行，最常用；
  2. C 扩展：在 C/C++ 代码中释放 GIL（Py_BEGIN_ALLOW_THREADS），如 NumPy、Pandas 内部计算；
  3. ctypes/cffi：调用原生 C 库时可释放 GIL；
  4. 换解释器：Jython（JVM）、IronPython（.NET）无 GIL，但生态和兼容性差；
  5. 协程：不绕过 GIL，但在 IO 等待时切换，提高单线程并发度。 注意：IO 密集型任务不需要绕过 GIL，因为等待 IO 时 GIL 会自动释放。

🔴 121. 死锁产生的条件和避免方法？

答案： 死锁四要素（同时满足才会死锁）：

  1. 互斥：资源不能共享，只能一个线程持有；
  2. 占有且等待：持有资源的同时等待其他资源；
  3. 不可抢占：资源不能被强行剥夺，只能主动释放；
  4. 循环等待：线程间形成环形等待链。

避免方法：

  • 按固定顺序获取锁（破坏循环等待）；
  • 用 try_acquire + 超时（破坏占有且等待）；
  • 尽量用一把锁，减少嵌套加锁；
  • 用 queue.Queue 等线程安全容器替代手工锁；
  • 用 concurrent.futures 等高层抽象。

🔴 122. asyncio 事件循环的工作原理是什么？

答案： 事件循环（Event Loop）是 asyncio 的核心，单线程内调度所有协程：

  1. 维护一个任务队列（就绪的协程/回调）；
  2. 循环取出任务执行，遇到 await 时挂起当前协程，控制权交回事件循环；
  3. 被等待的 IO 操作完成后（通过 selector 监听 fd 就绪），对应协程重新加入就绪队列；
  4. 如此循环，直到所有任务完成。 关键：协程在 await 处让出 CPU，而非被操作系统抢占，因此是协作式并发。事件循环用 selectors（epoll/kqueue）实现 IO 多路复用，单线程可处理大量并发连接。

🔴 123. multiprocessing 的 spawn/fork/forkserver 启动方式有什么区别？

答案： multiprocessing 创建子进程有三种方式（set_start_method）：

  • fork（Linux 默认）：复制父进程全部内存（写时复制），启动快，可继承父进程对象；但多线程下 fork 不安全（只复制调用线程，其他线程状态不一致），且与某些库（如 macOS 上的 CoreFoundation）不兼容；
  • spawn（Windows/macOS 默认）：启动全新 Python 解释器，只传递必要参数，安全但启动慢、需 pickle 序列化；
  • forkserver：启动一个单线程服务进程，后续 fork 都从它复制，避免多线程 fork 问题，兼顾安全和速度。 选择：Linux 多线程环境推荐 spawn 或 forkserver，避免 fork 的线程安全问题。

🔴 124. Python 3.11 / 3.12 / 3.13 有哪些重要新特性？

答案：

  • 3.11：速度提升约 10-60%（Faster CPython 项目）；更精准的错误提示（错误位置箭头）；ExceptionGroup/except* 批量异常；tomllib 标准库解析 TOML；Self 类型、LiteralString。
  • 3.12：支持在 f-string 中嵌套同种引号和多行表达式；类型参数语法 def f[T](x: T)（PEP 695）；override 装饰器；进一步性能优化；支持 Linux perf 性能分析。
  • 3.13：实验性移除 GIL（自由线程构建，--disable-gil）；JIT 编译器实验性支持；改进错误消息；asyncio 性能提升；更多模块支持自由线程。 3.13 的无 GIL 是 Python 历史上的重大变革，目前是实验阶段，预计 3.14/3.15 逐步成熟。

🔴 125. 如何手写一个 LRU 缓存？

答案： LRU（最近最少使用）缓存：容量满时淘汰最久未使用的项。用双向链表 + 哈希表实现 O(1) 读写：

class Node:
    def __init__(self, key=0, val=0):
        self.key, self.val = key, val
        self.prev = self.next = None

class LRUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.cache = {}          # key -> Node
        self.head = Node()       # 哨兵头（最近使用）
        self.tail = Node()       # 哨兵尾（最久未使用）
        self.head.next = self.tail
        self.tail.prev = self.head

    def _remove(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev

    def _add_to_head(self, node):
        node.next = self.head.next
        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node

    def get(self, key):
        if key not in self.cache: return -1
        node = self.cache[key]
        self._remove(node)
        self._add_to_head(node)   # 访问后移到头部
        return node.val

    def put(self, key, value):
        if key in self.cache:
            node = self.cache[key]
            node.val = value
            self._remove(node)
            self._add_to_head(node)
        else:
            if len(self.cache) >= self.cap:
                lru = self.tail.prev  # 淘汰尾部
                self._remove(lru)
                del self.cache[lru.key]
            node = Node(key, value)
            self.cache[key] = node
            self._add_to_head(node)

也可用 collections.OrderedDict 的 move_to_end 和 popitem(last=False) 快速实现。

🔴 126. Python 性能优化的常见手段有哪些？

答案： 按投入产出比排序：

  1. 选对数据结构：集合/字典查找 O(1)，避免列表 in 的 O(n)；用 deque 做双端操作；
  2. 避免重复计算：lru_cache 缓存、预计算、局部变量缓存（local = global_func 减少查找）；
  3. 用内置函数和推导式：sum/map/filter/列表推导比手写循环快（底层 C 实现）；
  4. 减少函数调用和属性访问：循环内避免频繁 . 访问和函数调用；
  5. 批量 IO：批量读写数据库/文件，避免逐条操作；
  6. 并发：IO 密集用 asyncio/线程池，CPU 密集用多进程；
  7. 向量化：数值计算用 NumPy/Pandas 代替纯 Python 循环；
  8. 扩展：热点用 Cython、C 扩展、Rust（PyO3）重写；
  9. 先测量：用 cProfile、py-spy、scalene 定位瓶颈，不要盲目优化。
