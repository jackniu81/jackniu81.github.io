.NET / C# 常见面试题 192 道（附答案）

C# 基础

1. 什么是 C#？

答案： C# 是由微软推出的现代面向对象编程语言，运行在 .NET 平台上，广泛用于 Web、桌面、服务端和云原生开发。

2. 什么是 .NET？

答案： .NET 是微软提供的开发平台和运行时生态，包含运行时、基础类库、工具链和多种应用开发框架。

3. .NET Framework、.NET Core 和 .NET 的关系是什么？

答案： .NET Framework 是早期 Windows 平台实现；.NET Core 是跨平台重构版本；现在统一演进为 .NET。

4. CLR 是什么？

答案： CLR 是公共语言运行时，负责内存管理、垃圾回收、异常处理、JIT 编译和安全控制。

5. CTS 和 CLS 分别是什么？

答案： CTS 定义公共类型系统，CLS 定义不同 .NET 语言之间互操作应遵守的最小规范集合。

6. 什么是值类型和引用类型？

答案： 值类型直接存储值本身，引用类型存储对象地址引用，二者在内存和复制行为上不同。

7. 常见值类型有哪些？

答案： 常见有 int、double、bool、char、decimal、struct、enum 等。

8. 常见引用类型有哪些？

答案： 常见有 class、string、数组、委托、接口实现对象等。

9. string 为什么是引用类型却表现得像不可变值？

答案： 因为 string 底层是引用类型，但设计为不可变对象，每次修改本质上都会创建新实例。

10. var 是什么？

答案： var 是编译器的隐式类型推断，变量类型在编译期确定，并不是动态类型。

11. dynamic 和 var 的区别是什么？

答案： var 是编译期推断，dynamic 则把成员解析推迟到运行时。

12. 什么是装箱和拆箱？

答案： 装箱是把值类型转换为 object 或接口引用；拆箱是把装箱对象再还原成值类型。

13. 为什么装箱拆箱有性能开销？

答案： 因为它涉及堆分配、类型转换和额外复制，会增加 GC 压力。

14. 什么是可空类型？

答案： 可空值类型允许值类型表示 null，写法如 int?。

15. ?? 和 ?. 运算符的作用是什么？

答案： ?? 提供空值合并默认值，?. 用于空条件访问，避免空引用异常。

16. 什么是枚举？

答案： 枚举用于定义一组具名常量，提升代码可读性。

17. 什么是结构体？

答案： 结构体是值类型，适合表示小型、轻量、不可继承的数据聚合对象。

18. 结构体和类的区别是什么？

答案： 结构体是值类型，默认按值复制；类是引用类型，支持继承和多态。

19. 什么是只读字段和常量？

答案： const 是编译期常量；readonly 可以在声明处或构造函数中赋值。

20. 什么是属性？

答案： 属性是对字段访问的封装语法，便于控制读写逻辑。

面向对象与语言特性

21. 面向对象的三大特性是什么？

答案： 封装、继承、多态。

22. 什么是封装？

答案： 封装是把数据和行为组合在一起，并通过访问控制隐藏内部实现细节。

23. 什么是继承？

答案： 继承允许子类复用父类已有的字段、属性和方法。

24. 什么是多态？

答案： 多态指同一个调用入口在不同对象上表现出不同行为。

25. virtual、override、abstract 的区别是什么？

答案： virtual 表示可重写，override 表示重写父类虚成员，abstract 表示必须由派生类实现。

26. 抽象类和接口的区别是什么？

答案： 抽象类可包含状态和实现；接口更强调能力契约，支持多实现。

27. 什么时候用抽象类，什么时候用接口？

答案： 有共享实现和公共状态时优先考虑抽象类；需要解耦能力契约时优先接口。

28. 什么是方法重载？

答案： 同一个类型中方法名相同但参数列表不同，称为方法重载。

29. 什么是方法重写？

答案： 子类重新实现父类的可重写成员，称为方法重写。

30. sealed 的作用是什么？

答案： sealed 用于禁止类被继承，或禁止方法继续被重写。

31. 什么是访问修饰符？

答案： 访问修饰符用于控制成员可见性，如 public、private、protected、internal。

32. public 和 internal 的区别是什么？

答案： public 可被任何程序集访问，internal 仅当前程序集内可见。

33. 什么是静态成员？

答案： 静态成员属于类型本身，而不是某个实例。

34. 什么是扩展方法？

答案： 扩展方法允许在不修改原类型源码的前提下，为其增加看似实例方法的调用方式。

35. 什么是索引器？

答案： 索引器允许对象像数组一样通过下标访问内部数据。

36. 什么是运算符重载？

答案： 运算符重载允许自定义类型重新定义 +、== 等运算符行为。

37. 什么是记录类型 record？

答案： record 是更适合表示不可变数据模型的引用类型，默认强调值相等语义。

38. record 和 class 的区别是什么？

答案： record 默认更适合数据载体和值比较；class 更适合一般业务对象与行为封装。

39. 什么是模式匹配？

答案： 模式匹配允许通过更直观的方式对类型和结构进行判断与解构。

40. switch 表达式相比传统 switch 有什么优势？

答案： 写法更简洁、更偏表达式风格，也更适合结合模式匹配使用。

泛型、集合与 LINQ

41. 什么是泛型？

答案： 泛型允许把类型参数化，提升复用性、类型安全和性能。

42. 为什么泛型优于 object？

答案： 因为泛型避免频繁装箱拆箱，并在编译期提供类型检查。

43. 常见泛型集合有哪些？

答案： 常见有 List<T>、Dictionary<TKey, TValue>、HashSet<T>、Queue<T>、Stack<T>。

44. List<T> 和数组的区别是什么？

答案： 数组长度固定；List<T> 可动态扩容，API 更丰富。

45. Dictionary 和 Hashtable 的区别是什么？

答案： Dictionary 是泛型集合，类型安全且性能更好；Hashtable 是早期非泛型实现。

46. HashSet<T> 适合什么场景？

答案： 适合去重和高效判断元素是否存在的场景。

47. 什么是 LINQ？

答案： LINQ 是 .NET 提供的统一查询语法，可用于对象、数据库、XML 等数据源。

48. LINQ 的优势是什么？

答案： 它使查询表达更统一、可读，也方便链式组合和延迟执行。

49. 什么是延迟执行？

答案： 延迟执行指查询表达式在真正枚举结果前不会立即执行。

50. IEnumerable<T> 和 IQueryable<T> 的区别是什么？

答案： IEnumerable<T> 主要用于内存对象枚举；IQueryable<T> 可让查询表达式继续翻译给底层提供程序，如数据库。

51. First 和 FirstOrDefault 的区别是什么？

答案： First 找不到元素会抛异常，FirstOrDefault 则返回默认值。

52. Single 和 First 的区别是什么？

答案： Single 要求结果恰好一个，否则抛异常；First 只取第一个匹配项。

53. Select 和 SelectMany 的区别是什么？

答案： Select 做一对一投影，SelectMany 常用于把多层集合拍平。

54. Where 的作用是什么？

答案： Where 用于按条件过滤序列元素。

55. Any 和 Count 在判断存在性上如何取舍？

答案： 判断是否存在时优先用 Any，通常更高效也更符合语义。

委托、事件与异步

56. 什么是委托？

答案： 委托是对方法引用的类型安全封装，可用于回调、事件和策略传递。

57. Action 和 Func 的区别是什么？

答案： Action 表示无返回值委托；Func 表示有返回值委托。

58. 什么是 Lambda 表达式？

答案： Lambda 是用于快速定义匿名函数的简洁语法。

59. 什么是事件？

答案： 事件是在委托基础上构建的发布-订阅机制，用于通知状态变化。

60. 为什么事件通常由发布者拥有、订阅者监听？

答案： 这样能保持职责分离，让状态变化通知更加解耦。

61. 什么是异步编程？

答案： 异步编程用于避免阻塞线程，让耗时操作完成后再继续处理结果。

62. async 和 await 的作用是什么？

答案： 它们让异步代码写法更接近同步流程，提高可读性。

63. Task 和 Thread 的区别是什么？

答案： Task 是更高级的异步抽象，通常建立在线程池之上；Thread 是更底层的线程对象。

64. Task.Run 适合什么场景？

答案： 适合把 CPU 密集型工作放到后台线程执行，不适合滥用于本已异步的 I/O 场景。

65. 为什么不要随意使用 async void？

答案： 因为它难以等待、难以捕获异常，通常只适用于事件处理器。

66. 什么是死锁风险中的 Result 和 Wait() 问题？

答案： 在异步上下文中同步阻塞等待任务结果，可能造成上下文互相等待而死锁。

67. 什么是 CancellationToken？

答案： 它用于向异步操作传递取消信号，实现协作式取消。

68. ConfigureAwait(false) 常用于什么？

答案： 它常用于库代码中，避免不必要地切回原同步上下文。

69. 什么是并发和并行？

答案： 并发强调多个任务交替推进，并行强调多个任务同时执行。

70. 线程安全是什么意思？

答案： 线程安全表示多个线程并发访问时仍能保持数据一致和行为正确。

内存、异常与性能

71. GC 是什么？

答案： GC 是垃圾回收器，负责自动回收不再使用的托管内存对象。

72. 托管内存和非托管内存的区别是什么？

答案： 托管内存由 CLR 管理；非托管内存需要开发者或外部资源自行控制释放。

73. 什么是终结器？

答案： 终结器是对象被 GC 回收前可能执行的清理逻辑，但时机不确定。

74. 为什么更推荐 IDisposable 而不是依赖终结器？

答案： 因为 Dispose 能显式释放资源，时机可控，性能和可靠性更好。

75. using 语句的作用是什么？

答案： using 用于确保实现 IDisposable 的对象在使用结束后被及时释放。

76. 什么是异常处理？

答案： 异常处理是通过 try-catch-finally 捕获和管理运行时错误的机制。

77. 什么时候应该捕获异常，什么时候应该抛出异常？

答案： 只有在你能补救、转换或补充上下文时才捕获；否则应让异常继续向上抛。

78. 为什么不要吞掉异常？

答案： 吞掉异常会掩盖真实问题，使排查变困难，甚至造成错误状态持续扩散。

79. throw 和 throw ex 的区别是什么？

答案： throw 会保留原始堆栈；throw ex 会重置堆栈，通常不推荐。

80. 什么是不可变对象？

答案： 不可变对象在创建后状态不可修改，通常更安全，也更利于并发和缓存。

81. StringBuilder 适合什么场景？

答案： 适合频繁字符串拼接的场景，可减少大量中间字符串对象创建。

82. 什么情况下值类型反而可能更高效？

答案： 小型数据结构、生命周期短、避免堆分配时，值类型可能更高效。

83. 什么是 Span？

答案： Span<T> 是用于高性能内存切片访问的类型，可减少额外分配。

84. 为什么性能优化要先测量再修改？

答案： 因为很多“优化”只是猜测，先定位瓶颈才能避免无效或有害改动。

ASP.NET Core 与工程实践

85. 什么是 ASP.NET Core？

答案： ASP.NET Core 是跨平台、高性能的 Web 开发框架，用于构建 API、MVC 和实时应用。

86. 中间件是什么？

答案： 中间件是按顺序处理 HTTP 请求和响应的组件管道。

87. 依赖注入在 ASP.NET Core 中有什么作用？

答案： 依赖注入用于解耦对象创建和依赖关系管理，提升可测试性与可维护性。

88. 常见服务生命周期有哪些？

答案： 常见有 Transient、Scoped 和 Singleton。

89. Scoped 生命周期适合什么场景？

答案： 适合同一个请求内共享状态的服务，如数据库上下文。

90. 什么是配置系统？

答案： 配置系统用于从 appsettings.json、环境变量、命令行等多来源读取配置。

91. 什么是日志系统？

答案： 日志系统用于记录应用运行状态、错误和业务关键事件，便于监控和排障。

92. 什么是最小 API？

答案： 最小 API 是 ASP.NET Core 提供的轻量接口定义方式，适合简单服务和微服务场景。

93. 什么是过滤器？

答案： 过滤器用于在 MVC 或 Web API 执行流程中插入横切逻辑，如鉴权、异常处理和结果包装。

94. 什么是模型绑定？

答案： 模型绑定会把请求中的路由、查询、表单或请求体数据映射到方法参数或模型对象。

95. 什么是 IHostedService？

答案： IHostedService 用于实现应用后台运行任务，如定时任务或消息消费。

96. 什么是仓储模式？

答案： 仓储模式用于封装数据访问逻辑，但是否需要应结合项目复杂度权衡，避免过度抽象。

97. 什么是单元测试友好的代码？

答案： 通常指依赖清晰、职责单一、外部资源可替换、逻辑可预测的代码。

98. 面试中如何回答 C# 的优势？

答案： 可以从语言现代化、类型系统强、生态成熟、工具链完善和企业级开发能力强几个方面回答。

99. 如何系统回答 .NET 工程问题？

答案： 可以按运行时、语言特性、框架能力、性能、可维护性和工程实践几个维度组织答案。

100. 如何总结 .NET / C# 的核心价值？

答案： 它的核心价值在于以强类型、现代语言特性、成熟运行时和完善生态支持构建稳定、可维护、可扩展的企业级应用。

现代 C# 特性

101. 什么是 yield return？

答案： yield return 用于迭代器方法（返回 IEnumerable<T>）中，让方法每次 yield return 一个值后暂停执行，调用方通过 foreach 或 MoveNext() 逐步消费。实现惰性求值，不需要一次性生成所有数据。yield break 用于提前结束迭代。适合大集合遍历、流式数据处理和分页生成等场景。

102. ValueTask 和 Task 的区别是什么？

答案： Task 始终是堆上的引用类型对象；ValueTask 是结构体，在异步操作同步完成（如命中缓存）时可避免堆分配，减少 GC 压力。但 ValueTask 有限制：只能 await 一次，不能调用 .Result 多次，不适合多次等待或存储。适合高频调用且通常同步完成的热路径（如缓存读取、Buffer 操作）。

103. 什么是可空引用类型（Nullable Reference Types）？

答案： C# 8 引入，通过 #nullable enable 或项目文件配置开启。启用后，普通引用类型（如 string）默认不可为 null，可能为 null 的引用需显式声明为 string?。编译器在可能出现空引用的地方发出警告，帮助在编译期发现潜在的 NullReferenceException，是提升代码健壮性的重要手段。

104. 什么是 init 访问器？

答案： C# 9 引入，init 属性访问器只允许在对象初始化阶段（构造函数或对象初始化器）赋值，之后变为只读。例如 public string Name { get; init; }。常与 record 类型配合使用，实现不可变对象而不需要复杂的只读构造，比 private set 更严格。

105. 什么是主构造函数（Primary Constructor）？

答案： C# 12 引入，允许在类或结构体声明处直接定义构造函数参数，参数在整个类体中可用，无需手动声明字段并赋值。语法：class MyService(ILogger<MyService> logger, IOptions<Config> options) { } 。简化了依赖注入场景大量的样板代码，是现代 C# 推荐的简洁写法。

106. 什么是 IAsyncEnumerable<T>？

答案： IAsyncEnumerable<T> 支持异步枚举，配合 await foreach 使用。适合流式处理异步数据源，如分批从数据库读取（EF Core AsAsyncEnumerable()）、处理消息流、读取大文件，避免一次性加载全部数据到内存。方法中用 yield return 配合 async 声明即可实现。

107. 什么是 Source Generator？

答案： Source Generator 是 .NET 5+ 引入的编译时代码生成机制，分析器在编译过程中生成额外的 C# 源文件并编入编译。常用于：减少反射开销（如 System.Text.Json 序列化、正则表达式 Regex.GeneratedRegex）、DI 注册代码生成、避免 AOT 兼容性问题。提升运行时性能，减少启动时的动态成本。

108. 什么是 record struct？

答案： C# 10 引入，record struct 是值类型的记录，结合了 struct 的值语义（栈分配、无堆分配）和 record 的声明简洁性（自动生成 Equals、GetHashCode、ToString、解构等）。record class 是引用类型；record struct 默认可变，readonly record struct 才完全不可变。适合小型数据载体的高性能场景。

109. 什么是模式匹配的常见用法？

答案： C# 7+ 持续增强的特性。常见模式：类型模式 if (obj is string s)、属性模式 if (p is { Age: > 18 })、位置模式（解构）if (p is (x, y))、列表模式 if (arr is [1, 2, ..])、switch 表达式配合模式。使类型判断和条件分支更简洁直观，避免大量 as/is + 强转组合。

110. Span<T> 和 Memory<T> 的区别是什么？

答案： Span<T> 是 ref struct，只能在栈上存在，不能存储为字段、不能跨 await、不能装箱；Memory<T> 是普通结构体，可以存储为字段、跨异步使用。两者都表示连续内存片段，零拷贝操作数组/字符串子段，避免 Substring、ToArray 等额外分配。高性能解析、序列化场景常用。

进程、线程与多线程

111. 进程和线程的区别是什么？

答案： 进程是操作系统资源分配和隔离的基本单位，拥有独立的地址空间、句柄等资源；线程是进程内的执行单元，是 CPU 调度的基本单位，同一进程的多个线程共享进程的内存和资源。创建进程开销大、通信成本高；线程更轻量，但需要自行处理同步。

112. 什么是线程池？为什么推荐使用它？

答案： 线程池是系统维护的一组可复用工作线程的集合，通过 ThreadPool 提供。它避免频繁创建/销毁线程的开销，并通过工作队列自动调整并发度。推荐用于大量短命任务，Task.Run 默认就是基于线程池执行的。

113. Thread、ThreadPool 和 Task 的区别是什么？

答案： Thread 是最底层的线程对象，可显式控制创建、优先级、前后台等，但开销大；ThreadPool 复用线程，减少创建销毁开销；Task 是更高层的异步抽象，默认运行在线程池上，支持返回值、组合、取消和异常捕获，是日常推荐的并发/异步编程模型。

114. 前台线程和后台线程的区别是什么？

答案： 前台线程会阻止进程退出；后台线程在进程所有前台线程结束后会被自动终止。默认 Thread 是前台线程，可通过 IsBackground 设置。主线程结束时，进程不会等待后台线程完成。

115. 多线程有哪些常见应用场景？

答案： 并行处理大数据集、后台任务（日志、消息发送）、提高 UI 响应性（异步 I/O）、Web 服务并发处理请求、生产者-消费者模型等。多线程提升吞吐量和资源利用率，但也会带来同步、死锁、上下文切换等成本。

116. 什么是竞态条件（Race Condition）？

答案： 竞态条件指多个线程同时访问和修改共享数据，结果依赖于线程执行顺序，导致数据不一致或行为异常。它是最典型的多线程 bug，需通过锁、原子操作等同步机制避免。

117. 什么是上下文切换？

答案： 上下文切换指操作系统暂停当前线程，保存其状态（寄存器、程序计数器等），再恢复另一个线程执行的过程。频繁上下文切换会带来性能开销，因此线程数量并非越多越好。

118. Thread.Sleep 和 Task.Delay 的区别是什么？

答案： Thread.Sleep 阻塞当前线程直到超时，占用线程资源；Task.Delay 是异步等待，不阻塞线程，配合 await 使用。在异步代码中应使用 await Task.Delay 而不是 Thread.Sleep。

119. 什么是 volatile 关键字？

答案： volatile 告诉编译器该字段可能被多个线程修改，读写在访问时都从内存执行（防止缓存/重排优化），保证访问的可见性。但它不提供原子性，也不能替代锁，适合标记单个简单字段（如布尔标志）的可见性场景。

120. 什么是 Interlocked？

答案： Interlocked 提供对整数等类型的原子操作，如 Increment、Add、CompareExchange、Exchange。它保证多线程下读-改-写操作是原子的，无需加锁，性能优于 lock，适合计数器等场景。

121. 什么是原子操作？

答案： 原子操作指不可被中断、要么全部完成要么不执行的操作，多线程下不会出现中间状态。CPU 指令级原子操作（Interlocked、volatile）是最轻量的同步手段，但只能覆盖简单读写。

线程安全与锁

122. 线程安全有哪几种实现方式？

答案： 常见方式：1) 使用锁（lock/Monitor、Mutex、Semaphore、ReaderWriterLockSlim）；2) 使用原子操作（Interlocked）；3) 使用线程安全集合（ConcurrentDictionary 等）；4) 使用 volatile 保证可见性；5) 使用不可变对象避免共享修改；6) 使用 async/await 减少共享状态。选择时权衡性能与复杂度。

123. lock 语句的底层机制是什么？

答案： lock 是 Monitor.Enter/Monitor.Exit 的语法糖：lock(obj){} 等价于 Monitor.Enter(obj) 进入 try 块，finally 中 Monitor.Exit(obj)。Monitor 保证同一时刻只有一个线程进入临界区，支持递归、等待和通知（Wait/Pulse）。为避免死锁，锁对象应始终是私有 readonly 引用类型。

124. 为什么 lock 不能锁定值类型？

答案： 因为 Monitor.Enter 需要引用类型对象作为同步块标识，值类型会被装箱成新对象，每次装箱都是不同实例，无法实现互斥。所以锁对象必须是引用类型，且是稳定、私有的字段。

125. 为什么不要 lock(this) 或锁定公开对象？

答案： this 或公开对象可能被外部代码意外地用于锁定，造成死锁或不可控竞争。最佳实践是锁定一个私有、只读的专门同步对象，避免把锁暴露给外部。

126. 什么是死锁？如何避免？

答案： 死锁指两个及以上线程各自持有资源并等待对方释放，导致互相永远阻塞。四要素：互斥、占有且等待、不可抢占、循环等待。避免方法：按固定顺序获取锁、使用超时（Monitor.TryEnter）、尽量减少锁持有时间、避免嵌套锁、使用更高层抽象（如 SemaphoreSlim、Channel）替代手工锁。

127. Mutex 和 lock 的区别是什么？

答案： Mutex 是系统级互斥对象，可跨进程同步，创建开销大；lock（Monitor）只用于进程内线程同步，开销小、性能好。只在需要跨进程互斥（如保证单实例程序）时才用 Mutex。

128. Semaphore 和 SemaphoreSlim 是什么？

答案： 信号量用于限制同时访问某资源的线程数量，维护一个计数器。Semaphore 可跨进程、基于系统内核；SemaphoreSlim 是轻量版本，仅进程内使用，性能更好，支持 WaitAsync。适合限流、连接池等场景。

129. ReaderWriterLockSlim 适合什么场景？

答案： 它区分读锁和写锁：多个读者可并发持有读锁，写者独占写锁。适合"读多写少"场景（如缓存、配置），能显著提升并发读性能。注意写锁会阻塞所有读者，且默认不支持递归。

130. 线程安全的集合类有哪些？

答案： ConcurrentDictionary<TKey,TValue>、ConcurrentQueue<T>、ConcurrentStack<T>、ConcurrentBag<T>、BlockingCollection<T>。它们内部使用细粒度锁或无锁算法（CAS），比在整个集合外加锁更高效。

131. lock 和 ConcurrentDictionary 的选择原则是什么？

答案： 如果只是单个原子操作（如按 key 读写），优先用 ConcurrentDictionary；如果需要对多个操作组合成原子事务（如先检查再更新多个 key），则需用 lock 包住整个逻辑，因为并发集合无法保证跨操作的原子性。

内存、堆栈、指针、不安全代码与内存泄漏

132. 栈（Stack）和堆（Heap）的区别是什么？

答案： 栈（调用栈）由系统自动管理，分配释放快、空间小，存放方法调用帧、局部变量；堆（托管堆）由 GC 管理，存放引用类型对象，分配慢、空间大。值类型通常分配在栈上（作为字段时随所属对象位置而定），引用类型对象在堆上，栈上只保存其引用。

133. 值类型一定分配在栈上吗？

答案： 不绝对。值类型局部变量确实在栈上，但如果是引用类型对象的字段，则随对象一起分配在堆上；如果是装箱或捕获到 Lambda/异步方法中，也会在堆上。栈上分配只针对"纯局部且未被装箱/捕获"的值类型。

134. 什么是装箱？它发生在哪里？

答案： 装箱是把值类型包装成 object 引用类型的过程，会在托管堆上分配一个包装对象并复制值进去。它发生在值被转换为 object/接口时，是性能热点之一，应避免在循环等高频路径触发。

135. 什么是 unsafe 代码和指针？

答案： C# 默认不直接操作指针，但在 unsafe 块中可使用原生指针（如 int*），用于底层、高性能或与原生代码互操作（P/Invoke）场景。使用指针需开启 AllowUnsafeBlocks，代码不可被验证，要极其谨慎，避免悬垂指针和越界访问。

136. fixed 语句的作用是什么？

答案： fixed 在 unsafe 代码中固定一个托管对象（如数组、字符串），防止 GC 移动内存时改变其地址，使指针能安全指向它。例如 fixed (int* p = arr) { ... }。固定对象会增加 GC 压力，应尽量缩短固定时间。

137. 什么是 stackalloc？

答案： stackalloc 在栈上分配一块原生内存（Span<T>），不经过托管堆、无 GC 压力、速度快。适合临时小型缓冲区，但栈空间有限，不能分配过大内存，生命周期受限于当前方法。

138. 指针和引用（ref）的区别是什么？

答案： 指针（unsafe 中）是原生地址，可任意运算（p++）、强制类型转换，不安全；引用（ref/托管引用）由运行时验证、类型安全，不能做任意算术运算。日常开发优先用 ref、Span<T> 而非指针。

139. 什么是 GC 分代（Generation）？

答案： GC 把托管堆对象分为 0、1、2 三代：新对象在第 0 代，存活则升代。GC 优先回收 0 代（频率高、成本低），大对象堆（LOH）单独管理。分代机制利用"年轻对象大多短命"的假设高效工作。

140. 什么是大对象堆（LOH）？

答案： 大于约 85000 字节的对象分配在 LOH，不参与分代压缩。LOH 收集是满代回收，代价高，且内存碎片可能造成"看似有内存却分配失败"。应避免频繁创建大对象，可复用缓冲池（ArrayPool<T>）。

141. 什么是内存泄漏？.NET 中会发生吗？

答案： 内存泄漏指不再使用的对象仍被引用，无法被 GC 回收，导致内存持续增长、最终 OutOfMemoryException。虽然 .NET 有自动 GC，但开发者仍会造成逻辑上的泄漏——对象"还在被引用"所以 GC 不会回收。.NET 应用同样会发生内存泄漏，需要主动排查。

142. .NET 内存泄漏的常见原因有哪些？

答案：

  1. 事件/委托未取消订阅：订阅者被发布者强引用，无法回收；2) 静态字段或单例持有大对象/集合，且无限增长（如缓存、日志、List）；3) 未释放非托管资源（文件、Socket、数据库连接、COM）且未实现 IDisposable；4) 匿名方法/Lambda 捕获对象形成长生命周期引用；5) Timer、Task、后台线程长期持有对象；6) 字符串或 string.Format 在循环中创建大量中间对象（多为临时压力）。排查重点是"谁还在引用这个对象"。

143. 如何检测和定位内存泄漏？

答案：

  1. 用 dotnet-counters 观察内存增长趋势；2) 用 dotnet-dump 抓取 dump，配合 dotnet-gcdump 分析对象图和引用链，找出未被回收的对象；3) 用 WinDbg/SOS 的 !dumpheap、!gcroot 定位根引用；4) 结合日志、复现场景对比内存基线。定位核心是找到强根引用并解除（如取消事件订阅、控制缓存上限）。

144. IDisposable、using 与终结器如何防止资源泄漏？

答案： 非托管资源必须显式释放：类实现 IDisposable.Dispose() 释放资源；调用方用 using（或 await using）保证作用域结束即释放；终结器（析构函数）作为兜底，时机不确定，仅作最后防线。推荐使用 SafeHandle 封装原生句柄，并遵循 Dispose 模式，避免把终结器当常规清理手段。

反射与元数据

145. 什么是反射（Reflection）？

答案： 反射是 .NET 提供的在运行时检查程序集、类型、成员、属性、方法的能力，通过 System.Reflection 实现。可动态创建实例、调用方法、读取特性（Attribute），是实现动态扩展、插件系统、序列化框架的基础。

146. typeof、GetType() 和 Type.GetType() 的区别是什么？

答案： typeof(T) 是编译期获取类型的 Type 对象，最快；obj.GetType() 是运行时获取对象的实际类型；Type.GetType("全名") 是通过字符串名称在运行时查找类型。前两者编译期安全，不需要字符串。

147. 反射的优缺点是什么？

答案： 优点是灵活、支持动态扩展、可跨程序集操作；缺点是性能开销大（调用比直接调用慢几个数量级）、破坏编译期类型安全、难以调试。现代做法是用 Source Generator、表达式树、动态缓存替代高频反射。

148. 如何提升反射的性能？

答案：

  1. 缓存 Type、MethodInfo、委托，避免重复反射查找；2) 用表达式树或 DynamicMethod 编译成委托；3) 用 MethodInfo.CreateDelegate 创建强类型委托；4) 优先用 Source Generator 在编译期生成代码（如 System.Text.Json）。现代 .NET 的序列化、依赖注入大多已改用编译期生成。

149. 什么是 Attribute（特性）？

答案： 特性是附加在类型、方法、属性等元数据上的声明式标签，可携带参数，运行时通过反射读取。应用广泛：序列化标记（[JsonIgnore]）、数据校验（[Required]）、权限、日志、模型绑定等。

150. 反射有哪些典型应用场景？

答案： 依赖注入容器（按类型解析构造对象）、ORM（实体映射）、序列化/反序列化框架、插件/模块系统（按程序集加载激活类型）、测试框架（发现运行测试方法）、AOP（动态代理）。这些场景都需要在运行时发现和操作类型。

网络、串口、TCP 与 UDP

151. .NET 中网络编程的常用类有哪些？

答案： System.Net.Http.HttpClient（HTTP 客户端）、System.Net.Sockets.Socket（底层套接字）、TcpClient/TcpListener（TCP 封装）、UdpClient（UDP 封装）、HttpListener（HTTP 服务器）、Dns（域名解析）。ASP.NET Core 还提供 SignalR（实时通信）、gRPC 等高级抽象。

152. TCP 和 UDP 的区别是什么？

答案： TCP 是面向连接、可靠的字节流协议：三次握手建立连接、数据有序、重传和确认、不丢包不重复，但有连接开销和延迟；UDP 是无连接、不可靠的数据报协议：不保证顺序和送达、无握手，但开销小、延迟低、支持广播/组播。TCP 适合文件传输、网页、数据库等要求可靠的应用；UDP 适合视频通话、实时游戏、DNS 查询等对延迟敏感、可容忍丢包的应用。

153. TCP 三次握手的过程是什么？

答案： 客户端发送 SYN 请求建立连接（SYN_SENT）；服务端收到后回复 SYN+ACK（SYN_RCVD）；客户端再发 ACK 确认，连接建立（ESTABLISHED）。三次握手是为了确认双方收发能力正常，并同步初始序列号。

154. TCP 四次挥手的过程是什么？

答案： 主动关闭方发 FIN；对方回 ACK；对方再发 FIN；主动方回 ACK 后连接关闭（TIME_WAIT）。比握手多一次是因为 TCP 全双工，每一方向都要单独关闭。TIME_WAIT 用于确保最后的 ACK 到达，避免旧连接数据干扰。

155. 什么是 TCP 粘包/拆包？如何解决？

答案： TCP 是字节流，不保留消息边界，多次发送可能被合并（粘包）或一次发送被拆开（拆包）。解决方式：1) 定长消息；2) 分隔符（如换行、\r\n）；3) 消息头加长度字段（最常用）；4) 自定义协议帧。服务端需维护接收缓冲区和状态机解析完整消息。

156. 什么是 TcpClient 和 TcpListener？

答案： TcpListener 用于服务端监听端口、接受连接并返回 TcpClient；TcpClient 封装 TCP 连接的 NetworkStream 供读写。它们是 Socket 的高层封装，适合多数应用层编程；需要底层控制（自定义协议、多路复用）时直接用 Socket。

157. UdpClient 适合什么场景？

答案： UdpClient 封装 UDP 套接字，支持发送/接收数据报，常用于实时音视频、游戏状态同步、DNS 查询、局域网广播/组播等对实时性要求高、可容忍丢包的场景。使用时无连接，直接 Send/Receive，可靠性需自行处理（如应用层重传）。

158. 什么是 Socket 的阻塞/非阻塞模式？

答案： 阻塞模式下 Receive/Send 阻塞当前线程直到有数据或完成；非阻塞立即返回，无数据时抛 WouldBlock。异步编程（BeginReceive、SocketAsyncEventArgs、async/await）可在不阻塞线程的情况下处理 I/O。阻塞模式简单但占用线程，非阻塞/异步更适合高并发服务器。

159. .NET 中如何实现串口通信？

答案： 使用 System.IO.Ports.SerialPort 类。设置端口名（如 COM3）、波特率（如 9600）、数据位、停止位、校验位，调用 Open()，通过 Read/Write 或 DataReceived 事件收发数据，结束时 Close()。常用于工业设备、传感器、条码枪、嵌入式设备通信。

160. 串口通信中需要注意哪些问题？

答案：

  1. 端口被占用时打开失败，需捕获异常并重试；2) DataReceived 事件在后台线程触发，访问 UI 需跨线程调度；3) 数据可能不完整到达，需按帧/长度协议解析；4) 波特率、校验位须与对端一致；5) 拔插设备后端口可能变化，需枚举可用端口（GetPortNames）；6) 结束时及时释放资源。

161. 什么是 HttpClient？为什么建议复用单个实例？

答案： HttpClient 用于发送 HTTP 请求，内部维护连接池。频繁新建实例会导致 TCP 连接反复建立、耗尽 TIME_WAIT 端口，造成性能下降甚至 Socket 异常。因此建议复用同一实例（或用 IHttpClientFactory）来复用连接、管理生命周期和 DNS 变更。

162. 什么是 HttpClient 的超时与取消？

答案： HttpClient.Timeout 设置请求总超时；CancellationToken 用于主动取消在途请求，二者配合可避免请求无限挂起，防止外部服务故障拖垮整个应用。

163. 什么是 Socket 端口耗尽（TIME_WAIT）问题？

答案： TCP 连接关闭后，主动关闭方会进入 TIME_WAIT 状态一段时间。高并发短连接过多会耗尽可用端口，导致新连接失败。缓解方式：复用连接、开启端口重用（SO_REUSEADDR）、调整系统 TIME_WAIT 策略、减少短连接。

软件闪退与崩溃处理

164. 程序闪退/崩溃的常见原因有哪些？

答案： 未处理的异常（如 NullReferenceException、越界）、内存不足/栈溢出、无限递归、非托管内存错误（堆损坏）、并发死锁导致卡死被系统结束、配置或依赖缺失、外部资源（数据库、文件）异常等。定位需结合日志、崩溃转储和代码审查。

165. 如何捕获未处理异常避免闪退？

答案： 订阅全局异常事件：AppDomain.CurrentDomain.UnhandledException（应用级未处理异常）、TaskScheduler.UnobservedTaskException（未观察的 Task 异常）、DispatcherUnhandledException（WPF UI 线程异常）。在这些处理器中记录日志、收集崩溃转储、做优雅降级或重启。注意 StackOverflowException、OutOfMemoryException 无法通过捕获正常恢复。

166. 什么是崩溃转储（Dump）？如何分析？

答案： 崩溃转储是进程崩溃时内存状态的快照，包含线程栈、对象、模块信息。可用 dotnet-dump、WinDbg、ProcDump 抓取，用 !analyze、!clrstack、!pe 等命令查看异常类型和调用栈，定位崩溃根因。生产环境建议开启自动转储（如 DOTNET_DbgEnableMiniDump 或 ProcDump 规则）。

167. 为什么 StackOverflowException 很难处理？

答案： 因为栈溢出时栈空间已耗尽，无法安全执行异常处理代码和分配新帧，运行时直接终止进程，try-catch 无效。预防比捕获更重要：避免无限递归、过深递归改用迭代或尾递归、控制调用深度。.NET 6+ 中栈溢出默认即终止进程。

168. 如何定位"偶发闪退"？

答案：

  1. 全面记录日志（异常、环境、输入上下文）；2) 开启崩溃转储并分析 dump；3) 用内存分析工具排查泄漏和对象异常增长；4) 检查并发和资源竞争；5) 关注 P/Invoke 原生代码的内存错误；6) 逐步二分排查（A/B、缩小输入）。偶发问题往往与并发、时序或资源耗尽相关。

169. 什么是优雅退出（Graceful Shutdown）？

答案： 收到终止信号（Ctrl+C、SIGTERM、主机停止）时，先停止接收新请求、完成在途任务、释放资源、保存状态，再退出进程。ASP.NET Core 用 IHostApplicationLifetime、StopAsync 实现。优雅退出能避免数据丢失和资源泄漏，是生产级应用必备能力。

设计模式

170. 什么是设计模式？为什么重要？

答案： 设计模式是针对反复出现的设计问题总结的成熟解决方案模板，是设计思想而非代码片段。它提高复用性、可读性和可维护性，是团队沟通的共同语言。分类：创建型（单例、工厂、建造者）、结构型（适配器、装饰器、代理）、行为型（观察者、策略、模板方法）。

171. 什么是单例模式？如何保证线程安全？

答案： 单例模式保证一个类只有一个实例并全局可访问。线程安全实现：1) Lazy<T>（默认 LazyThreadSafetyMode.ExecutionAndPublication），最推荐；2) 静态字段初始化（CLR 保证线程安全）；3) lock + 双重检查（Double-Checked Locking）。Lazy<T> 是当前 C# 最优雅的线程安全单例写法。

172. 双重检查锁定（Double-Checked Locking）是什么？

答案： 先判断实例是否为 null（无锁快速路径），为 null 才进入锁，加锁后再次检查，为 null 才创建。既保证线程安全，又避免每次访问都加锁的性能开销。由于 .NET 内存模型，字段需声明 volatile，或直接用 Lazy<T> 更稳妥。

173. 什么是工厂模式？

答案： 工厂模式把对象创建逻辑从使用方解耦。简单工厂按参数返回不同对象；工厂方法由子类决定实例化哪个类；抽象工厂创建一族相关对象。好处是集中创建逻辑、便于扩展、降低耦合。

174. 什么是观察者模式？.NET 中如何体现？

答案： 观察者模式定义一对多依赖：被观察对象状态变化时自动通知所有观察者。.NET 中典型实现是 event（事件）+ 委托：发布者声明 event，订阅者 += 订阅，触发时批量通知。也体现在 INotifyPropertyChanged、IProgress<T> 等接口上。

175. 什么是策略模式？

答案： 策略模式把一组可互换的算法封装成独立类（策略），让调用方在运行时选择，避免大量 if-else。.NET 中常通过接口 + 依赖注入（如注入不同 IComparer<T>、支付策略）实现，符合开闭原则。

176. 什么是建造者模式？

答案： 建造者模式将复杂对象的构建过程与表示分离，通过一步步构建（链式 SetX().SetY().Build()）生成对象，隐藏内部组装逻辑。适用于构造参数多、配置复杂的对象（如 StringBuilder、DbContextOptionsBuilder、HttpClient 配置）。

177. 什么是依赖注入（DI）？和设计模式的关系？

答案： 依赖注入是一种设计原则/模式，把依赖对象的创建和注入交给容器，而不是在类内部自行 new。它实现控制反转（IoC），降低耦合、提升可测试性。ASP.NET Core 内置 DI 容器，支持构造函数注入，是现代 .NET 应用标配。

178. 常见的设计原则（SOLID）是什么？

答案： S 单一职责（一个类只做一件事）；O 开闭原则（对扩展开放、对修改关闭）；L 里氏替换（子类可替换父类）；I 接口隔离（小而专的接口优于大而全）；D 依赖倒置（依赖抽象而非具体实现）。理解并应用这些原则比背模式更重要。

179. 什么是装饰器模式？举例说明

答案： 装饰器模式动态给对象增加职责，通过包装对象并保持相同接口实现。.NET 典型例子：Stream 系列（BufferedStream 包装 FileStream）、ASP.NET Core 中间件、缓存/日志装饰器。装饰器按顺序叠加，职责灵活组合。

最新 .NET / C# 热点

180. 什么是原生 AOT（NativeAOT）？

答案： .NET 7+ 支持把应用编译成原生机器码（NativeAOT），无需 JIT，启动快、内存低、便于分发单文件，但失去部分反射和动态加载能力（需裁剪反射、用 Source Generator 替代）。适合云原生、Serverless、小体积高启动要求的场景。

181. 什么是集合表达式（Collection Expressions）？

答案： C# 12 引入，用 [...] 简洁创建数组/集合：int[] a = [1, 2, 3];、List<string> list = ["a", "b"];，并支持展开 [..other]。统一了多种集合初始化语法，是 C# 12 最常用的新特性之一。

182. 什么是主构造函数（Primary Constructors）？有什么好处？

答案： C# 12 允许在类/结构声明处直接写构造函数参数，参数在整个类体中可用。好处：消除大量手写字段和构造器样板代码，尤其适合依赖注入。注意参数不是字段，如需长期保留应显式赋值给字段。

183. 什么是键控服务（Keyed Services）？

答案： .NET 8 为 DI 增加按 key 解析服务的能力，用 [FromKeyedServices("name")] 或 AddKeyedSingleton("name", ...) 注册和注入不同实现。适合按配置/名称选择多个同接口实现的场景（如多种存储），比手动字典映射更优雅。

184. 什么是 gRPC？

答案： gRPC 是基于 HTTP/2 的高性能 RPC 框架，使用 Protocol Buffers（Protobuf）做接口定义和序列化，支持流式通信、双向流。.NET 一等支持，适合微服务内部高性能通信。相比 REST 更高效、强类型、支持双向流，但调试和浏览器兼容性较差。

185. 什么是 SignalR？

答案： SignalR 是 ASP.NET Core 的实时通信库，支持 WebSocket、Server-Sent Events 等传输并自动协商最优方式，用于服务端向客户端实时推送（聊天、通知、看板、实时进度）。提供 Hub 抽象、分组、断线重连机制，客户端可多平台接入。

186. 什么是 Blazor？

答案： Blazor 允许用 C# 和 Razor 组件构建交互式 Web UI，两种模式：Server（服务端运行、SignalR 更新 UI）和 WebAssembly（浏览器运行 C#）。适合复用 C# 技能栈的团队和全栈 .NET 场景。

187. .NET 9 的 AOT 和性能优化热点是什么？

答案： .NET 9 进一步推进原生 AOT 普及，改进了 System.Text.Json、正则（编译期生成）、LINQ（向量化）、序列化反射裁剪。热点方向：更快启动、更低分配、更好容器化（.NET Aspire）、更强的高性能（向量 SIMD）。

188. 什么是 .NET Aspire？

答案： .NET Aspire 是面向云原生应用的开发栈，提供统一编排、服务发现、配置和遥测（OpenTelemetry），内置 Redis、PostgreSQL、Azure Service Bus 等依赖的云原生模式，简化微服务和分布式应用的开发、部署与可观测性。

189. 什么是 FrozenSet / FrozenDictionary？

答案： .NET 8 引入的不可变、深度优化过的只读集合。创建后不能修改，内部按使用模式优化查找性能，适合启动时构建、之后频繁只读查询的场景（如配置、白名单、路由表）。

190. async/await 的最佳实践有哪些？

答案：

  1. 全程 async/await，避免 .Result/.Wait() 同步阻塞；2) 库代码用 ConfigureAwait(false)；3) 避免 async void（仅事件用）；4) 用 ValueTask 优化热路径；5) 用 CancellationToken 支持取消；6) 异步代码中不要用 CPU 密集混搭；7) 用 AsyncLocal 传递上下文。核心是"异步一直到底，避免同步阻塞线程"。

191. 什么是 AsyncLocal<T>？

答案： AsyncLocal<T> 在异步流程中传递上下文数据，即使 await 切换线程，值也能沿调用链传递，类似逻辑执行上下文。常用于传递请求 ID、用户标识、分布式追踪（OpenTelemetry 的 Activity）等横切信息。

192. 如何衡量并优化 .NET 应用性能？

答案：

  1. 用 BenchmarkDotNet 做微基准；2) 用 dotnet-counters、dotnet-trace、dotnet-dump、PerfView 做运行时观测；3) 关注分配量、GC 次数、CPU、内存；4) 减少装箱、字符串拼接（用 StringBuilder/String.Create）、避免热路径 LINQ；5) 用 Span<T>/Memory<T>、ArrayPool<T> 减少分配；6) 用 Source Generator 减少反射。原则：先测量、后优化，避免过早优化。

这些题目覆盖了 C# 基础、面向对象、泛型与 LINQ、异步编程、内存与异常、ASP.NET Core 与工程实践、现代 C# 新特性，并新增了进程与线程、线程安全与锁、内存堆栈指针、内存泄漏、反射、网络与串口、TCP/UDP、软件闪退处理、设计模式以及 .NET 8/9 最新热点，适合作为 .NET / C# 面试系统复习资料。
