Go 语言学习教程：给 TypeScript / C# 开发者

你已经会 TypeScript 和 C#。这篇教程不重复"什么是变量、什么是函数"，只讲 Go 与 TS/C# 的差异、Go 的独特设计、以及最容易踩的坑。每节附对比代码，快速建立映射。

0. 核心差异速览

维度 TypeScript C# Go
运行时 JS / Node CLR (JIT) 编译为原生机器码（无 VM）
类型系统 静态类型，编译期 静态类型，运行时 静态类型，编译期，无异常
并发模型 Event Loop / Promise async/await + 线程 goroutine + channel（CSP）
空值 null/undefined null nil（指针/接口/slice/map/channel 可空）
错误处理 try/catch try/catch/finally 返回 error 值，不用异常
面向对象 class + interface class + interface 结构体 + 隐式接口（无继承）
继承 extends 继承 没有继承，用组合（嵌入）
泛型 有 有（强大） 1.18+ 引入，较简单
包管理 npm NuGet go mod（内置）
缩进 不敏感 不敏感 gofmt 强制（gofmt 自动格式化）

一句话总结：Go 是"编译为原生码 + 极简语法 + goroutine 并发 + 无异常无继承"的语言。TS/C# 开发者最大的转变是：从面向对象继承思维转向组合 + 并发思维。

1. 环境与工具链

1.1 安装与验证

go version    # go1.22+

1.2 模块（对应 npm / .csproj）

go mod init myproject    # 初始化模块，生成 go.mod（对应 package.json）
go get github.com/gin-gonic/gin   # 安装依赖（对应 npm install）
go mod tidy              # 清理/同步依赖

go.mod 记录模块路径和依赖版本，go.sum 锁定哈希。

1.3 常用命令

go run main.go     # 编译并运行（对应 ts-node / dotnet run）
go build           # 编译为可执行文件
go test            # 运行测试（对应 npm test / dotnet test）
go fmt             # 自动格式化（项目保存时推荐装 gofmt 插件）
go vet             # 静态检查（对应 ESLint / Roslyn）

2. 基础语法

2.1 变量声明

var x int = 10           // 完整声明（对应 int x = 10;）
y := 20                  // 短变量声明（最常用，类型自动推导）
var name string = "Go"
var a, b int = 1, 2      // 多变量声明
var c, d = 1, "hello"    // 不同类型也行
const Pi = 3.14          // 常量（对应 const）

对比 C#：

int x = 10;
var y = 20;  // 注意：C# 的 var 也是编译期推导
const double Pi = 3.14;

对比 TS：

let x: number = 10;
const y = 20;  // 注意：TS 用 const 表示不可重新赋值

坑：Go 中 未使用的局部变量会编译报错（TS/C# 只警告），这是强制的代码卫生。

2.2 基本类型

int, int8, int16, int32, int64    // 有符号整数（对应 long/int/short）
uint, uint8, uint16, uint32, uint64  // 无符号
float32, float64                   // 浮点（对应 float/double）
bool                               // true/false（对应 bool）
string                             // 字符串（不可变，对应 string）
byte                              // uint8 别名（对应 byte）
rune                              // int32 别名，代表 Unicode 码点（对应 char）

注意：Go 没有 char，用 rune 表示单个字符；字符串是字节切片（string 底层是 []byte）。

2.3 控制流

// if（条件不需要括号，但大括号必须）
if x > 10 {
    fmt.Println("大于10")
} else if x > 5 {
    fmt.Println("大于5")
} else {
    fmt.Println("小")
}

// if 可以带初始化语句（常见：if val := compute(); val > 0 { ... }）
if err := doSomething(); err != nil {
    log.Fatal(err)
}

// for（Go 只有 for，没有 while）
for i := 0; i < 10; i++ { }          // 标准 for
for x > 0 { }                        // 相当于 while
for { }                              // 无限循环（对应 while(true)）
for i, v := range slice { }          // 遍历（对应 for...of / foreach）

// switch（不需要 break，自动 break；fallthrough 显式）
switch day {
case 1, 2, 3:
    fmt.Println("工作日")
case 6, 7:
    fmt.Println("周末")
default:
    fmt.Println("未知")
}

对比 C#：

if (x > 10) { }
for (int i = 0; i < 10; i++) { }
switch (day) { case 1: break; }  // C# 需要 break（除非写 fall-through）

2.4 数组与切片

// 数组（固定长度，极少直接用）
var arr [5]int = [5]int{1, 2, 3, 4, 5}

// 切片（动态数组，最常用，对应 List<T> / Array）
s := []int{1, 2, 3}
s = append(s, 4)          // 添加（对应 List.Add）
len(s)                    // 长度（对应 .Count / .length）
cap(s)                    // 容量（对应内部数组大小）
s[1:3]                    // 切片（对应 slice / Array.Slice）

// make 预分配（避免扩容拷贝）
s := make([]int, 0, 100)  // 长度0，容量100

对比 C#：

List<int> s = new List<int> {1, 2, 3};
s.Add(4);
s.Count;

坑：切片是引用类型，底层共享数组，修改一个切片可能影响另一个：

a := []int{1, 2, 3}
b := a[1:]   // b 和 a 共享底层数组！
b[0] = 99    // a[1] 也变成 99

2.5 Map（对应 Dictionary / Map）

m := map[string]int{"alice": 25, "bob": 30}
m["carol"] = 35                    // 新增
age := m["alice"]                  // 读取（key 不存在返回零值）
delete(m, "bob")                   // 删除
v, ok := m["david"]                // 安全读取（对应 TryGetValue）
if ok { fmt.Println(v) }

// 初始化空 map
m := make(map[string]int)

对比 C#：

Dictionary<string, int> m = new() { {"alice", 25} };
m.TryGetValue("david", out var age);

3. 函数

3.1 基本定义

func add(a int, b int) int {
    return a + b
}

// 相同类型参数可简写
func add(a, b int) int {
    return a + b
}

3.2 多返回值（Go 特色！）

func divide(a, b int) (int, int) {
    return a / b, a % b
}

quotient, remainder := divide(10, 3)

对比 C#：C# 没有原生多返回值，用 out 参数或元组 (int, int)。 对比 TS：TS 用数组解构 const [q, r] = divide(10, 3)。

3.3 命名返回值

func sum(nums ...int) (result int) {
    for _, n := range nums {
        result += n
    }
    return  // 裸 return，自动返回命名返回值 result
}

3.4 可变参数（对应 params / ...rest）

func sum(nums ...int) int {
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}
sum(1, 2, 3, 4)  // 10

3.5 defer（C# 没有对应，类似 using/finally）

func readFile(path string) error {
    f, err := os.Open(path)
    if err != nil {
        return err
    }
    defer f.Close()  // 函数返回前执行，注册顺序 LIFO

    // ... 读写文件
    return nil
}

对比 C#：

using var f = new FileStream(path, FileMode.Open);
// 相当于 using（自动 Dispose）

关键：defer 的参数在注册时就求值，但执行延迟到函数返回。这是常见坑。

3.6 函数是一等公民

// 函数类型
type MathFunc func(int, int) int

func apply(a, b int, f MathFunc) int {
    return f(a, b)
}

// 匿名函数（对应 lambda）
result := apply(3, 4, func(a, b int) int { return a + b })

4. 结构体与方法（对应 class）

4.1 结构体定义

type User struct {
    Name string
    Age  int
}

// 构造函数（Go 没有构造函数，用工厂函数约定）
func NewUser(name string, age int) *User {
    return &User{Name: name, Age: age}
}

u := NewUser("Alice", 25)

4.2 方法（给结构体绑定函数）

func (u *User) Greet() string {
    return fmt.Sprintf("Hello, I'm %s, %d years old", u.Name, u.Age)
}

u := NewUser("Alice", 25)
u.Greet()

对比 C#：

public class User {
    public string Name { get; set; }
    public int Age { get; set; }
    public string Greet() => $"Hello, I'm {Name}";
}

4.3 组合（替代继承）

Go 没有继承，用**嵌入（embedding）**实现代码复用：

type Animal struct {
    Name string
}

func (a *Animal) Eat() {
    fmt.Println(a.Name, "is eating")
}

type Dog struct {
    Animal  // 嵌入 Animal（不是继承！）
    Breed   string
}

d := Dog{Animal: Animal{Name: "Buddy"}, Breed: "Golden"}
d.Eat()        // 直接调用 Animal 的方法（提升）
d.Name         // 也能直接访问 Animal 的字段

对比 C#：

public class Dog : Animal { ... }  // C# 是真继承

关键：嵌入不是继承，没有多态关系。Dog 不是 Animal，只是拥有 Animal 的能力。

5. 接口（隐式实现，Go 特色）

5.1 接口定义与实现

// 定义接口
type Speaker interface {
    Speak() string
}

// 任何类型只要有 Speak() string 方法，就自动实现了 Speaker
// 不需要 implements 关键字！
type Dog struct{}
func (d Dog) Speak() string { return "Woof!" }

type Cat struct{}
func (c Cat) Speak() string { return "Meow!" }

// 使用
var s Speaker = Dog{}
fmt.Println(s.Speak())  // Woof!

对比 C#：

public interface ISpeaker { string Speak(); }
public class Dog : ISpeaker { public string Speak() => "Woof!"; }  // 显式声明

5.2 空接口 any（对应 object / unknown）

var x any = 42        // 可以是任何类型
var y any = "hello"

// 类型断言（对应 C# 的 as / is）
n, ok := x.(int)     // n=42, ok=true
s, ok := y.(string)  // s="hello", ok=true

5.3 类型开关

func describe(i any) {
    switch v := i.(type) {
    case int:
        fmt.Println("整数:", v)
    case string:
        fmt.Println("字符串:", v)
    default:
        fmt.Println("未知类型")
    }
}

6. 并发（Go 最大特色！）

6.1 goroutine（对应线程，但轻量得多）

go func() {
    fmt.Println("在后台运行")
}()

// 启动多个 goroutine
for i := 0; i < 5; i++ {
    go func(n int) {
        fmt.Println(n)
    }(i)
}

关键差异：

  • C# 线程：OS 线程，栈 ~1MB，创建开销大；
  • Go goroutine：用户态协程，初始栈 ~2KB，由 Go 调度器管理，创建开销极小；
  • 一个 Go 程序可以跑几十万个 goroutine，C# 线程做不到。

6.2 channel（goroutine 间通信）

// 无缓冲 channel（同步通信）
ch := make(chan string)

go func() {
    ch <- "hello"   // 发送
}()

msg := <-ch         // 接收
fmt.Println(msg)    // hello

6.3 带缓冲 channel

ch := make(chan int, 3)  // 缓冲 3 个
ch <- 1
ch <- 2
ch <- 3
// ch <- 4  // 会阻塞，缓冲满了

fmt.Println(<-ch)  // 1

6.4 select（对应 C# 的 Task.WhenAny）

select {
case msg1 := <-ch1:
    fmt.Println("从 ch1:", msg1)
case msg2 := <-ch2:
    fmt.Println("从 ch2:", msg2)
case <-time.After(time.Second):
    fmt.Println("超时")
}

6.5 WaitGroup（等待一组 goroutine 完成）

var wg sync.WaitGroup

for i := 0; i < 5; i++ {
    wg.Add(1)
    go func(n int) {
        defer wg.Done()
        fmt.Println("处理", n)
    }(i)
}

wg.Wait()  // 等所有 goroutine 完成
fmt.Println("全部完成")

6.6 context（对应 C# 的 CancellationToken）

ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()

go func() {
    select {
    case <-ctx.Done():
        fmt.Println("超时或取消:", ctx.Err())
    case <-time.After(1 * time.Second):
        fmt.Println("完成")
    }
}()

对比 C#：

var cts = new CancellationTokenSource(TimeSpan.FromSeconds(2));
await Task.Run(async () => { ... }, cts.Token);

7. 错误处理（Go 没有异常！）

7.1 基本模式

result, err := doSomething()
if err != nil {
    return fmt.Errorf("处理失败: %w", err)  // 包装错误
}

对比 C#：

try {
    var result = DoSomething();
} catch (Exception e) {
    throw new Exception("处理失败", e);
}

7.2 errors.Is / errors.As（错误链判断）

if errors.Is(err, os.ErrNotExist) {
    fmt.Println("文件不存在")
}

var perr *os.PathError
if errors.As(err, &perr) {
    fmt.Println("路径错误:", perr.Path)
}

7.3 panic / recover（类似 try-catch，但不推荐）

func safeDivide(a, b int) (result int) {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("捕获 panic:", r)
            result = 0
        }
    }()
    if b == 0 {
        panic("除以零")
    }
    return a / b
}

关键：Go 不推荐用 panic/recover 做常规错误处理，只用于不可恢复的错误。普通错误用 error 返回。

8. 常见坑（TS/C# 开发者必看）

坑 1：未使用的变量报错

x := 10
// 没使用 x，直接编译错误！

TS/C# 只警告，Go 强制。用 _ = x 显式忽略。

坑 2：切片共享底层数组

a := []int{1, 2, 3}
b := a[1:]
b[0] = 99  // a[1] 也变 99

需要独立副本时用 copy() 或 append([]int{}, a...)。

坑 3：map 不能并发读写

m := make(map[string]int)
go func() { m["a"] = 1 }()  // 写
go func() { _ = m["a"] }()  // 读 → 致命错误：concurrent map read/write

用 sync.Mutex 或 sync.Map。

坑 4：闭包捕获循环变量

for i := 0; i < 3; i++ {
    go func() {
        fmt.Println(i)  // 可能全输出 3！（捕获的是变量引用）
    }()
}
// 正确：传参
for i := 0; i < 3; i++ {
    go func(n int) {
        fmt.Println(n)
    }(i)
}

坑 5：defer 参数立即求值

func f() {
    i := 1
    defer fmt.Println("值:", i)  // 输出 1（注册时求值）
    i = 2
}

坑 6：nil 接口陷阱

var err error = nil
// err 是 nil
var err error = (*MyError)(nil)
// err 不是 nil！（接口有类型，但值为 nil）

坑 7：没有泛型（1.18 之前）

Go 1.18 才引入泛型，使用时注意版本。泛型用法比 C# 简单但功能有限。

坑 8：for-range 遍历是值拷贝

for _, v := range users {
    v.Name = "new"  // 修改的是副本，原 users 不变！
}
// 正确：用索引
for i := range users {
    users[i].Name = "new"
}

10. 学习路径

  1. 第 1 周：过一遍本教程，用 Go 重写一个你熟悉的 C#/TS 小工具；
  2. 第 2 周：学 goroutine/channel/context，写一个并发爬虫或 Web 服务；
  3. 第 3 周：学 Gin + GORM，写一个 REST API；
  4. 持续：读 Effective Go、Go Code Review Comments，养成 go fmt + go vet 习惯。

核心心态：Go 追求极简，不追求"面向对象的完美"。 embrace：无继承、无异常、显式错误处理、goroutine 并发。你会发现很多 C#/TS 的"高级特性"在 Go 里被刻意省略了——这是设计选择，不是缺陷。
