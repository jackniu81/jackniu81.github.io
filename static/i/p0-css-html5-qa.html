CSS / HTML5 常见面试题 124 道（附答案）

HTML5 基础

1. 什么是 HTML？

答案： HTML 是超文本标记语言，用于定义网页的结构和语义。

2. 什么是 HTML5？

答案： HTML5 是 HTML 的现代标准版本，增强了语义化、多媒体、表单和 Web API 能力。

3. 为什么要强调语义化标签？

答案： 语义化有助于提升可读性、可维护性、SEO 和无障碍访问能力。

4. 常见语义化标签有哪些？

答案： 常见有 header、nav、main、section、article、aside、footer 等。

5. div 和语义化标签的区别是什么？

答案： div 只有结构作用，语义化标签还表达内容含义和页面角色。

6. 什么是块级元素和行内元素？

答案： 块级元素通常独占一行，行内元素通常不会独占一行，只包裹内容本身。

7. img 标签的 alt 属性有什么作用？

答案： alt 用于图片无法显示时提供替代文本，也有助于无障碍和搜索引擎理解内容。

8. meta viewport 的作用是什么？

答案： 它用于控制移动端页面视口宽度和缩放行为，是响应式布局基础配置之一。

9. defer 和 async 的区别是什么？

答案： 两者都能异步下载脚本；async 下载完立即执行，顺序不可控；defer 会按顺序在 DOM 解析完成后执行。

10. 什么是无障碍访问？

答案： 无障碍访问是让残障用户也能顺畅使用网页，包括语义标签、键盘操作、对比度和屏幕阅读器支持等。

11. HTML5 新增了哪些表单能力？

答案： 新增了更多输入类型、占位符、校验属性和更好的移动端适配能力。

12. 常见 HTML5 输入类型有哪些？

答案： 如 email、number、date、url、tel、range 等。

13. label 标签为什么重要？

答案： 它能提升表单可用性和无障碍体验，点击标签即可聚焦关联控件。

14. canvas 和 svg 的区别是什么？

答案： canvas 更适合像素级绘制和高频渲染；svg 更适合矢量图形和结构化图形场景。

15. audio 和 video 标签带来了什么？

答案： 它们让网页可以原生嵌入音视频，而不必依赖传统插件。

16. 什么是自定义数据属性？

答案： 自定义数据属性以 data- 开头，可用于在 DOM 上存储扩展信息。

17. localStorage 和 sessionStorage 属于 HTML5 哪类能力？

答案： 它们属于 Web Storage 本地存储能力。

18. 什么是拖拽 API？

答案： HTML5 提供了拖拽相关事件和数据传递机制，用于实现元素拖放交互。

19. 什么是 Web Worker？

答案： Web Worker 允许在后台线程执行脚本，避免阻塞主线程 UI。

20. 什么是 WebSocket？

答案： WebSocket 提供浏览器与服务器之间的全双工长连接通信能力。

CSS 基础

21. CSS 是什么？

答案： CSS 是层叠样式表，用于控制网页的外观、布局和视觉表现。

22. CSS 的引入方式有哪些？

答案： 常见有行内样式、内部样式表和外部样式表，实际项目中多使用外部样式表。

23. 什么是选择器？

答案： 选择器用于指定样式作用的元素范围，如标签、类、ID 和属性选择器等。

24. 常见选择器有哪些？

答案： 常见有标签选择器、类选择器、ID 选择器、后代选择器、伪类、伪元素等。

25. 什么是伪类？

答案： 伪类用于描述元素的特殊状态，如 :hover、:focus、:nth-child()。例如 li:nth-child(odd) 可选中奇数位置的列表项，常用于表格斑马纹。

26. 什么是伪元素？

答案： 伪元素用于选中元素内容的特殊部分，如 ::before、::after。

27. CSS 优先级如何计算？

答案： 一般比较内联样式、ID、类/属性/伪类、标签/伪元素的权重，权重高者优先。

28. !important 有什么作用？

答案： 它会强行提高声明优先级，但不应滥用，否则会降低样式可维护性。

29. 什么是继承？

答案： 继承指某些样式属性会从父元素传递给子元素，如字体和颜色等。

30. 什么是层叠？

答案： 层叠是指多个样式规则共同作用时，浏览器根据来源、优先级和顺序决定最终结果。

盒模型与布局

31. 什么是盒模型？

答案： 盒模型描述元素由 content、padding、border、margin 组成。

32. 标准盒模型和怪异盒模型的区别是什么？

答案： 标准盒模型中宽高只包含内容区；怪异盒模型中宽高包含内容、内边距和边框。

33. box-sizing: border-box 有什么好处？

答案： 它让元素宽高计算更直观，更适合实际项目布局。

34. 什么是外边距塌陷？

答案： 垂直相邻块级元素的 margin 可能合并为一个更大的外边距，这种现象叫塌陷。

35. 如何解决外边距塌陷？

答案： 可通过创建 BFC、设置边框、内边距或改变布局方式来解决。

36. 什么是 BFC（Block Formatting Context）

答案： BFC 是块级格式化上下文，可用于隔离布局影响、清除浮动和避免外边距塌陷等。

37. 如何触发 BFC

答案： 常见方式有设置 display: flow-root、 overflow: hidden、float、position: absolute 等。

38. display 常见取值有哪些？

答案： 常见有 block、inline、inline-block、none、flex、grid。

39. position 常见取值有哪些？

答案： 常见有 static、relative、absolute、fixed、sticky。

40. relative 和 absolute 的区别是什么？

答案： relative 相对自身原位置偏移；absolute 脱离文档流并相对最近定位祖先定位。

41. fixed 的特点是什么？

答案： fixed 元素相对视口定位，通常不随页面滚动而移动。

42. sticky 是什么？

答案： sticky 是粘性定位，在达到阈值前表现像普通定位，达到后像固定定位。

43. 什么是浮动？

答案： 浮动最初用于文字环绕图片，也被早期大量用于布局，但现在常被 Flex 和 Grid 替代。

44. 如何清除浮动？

答案： 常见方式有清除元素、伪元素清除和触发 BFC。

45. Flex 布局适合什么场景？

答案： 适合一维布局，如横向或纵向排列、居中对齐和分布控制。

46. Grid 布局适合什么场景？

答案： 适合二维布局，如页面区域划分、表格式模块和复杂卡片排列。

47. Flex 中 justify-content 的作用是什么？

答案： 它控制主轴方向上项目的对齐和分布方式。

48. Flex 中 align-items 的作用是什么？

答案： 它控制交叉轴方向上项目的整体对齐方式。

49. 如何让元素水平垂直居中？

答案： 常见方式有 Flex 居中、Grid 居中、定位加变换等，现代项目最常用 Flex。

50. gap 有什么作用？

答案： gap 用于控制 Flex 或 Grid 子项之间的间距，比手动设边距更统一。

响应式与视觉表现

51. 什么是响应式设计？

答案： 响应式设计是让页面在不同设备和屏幕尺寸下都能良好展示和交互。

52. 什么是媒体查询？

答案： 媒体查询允许根据屏幕宽度、方向、分辨率等条件应用不同样式。

53. max-width 和 min-width 的区别是什么？

答案： max-width 常用于桌面优先向下兼容；min-width 常用于移动优先逐步增强。

54. 什么是移动优先？

答案： 移动优先是先为小屏设备设计基础样式，再逐步增强到更大屏幕。

55. 相对单位有哪些？

答案： 常见有 %、em、rem、vw、vh 等。

56. em 和 rem 的区别是什么？

答案： em 相对当前元素字体大小，rem 相对根元素字体大小。

57. vw 和 vh 的作用是什么？

答案： 它们分别相对视口宽度和高度，常用于全屏布局和响应式尺寸控制。

58. 什么是 CSS 变量？

答案： CSS 变量通过 --name 定义，可复用主题值、间距、颜色等设计令牌。

59. calc() 的作用是什么？

答案： calc() 用于在 CSS 中进行简单计算，适合动态尺寸组合。

60. 什么是过渡 transition？

答案： 过渡用于让属性变化在一段时间内平滑完成。

61. 什么是动画 animation？

答案： 动画通过 @keyframes 定义关键帧，可实现更复杂的连续变化效果。

62. transform 常见用途有哪些？

答案： 常用于位移、旋转、缩放和倾斜，并且通常性能优于直接改布局属性。

63. 为什么动画常推荐用 transform 和 opacity？

答案： 因为它们通常更容易由浏览器进行合成层优化，性能更好。

64. 什么是层叠上下文？

答案： 层叠上下文决定元素的堆叠顺序和 z-index 生效范围。

65. z-index 为什么有时不生效？

答案： 因为元素可能不在同一层叠上下文中，或没有形成可定位上下文。

实战与工程化

66. 什么是 CSS Reset？

答案： CSS Reset 用于清除浏览器默认样式差异，建立统一的样式基线。

67. Normalize.css 和 Reset 的区别是什么？

答案： Normalize 更偏保留合理默认样式并做统一，Reset 更倾向完全清空默认样式。

68. 什么是 CSS Modules？

答案： CSS Modules 通过局部作用域避免类名冲突，适合组件化开发。

69. 什么是 BEM 命名规范？

答案： BEM 是一种 CSS 类命名方法，通过 Block、Element、Modifier 提升可维护性。

70. 为什么大型项目需要命名规范？

答案： 因为规范能减少样式冲突、提升协作效率并增强代码可读性。

71. 什么是预处理器？

答案： 预处理器如 Sass、Less 提供变量、嵌套、混入等能力，提高样式开发效率。

⚠️ 版本更新（2026-09 核实）：预处理器曾经的核心卖点"嵌套"和"变量"如今已有原生替代——CSS 原生嵌套（见第 111 题）和 CSS 自定义属性（见第 58 题），新项目不一定要为此引入 Sass/Less；但 mixin、函数、循环、条件编译等能力预处理器仍有价值。

72. Sass 的常见优势是什么？

答案： 它支持变量、嵌套、函数、混入和模块化能力，适合中大型样式工程。

73. 什么是后处理器？

答案： 后处理器在 CSS 编译后再做转换，如自动加前缀、压缩和兼容性处理。

74. Autoprefixer 的作用是什么？

答案： 它根据浏览器兼容配置自动补全厂商前缀。

75. 什么是 Tailwind CSS？

答案： Tailwind CSS 是一种原子化 CSS 框架，通过大量工具类快速组合界面样式。

76. 原子化 CSS 的优缺点是什么？

答案： 优点是开发快、复用强、样式一致；缺点是类名较多，初学者阅读成本较高。

77. 什么是关键渲染路径？

答案： 关键渲染路径是浏览器从下载资源到生成可交互页面的核心流程。

78. 为什么 CSS 会阻塞渲染？

答案： 因为浏览器在构建渲染树前需要先拿到关键样式，避免页面闪烁和布局不稳定。

79. 如何优化 CSS 加载性能？

答案： 可以压缩、拆分、按需加载、减少冗余规则和提取关键 CSS。

80. 为什么要减少重排和重绘？

答案： 因为频繁布局和绘制会影响页面性能和交互流畅度。

81. 什么是重排？

答案： 重排是元素几何属性变化后，浏览器重新计算布局的过程。

82. 什么是重绘？

答案： 重绘是元素样式变化但不影响布局时，浏览器重新绘制视觉表现的过程。

83. 哪些操作更容易触发重排？

答案： 如修改宽高、位置、字体大小、插入删除节点和读取某些布局属性后再写入。

84. 什么是雪碧图？

答案： 雪碧图是把多个小图合并到一张图中，通过背景定位减少请求次数的优化方式。

85. 现代项目中雪碧图还常用吗？

答案： 使用频率下降了，很多场景已被 SVG、Icon Font 或组件化图标方案替代。

常见问题与面试表达

86. 什么是 SEO 友好的 HTML 结构？

答案： 它通常具有清晰语义、合理标题层级、可读文本内容和规范元信息。

87. 为什么按钮操作应优先使用 button 而不是 div？

答案： 因为 button 自带语义、可聚焦和键盘交互支持，更符合无障碍和可维护性要求。

88. 图片懒加载有什么意义？

答案： 它能减少首屏资源加载压力，提升首屏速度和节省带宽。

89. 什么是响应式图片？

答案： 响应式图片通过不同资源和尺寸适配不同设备，常结合 srcset、sizes 使用。

90. overflow: hidden 常见用途有哪些？

答案： 可用于裁剪溢出内容、触发 BFC、隐藏滚动条区域外元素等。

91. 什么是文本溢出省略号？

答案： 通常通过 overflow: hidden、text-overflow: ellipsis 和 white-space: nowrap 实现单行省略。

92. 多行文本省略常见怎么做？

答案： 常见用 -webkit-line-clamp 配合弹性盒相关属性实现。

93. 什么是 aspect-ratio？

答案： aspect-ratio 用于声明元素宽高比，简化图片和卡片比例控制。

94. 为什么样式抖动会影响体验？

答案： 因为布局突然变化会影响用户点击和阅读，增加 CLS 等体验指标风险。

95. 什么是 CLS？

答案： CLS 是累计布局偏移指标，用于衡量页面加载过程中布局稳定性。

96. 如何减少布局偏移？

答案： 可以为图片和异步内容预留尺寸，避免后加载内容把页面挤动。

97. 面试中如何回答 Flex 和 Grid 的取舍？

答案： 可以说 Flex 更适合一维排列，Grid 更适合二维区域布局，实际项目往往搭配使用。

98. 面试中如何系统回答 CSS 问题？

答案： 可以按原理、布局模型、适用场景、兼容性和性能注意点来组织答案。

99. 面试中如何系统回答 HTML5 问题？

答案： 可以围绕语义化、表单、多媒体、存储、离线能力和 Web API 扩展来展开。

100. 如何总结 CSS / HTML5 的核心价值？

答案： HTML5 负责结构和语义，CSS 负责表现和布局，二者共同决定页面的可读性、可用性和用户体验。

现代 CSS 与 HTML 特性

101. 什么是 CSS 容器查询（Container Queries）？

答案： 容器查询允许根据父容器的尺寸（而不是视口）来应用样式，使用 @container 规则。父元素需声明 container-type: inline-size。比媒体查询粒度更细，让同一个组件在不同容器宽度下有不同表现，实现真正的组件级响应式，无需修改父级结构。

102. CSS clamp() 有什么作用？

答案： clamp(min, preferred, max) 在最小值和最大值之间动态计算值。典型用法：font-size: clamp(14px, 2vw, 20px) 让字体随视口缩放但不超出范围，无需媒体查询。常用于响应式字号、间距和容器宽度，实现流体设计。

103. 什么是 CSS 逻辑属性？

答案： 逻辑属性用逻辑方向（block/inline、start/end）代替物理方向（top/left），如 margin-inline-start 代替 margin-left，padding-block-end 代替 padding-bottom。在多语言（LTR/RTL）场景自动适配书写方向，无需为不同语言单独覆盖物理方向样式。

104. 什么是 :is() 和 :where() 伪类？

答案： :is() 接受选择器列表，匹配其中任一选择器的元素，优先级取参数中最高的选择器；:where() 功能相同但优先级始终为 0，不影响整体权重。二者都可简化重复选择器，如 :is(h1, h2, h3) a 代替三条重复规则。

105. 什么是 CSS Scroll Snap？

答案： Scroll Snap 让滚动在特定位置自动吸附停止，在容器设 scroll-snap-type，子元素设 scroll-snap-align。无需 JavaScript 即可实现轮播、全屏分页滚动、横向卡片吸附等体验，性能比 JS 监听方案更好。

106. display: contents 有什么作用？

答案： display: contents 让元素自身不生成盒子（相当于"透明"），但其子元素正常渲染。常用于在 Flex/Grid 容器中插入语义化包装元素而不影响布局，如 <ul> 加 display: contents 后其 <li> 直接参与外层 Grid 布局。

⚠️ 版本更新（2026-09 核实）：早期浏览器存在严重 bug——该元素会被移出可访问性树，屏幕阅读器读不到它的内容（"角色丢失"）。该问题已在 Firefox 62+、Chrome/Edge 89+ 修复，Safari 16/17 起也集中修复了大批相关问题。现代浏览器中可放心用于 div/span 等无语义包装层；但若用在 button、table、ul 等自带语义和交互的元素上，仍建议用读屏器实测确认。

107. 什么是 CSS Subgrid？

答案： Subgrid 允许子元素继承祖先 Grid 容器的行列轨道，通过 grid-template-columns: subgrid 声明。解决了嵌套 Grid 中内层元素难以与外层对齐的问题，常用于卡片列表中标题、内容、操作区跨卡片对齐的场景。

⚠️ 版本更新（2026-09 核实）：Subgrid 现已全面可用——Firefox 71+、Safari 16+、Chrome/Edge 117+，2023 年 9 月达成 Baseline 新增可用（newly available），2026 年 3 月起已进入广泛可用（widely available），不再属于"需要观望的新特性"。

108. aspect-ratio 属性有什么用？

答案： aspect-ratio: 16/9 声明元素固定宽高比，当设置宽度后高度自动按比例计算，无需传统的 padding-top 百分比黑客技巧。常用于图片占位、视频容器、头像框、卡片等需要固定比例的元素。

109. 什么是 CSS @layer（级联层）？

答案： @layer 允许将样式分组到具名层中，并通过 @layer base, components, utilities 声明层的优先级顺序。高层级的样式总是覆盖低层级，无论选择器权重如何。解决了第三方库样式权重难以覆盖、工具类 vs 组件样式冲突等问题，是现代 CSS 架构的重要新工具。

110. CSS color-scheme 和深色模式适配有什么最佳实践？

答案： 通过媒体查询 @media (prefers-color-scheme: dark) 检测系统深色模式并应用变量：在 :root 定义亮色变量，在媒体查询内覆盖为深色值。结合 color-scheme: light dark 让表单控件、滚动条等浏览器原生元素也自动适配。也可配合 data-theme 属性实现手动切换。

111. 🆕 什么是 CSS 原生嵌套（Native Nesting）？和 Sass 嵌套有什么区别？

答案： 原生嵌套指浏览器直接支持在一条规则内部书写子规则，用 & 代表父选择器，无需 Sass/Less 预编译。

.card {
  padding: 16px;
  &:hover { box-shadow: 0 2px 8px rgb(0 0 0 / .15); }
  & > .title { font-size: 18px; }
  .body { color: #555; }          /* 放宽语法：等价于 .card .body */
  &.featured { border: 2px solid gold; }
}
  • 演进：2023 年中的初版要求嵌套选择器必须以 & 开头，且早期规范包含 @nest 规则；2023 年底规范改为"放宽嵌套解析"，可直接写普通选择器，@nest 已废弃并从规范移除。保守写法可始终显式写 &。
  • 与 Sass 区别：原生嵌套即标准 CSS、浏览器直接解析，而 Sass 还提供 mixin、函数、循环、条件、模块系统等原生没有的能力；优先级按展开后的选择器正常计算，& 语义与 Sass 基本一致。
  • 场景：组件样式就近收拢、:hover/媒体查询与主规则写在一起，替代部分预处理器场景。
  • 兼容性（2026-09 核实）：Chrome/Edge 112+、Firefox 117+、Safari 17+ 起支持嵌套（2023 年下半年），放宽语法需 Chrome/Edge 120+、Safari 17.2+。2023 年 9 月成为 Baseline 新增可用，2026 年已属广泛可用。

112. 🆕 :has() 父选择器能做什么？

答案： :has() 是第一个能根据后代/兄弟元素反选父元素或前序兄弟元素的选择器，被俗称为"父选择器"。

/* 含图片的文章切成两栏 */
article:has(img) { display: grid; grid-template-columns: 1fr 2fr; }
/* 表单字段内含错误提示时，输入框变红 */
.field:has(.error) input { border-color: #e53e3e; }
/* 复选框勾选后高亮 label */
label:has(input[type="checkbox"]:checked) { background: #eef6ff; }
/* "前序兄弟"选择：标题后紧跟副标题时收紧标题下边距 */
h2:has(+ .subtitle) { margin-bottom: 4px; }
/* 空容器判断 */
.section:not(:has(*)) { display: none; }
  • 场景：表单校验状态联动、卡片含图自适应、:has(:checked) 实现纯 CSS 手风琴/Tab、空状态隐藏、前序兄弟样式调整。
  • 性能注意：避免 body :has(*) 这类全局、深层、多层嵌套的匹配，尽量限定在类名容器内；现代引擎对选择器失效做了专项优化，局部使用没有问题。
  • 兼容性（2026-09 核实）：Safari 15.4+（2022-03）、Chrome/Edge 105+（2022-08）、Firefox 121+（2023-12）。2023 年 12 月成为 Baseline 新增可用，2026 年已进入广泛可用；不支持时整条选择器失效，可用 :is()/@supports selector(:has(*)) 做容错。

113. 🆕 View Transitions API 是什么？

答案： View Transitions API 让浏览器在两个 DOM 状态（SPA）或两次页面导航（MPA）之间自动生成截图过渡，默认是交叉淡入淡出，可自定义，无需手写动画库。

单页应用（SPA）用法：把 DOM 更新包进回调，浏览器自动捕获前后两帧：

function go(next) {
  if (!document.startViewTransition) return render(next);   // 渐进增强
  document.startViewTransition(() => render(next));
}
.hero { view-transition-name: hero; }                       /* 给元素命名，实现"共享元素" morph */
::view-transition-old(root) { animation: fade .2s ease both; }
::view-transition-new(root) { animation: fade .2s ease reverse both; }
@keyframes fade { to { opacity: 0; } }

多页应用（MPA）只需一行 CSS，同源整页导航即可转场：

@view-transition { navigation: auto; }
  • 场景：SPA 路由切换、列表→详情共享元素（大图/卡片）平滑移动、MPA 传统页面转场；可配合路由库和 Navigation API，DOM 更新放进回调里只执行一次。
  • 注意：务必包一层 @media (prefers-reduced-motion: no-preference)，为减少动效偏好的用户关闭大段动画；用 CSS.supports('view-transition-name: x') 或能力检测回退。
  • 兼容性（2026-09 核实）：同文档过渡 Chrome/Edge 111+（2023-03）、Safari 18+（2024-09）、Firefox 144+（2025-12），2025 年底成为 Baseline 新增可用；跨文档 @view-transition Chrome/Edge 126+、Safari 18.2+、Firefox 144+（2024 下半年至 2025 年底陆续到位），截至核实时尚未进入 Baseline，按渐进增强使用。

114. 🆕 Popover API 解决了什么问题？

答案： Popover 是原生"弹出层"能力：声明 popover 属性后，元素通过 popovertarget 按钮即可显隐，浏览器自动处理顶层渲染、点击外部关闭（light dismiss）和 ESC 关闭。

<button popovertarget="menu" popovertargetaction="toggle">菜单</button>
<div id="menu" popover="auto">
  <button popovertarget="menu" popovertargetaction="hide">关闭</button>
  任意弹层内容
</div>

也可用 el.showPopover()、el.hidePopover()、el.togglePopover() 控制，监听 beforetoggle/toggle 事件。取值有 auto（一次只允许一个、点击外部自动关）、manual（完全程序控制）、hint（提示气泡语义，较新）。

  • 关键特性：弹层进入 top layer（顶层），不受父级 overflow: hidden 和 z-index 影响；非模态、不锁焦、不屏蔽页面其余部分。
  • 与 <dialog> 分工：需要模态确认、焦点陷阱用 <dialog>（见第 115 题）；菜单、气泡卡片、toast、命令面板用 Popover。二者也可组合（<dialog popover>）。
  • 场景：下拉菜单、悬浮卡片、Toast 通知、@提及/搜索建议气泡，替代手写"点击外部关闭 + 动态计算层级"逻辑。
  • 兼容性（2026-09 核实）：Chrome/Edge 114+（2023-05）、Safari 17+（2023-09）、Firefox 125+（2024-04），2024 年成为 Baseline 新增可用，可放心使用 auto/manual；较新的 hint 值和 popoverhint 语义仍属有限可用。

115. 🆕 <dialog> 元素怎么用？相比手写弹窗好在哪？

答案： <dialog> 是原生对话框元素，showModal() 打开模态对话框时浏览器免费提供：顶层渲染、::backdrop 遮罩、ESC 关闭、焦点陷阱（Tab 只在弹窗内循环），关闭后焦点自动归还触发元素。

<dialog id="d">
  <h3>确认删除？</h3>
  <form method="dialog">
    <button value="cancel">取消</button>
    <button id="ok" value="ok">删除</button>
  </form>
</dialog>
<button onclick="d.showModal()">打开</button>
<script>
  d.addEventListener('close', () => {
    if (d.returnValue === 'ok') doDelete();   // form method="dialog" 自动关窗并写入 returnValue
  });
</script>
  • 三种方式：showModal()（模态，进 top layer）、show()（非模态）、close(value)（关闭并设置 returnValue）；不要手动切换 open 属性。点击遮罩关闭需自行监听 click 事件（较新的 closedby 属性可声明式实现，支持仍有限）。
  • 场景：确认框、登录/表单弹窗、图片预览、侧滑抽屉（配合定位与 transform 改样式）。与 Popover 的取舍：模态阻断用 dialog，非阻断浮层用 popover。
  • 兼容性（2026-09 核实）：Chrome 37+、Edge 79+、Firefox 98+、Safari 15.4+，2022 年起所有核心浏览器齐备，属 Baseline 广泛可用；入出场动画可配合 @starting-style（见第 118 题）。

116. 🆕 CSS Anchor Positioning（锚点定位）是什么？

答案： 锚点定位允许一个定位元素跟随另一个元素（锚点）摆放，纯 CSS 实现以前需要 Popper.js / Floating UI 才能做的气泡定位，并自带空间不足时的翻转策略。

.btn { anchor-name: --menu-btn; }

.menu {
  position: fixed;
  position-anchor: --menu-btn;
  position-area: bottom;                 /* 九宫格式声明：按钮正下方（早期草案名为 inset-area，已更名） */
  margin-top: 6px;
  position-try-fallbacks: flip-block, flip-inline;   /* 空间不够自动翻转方向 */
}

/* 也可用函数取锚点几何值 */
.menu-x {
  position: fixed;
  position-anchor: --menu-btn;
  top: anchor(bottom);
  left: anchor(center);
  translate: -50% 0;
  width: anchor-size(width);
}
  • 关键属性：anchor-name 命名锚点、position-anchor 关联、anchor()/anchor-size() 读取锚点位置与尺寸、position-area 语义化方位、position-try-fallbacks 与 @position-try 声明翻转/贴边备选方案。
  • 场景：Tooltip、下拉菜单、富文本气泡、悬浮工具栏，通常与 Popover 组合覆盖"显隐 + 定位"两件事，替换 Popper/Floating UI 一类库。
  • 兼容性（2026-09 核实）：Chrome/Edge 125+（2024-05）、Safari 26+（2025-09）、Firefox 147+（2026-01 默认开启），2026 年初才全引擎打通，属 Baseline 最新一批新增可用；旧浏览器必须用 @supports (anchor-name: --a) 回退到常规定位或 JS 方案。

117. 🆕 scroll-driven animations（滚动驱动动画）怎么实现？

答案： 它让 CSS 动画的时间轴不再跟随时间，而是跟随滚动容器的滚动进度或元素进出视口的进度，由合成线程驱动，不占用主线程。

/* 1）整页阅读进度条：跟随页面滚动 */
.progress {
  transform-origin: 0 50%;
  animation: grow linear;
  animation-timeline: scroll(root block);
}
@keyframes grow { to { transform: scaleX(1); } }

/* 2）卡片进入视口时上浮淡入 */
.card {
  animation: rise linear both;
  animation-timeline: view();
  animation-range: entry 0% entry 100%;
}
@keyframes rise { from { opacity: 0; transform: translateY(24px); } }
  • 两种时间轴：scroll() 绑定滚动容器的整体进度；view() 绑定元素自身进入/离开视口的进度（配合 animation-range 控制区间），也可用 scroll-timeline-name/view-timeline-name 命名后供其他元素引用。
  • 场景：阅读进度条、视差背景、图片/卡片入场 reveal、章节进度联动，替代 scroll 事件、IntersectionObserver 或 GSAP ScrollTrigger。
  • 坑：animation 简写会重置 animation-timeline，需写在简写之后；overflow-x: hidden 会创建滚动容器，可能意外破坏 view()；不支持的浏览器上元素会停留在首帧，务必把默认样式写成"动画结束态"并用 @supports (animation-timeline: view()) 包裹增强。
  • 兼容性（2026-09 核实）：Chrome/Edge 115+（2023-07）、Safari 26+（2025-09）；Firefox 截至 2026-09 仍未默认开启（需 about:config flag，是 Interop 2026 重点推进项），因此尚未进入 Baseline，只能按渐进增强使用。

118. 🆕 @starting-style 和 transition-behavior: allow-discrete 解决了什么？

答案： 解决 display: none ↔ 显示状态、或顶层元素（dialog/popover）首次出现时无法播放入场动画的问题。@starting-style 声明元素"首次显示那一帧"的初始值；allow-discrete 允许 display 这类离散属性参与过渡。

.pop {
  opacity: 1;
  transition:
    opacity .25s,
    display .25s allow-discrete,
    overlay .25s allow-discrete;
  @starting-style { opacity: 0; }
}
.pop[hidden] { opacity: 0; display: none; }
  • 原理：离散属性过渡时，入场在 0% 瞬间翻转、出场在 100% 瞬间翻转；overlay 属性让 dialog/popover 在出场动画结束后再离开 top layer，避免"立刻消失"。
  • 场景：弹窗、抽屉、Popover、手风琴、Toast 的纯 CSS 入/出场动画，告别"双 requestAnimationFrame + setTimeout"的 hack；也用于 display: none 的元素首次挂载动画。
  • 兼容性（2026-09 核实）：@starting-style 与 transition-behavior: allow-discrete：Chrome/Edge 117+、Safari 17.5+、Firefox 129+，2024 年 8 月成为 Baseline 新增可用；overlay 仍为有限可用（Chromium/Safari 支持，Firefox 尚未支持），不支持时只是没有退场动画，不影响显隐功能。

119. 🆕 text-wrap: balance 和 pretty 有什么用？

答案： 它们让浏览器介入换行决策：balance 平衡多行标题各行长度，消除末行只剩一两个字的"孤词"；pretty 优化长段落排版（避免孤词行、改善右侧参差），计算成本更高，适合正文。

h1, h2, h3, .card-title { text-wrap: balance; }
article p, .prose li     { text-wrap: pretty; }
  • 限制：balance 只对少量行数的短文本生效（Chrome/Safari 限 6 行以内，Firefox 限 10 行），大段正文请用 pretty。
  • 场景：新闻/营销标题、卡片标题、Hero 文案；正文段落防止末行孤词。两者都纯增强——不支持时回退普通换行，无任何副作用。
  • 兼容性（2026-09 核实）：balance Chrome/Edge 114+、Firefox 121+、Safari 17.5+，为 Baseline 2024 新增可用；pretty Chrome/Edge 117+、Safari 26+（2025-09），Firefox 截至 2026-09 尚未支持，按渐进增强使用。

120. 🆕 color-mix() 函数怎么用于主题配色？

答案： color-mix(in <色彩空间>, 颜色A x%, 颜色B) 在指定色彩空间中混合两种颜色，推荐用感知均匀的 oklch，中间色不会发灰。

:root { --brand: #2563eb; }
.btn:hover      { background: color-mix(in oklch, var(--brand) 82%, black); }  /* 加深 */
.btn:disabled   { background: color-mix(in oklch, var(--brand) 35%, white); }  /* 调浅 */
.dialog-scrim   { background: color-mix(in srgb, #000 45%, transparent); }     /* 加透明 */
  • 场景：只维护一个主色变量，派生出 hover、禁用、选中、描边、遮罩等整套色阶；深色模式用同一变量与黑/白混合派生；替代 Sass 的 darken()/lighten()（它们基于 RGB/HSV，容易发灰）。
  • 兼容性（2026-09 核实）：Chrome/Edge 111+（2023-03）、Safari 16.2+（2022-12）、Firefox 113+（2023-05），2023 年 5 月起跨核心浏览器可用，2025 年底已达 Baseline 广泛可用；需要兼容旧浏览器时在前面先写一行静态颜色兜底。

121. 🆕 容器查询单位（cqw/cqh/cqi）和 style() 容器查询是什么？

答案： 容器查询单位相对最近的查询容器尺寸（而非视口），是容器查询的配套：1cqw/1cqh = 容器宽/高的 1%，cqi/cqb 对应 inline/block 方向，另有 cqmin/cqmax。style() 查询则让 @container 按容器的计算样式（主要是自定义属性）分支。

.card-wrap { container-type: inline-size; }
.card h2 { font-size: clamp(16px, 4cqi, 28px); }   /* 组件内流式字号，随容器宽度变化 */

/* 容器不需要 container-type，自定义属性挂在任意祖先即可 */
@container style(--theme: dark) {
  .card { background: #1a1a1a; color: #eee; }
}
  • 场景：真正"自包含"的可移植组件——字号、间距跟随所在容器而非视口；style(--variant: x) 让组件外观由父级通过 CSS 变量传参，无需多写修饰类。尺寸容器查询基础见第 101 题。
  • 兼容性（2026-09 核实）：尺寸查询与 cq* 单位 Chrome/Edge 105+、Safari 16+、Firefox 110+，已属广泛可用；style() 自定义属性查询 Chrome/Edge 111+、Safari 18+，Firefox 截至 2026-09 尚未支持（开发中），需 @supports 渐进增强。

122. 🆕 HTML inert 属性有什么用？

答案： 给元素加 inert 后，该元素及其全部后代变为"惰性"：不可点击、不可 Tab 聚焦、不可编辑、浏览器页内查找不到，并且整体移出可访问性树（读屏器不可见）。

<dialog id="d">弹窗内容</dialog>
<main id="page" inert>弹窗打开期间，背景页面被完全锁住</main>
<script>
  d.addEventListener('toggle', e => page.toggleAttribute('inert', d.open));
</script>
  • 场景：模态弹窗打开时给背景容器加 inert，一行实现可靠的"锁焦 + 屏蔽读屏"，比手写 focus trap 简单；也用于轮播中离屏幻灯片、分步表单中未激活的步骤、禁用的整块 UI。
  • 注意：它不等于 pointer-events: none——后者仍可键盘聚焦、对读屏器仍可见；inert 本身没有视觉变化，需要自行加变暗/遮罩反馈。showModal() 打开的 dialog 本身会自动豁免祖先的 inert。
  • 兼容性（2026-09 核实）：Chrome/Edge 102+、Safari 15.5+（2022 年）、Firefox 112+（2023-04），2023 年 4 月成为 Baseline 新增可用，2025 年底已广泛可用。

123. 🆕 Baseline 是什么？它如何判断"新特性能不能用"？

答案： Baseline 是由 Web Platform DX（web-platform-dx/web-features 社区组）维护的 Web 特性支持分级，数据基于 browser-compat-data（MDN 页首的徽章即来自它），核心浏览器集合包含 Chrome/Edge/Firefox/Safari 的桌面与移动版：

  • 广泛可用（Widely available）：在所有核心浏览器互操作可用满 30 个月，可无兜底直接用；
  • 新增可用（Newly available）：最后一个核心浏览器刚补齐，最新版都能用，但旧设备仍需考虑降级；
  • 有限可用（Limited availability）：仍有核心引擎缺失或带前缀/flag。
  • 怎么用：查 MDN/Can I Use 上的 Baseline 徽章；工程上 Browserslist（2025 年起）已支持 baseline widely available、baseline newly available、baseline 2024 等查询，Autoprefixer/PostCSS 等工具据此决定是否转译。
  • 场景/意义：面试中遇到"这个新属性能不能上生产"，正确姿势不是只看 caniuse 一块绿色，而是确认它处于哪个 Baseline 级别，并对 newly/limited 特性配合 @supports 做渐进增强、给出降级体验。

124. 🆕 可自定义 <select> 和 Invoker Commands（command/commandfor）进展如何？

答案： 这是 Open UI 推动的两个表单/交互增强，面试中定位为"知道方案、知道支持状态、知道渐进增强"即可。

（1）Customizable Select：保留原生 <select> 的键盘与无障碍行为，通过 appearance: base-select 开放样式，配合内置 <button>、<selectedcontent> 自定义触发按钮和富文本选项（早期提案名 <selectmenu>/<selectlist> 已废弃更名）：

<style>
  select, select::picker(select) { appearance: base-select; }
</style>
<select>
  <button type="select"><selectedcontent></selectedcontent></button>
  <option>● 进行中</option>
  <option>✓ 已完成</option>
  <option>✕ 已取消</option>
</select>

（2）Invoker Commands API：用 commandfor/command 声明式触发命令，替代开关 dialog/popover 的样板 JS：

<dialog id="d">...</dialog>
<button commandfor="d" command="show-modal">打开对话框</button>
<button commandfor="tip" command="show-popover">显示提示</button>

内置命令包括 show-modal、close、request-close、show-popover、hide-popover、toggle-popover 等；自定义命令通过监听 command 事件实现，可视为 popovertarget 的泛化版本。

  • 场景：消灭自建下拉组件和弹窗开关的重复 JS；统一键盘、读屏和移动端行为。
  • 兼容性（2026-09 核实）：Customizable Select 在 Chrome/Edge 135+（2025 年）已稳定发布，Safari 27（2026 年新版）加入，Firefox 尚未支持，非 Baseline，但旧浏览器自动回退为原生控件，可安全渐进增强；command/commandfor Chrome/Edge 135+（2025-04），2025 年 12 月成为 Baseline 新增可用（Safari/Firefox 新版已跟进），旧浏览器可用点击监听兜底。

总结

这些题目覆盖了 HTML5 语义化、表单与多媒体、CSS 基础、盒模型、布局、响应式、性能优化、工程实践，以及现代 CSS/HTML 新特性——包括容器查询、原生嵌套、:has()、<dialog>/Popover、锚点定位、滚动驱动动画、View Transitions、color-mix() 与 Baseline 兼容性判断，适合作为前端基础面试系统复习资料。新特性均建议遵循"Baseline 分级 + @supports 渐进增强 + 尊重 prefers-reduced-motion"的原则落地。
