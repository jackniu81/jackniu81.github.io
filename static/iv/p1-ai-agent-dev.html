一、从零实现 Agentic Loop

1.1 什么是 Agentic Loop？

AI Agent 的核心是一个"感知 → 决策 → 行动 → 感知"的循环，每一轮都携带完整历史：

用户输入
    ↓
[循环开始]
  Step 1: 调用 LLM（携带完整 messages）
  Step 2: LLM 返回 → 判断：
          ├─ 普通回复  → 结束循环，返回给用户
          └─ Tool Call → 执行工具 → 结果加入 messages → 回到 Step 1
[循环结束]

1.2 最小可运行的 Agentic Loop（TypeScript）

import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.SILICONFLOW_KEY,
  baseURL: "https://api.siliconflow.cn/v1",
});

// 工具定义
const tools: OpenAI.Chat.ChatCompletionTool[] = [
  {
    type: "function",
    function: {
      name: "get_weather",
      description: "获取指定城市的当前天气",
      parameters: {
        type: "object",
        properties: {
          city: { type: "string", description: "城市名，如：北京" },
        },
        required: ["city"],
      },
    },
  },
];

// 工具实现
const toolHandlers: Record<string, (args: any) => string> = {
  get_weather: ({ city }) => `${city}：晴天，25°C，湿度 60%`,
};

// Agentic Loop 主函数
async function runAgent(userInput: string): Promise<string> {
  const messages: OpenAI.Chat.ChatCompletionMessageParam[] = [
    { role: "user", content: userInput },
  ];

  const MAX_STEPS = 10; // 防止无限循环

  for (let step = 0; step < MAX_STEPS; step++) {
    const response = await client.chat.completions.create({
      model: "deepseek-ai/DeepSeek-V4-Flash",
      messages,
      tools,
    });

    const message = response.choices[0].message;
    messages.push(message); // 将 AI 回复加入历史

    // 没有工具调用 → 最终回答，结束循环
    if (!message.tool_calls || message.tool_calls.length === 0) {
      return message.content ?? "";
    }

    // 执行所有工具调用
    for (const toolCall of message.tool_calls) {
      const name = toolCall.function.name;
      const args = JSON.parse(toolCall.function.arguments);
      const result = toolHandlers[name]?.(args) ?? "工具未找到";

      messages.push({
        role: "tool",
        tool_call_id: toolCall.id,
        content: result,
      });
    }
    // 继续循环，让 LLM 基于工具结果生成下一步
  }

  return "已达到最大步骤数，任务未完成";
}

// 调用
const answer = await runAgent("北京今天天气怎么样？帮我决定要不要带伞");
console.log(answer);

二、多轮对话管理

2.1 维护对话历史

class ChatSession {
  private messages: OpenAI.Chat.ChatCompletionMessageParam[] = [];
  private model: string;

  constructor(
    systemPrompt: string,
    model = "deepseek-ai/DeepSeek-V4-Flash"
  ) {
    this.model = model;
    if (systemPrompt) {
      this.messages.push({ role: "system", content: systemPrompt });
    }
  }

  async send(userInput: string): Promise<string> {
    this.messages.push({ role: "user", content: userInput });

    const response = await client.chat.completions.create({
      model: this.model,
      messages: this.messages,
    });

    const reply = response.choices[0].message.content ?? "";
    this.messages.push({ role: "assistant", content: reply });
    return reply;
  }

  // 切换模型但保留历史（应对限流时切换）
  switchModel(newModel: string) {
    this.model = newModel;
  }

  // 压缩历史（防止 context 超限）
  trimHistory(keepLast = 10) {
    const system = this.messages.filter((m) => m.role === "system");
    const rest = this.messages.filter((m) => m.role !== "system");
    this.messages = [...system, ...rest.slice(-keepLast)];
  }
}

// 使用
const session = new ChatSession("你是一个 Node.js 专家");
const r1 = await session.send("用 Express 写一个 GET 接口");
const r2 = await session.send("帮我加上参数验证");  // 携带上下文，知道上文的接口

2.2 多轮中的 Token 成本控制

// 估算 token 数（粗略：1 token ≈ 4 个英文字符 / 1.5 个中文字符）
function estimateTokens(messages: OpenAI.Chat.ChatCompletionMessageParam[]) {
  const text = messages.map((m) => String(m.content)).join("");
  return Math.ceil(text.length / 3);
}

// 超过阈值就自动压缩
async function sendWithTrim(session: ChatSession, input: string) {
  if (estimateTokens(session["messages"]) > 6000) {
    session.trimHistory(6); // 保留最近 6 轮
    console.log("已压缩对话历史");
  }
  return session.send(input);
}

三、限流与重试（生产必备）

3.1 指数退避重试

interface RetryOptions {
  maxRetries?: number;
  baseDelay?: number;   // 初始等待时间（毫秒）
  maxDelay?: number;    // 最长等待时间（毫秒）
  stopThreshold?: number; // retry-after 超过此值直接报错（配额耗尽）
}

async function withRetry<T>(
  fn: () => Promise<T>,
  options: RetryOptions = {}
): Promise<T> {
  const {
    maxRetries = 5,
    baseDelay = 1000,
    maxDelay = 30000,
    stopThreshold = 5 * 60 * 1000, // 5 分钟
  } = options;

  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await fn();
    } catch (err: any) {
      const is429 = err?.status === 429;
      const isLast = attempt === maxRetries;

      if (!is429 || isLast) throw err;

      // 读取服务器建议的等待时间
      const retryAfterSec = parseInt(err?.headers?.["retry-after"] ?? "0");
      const retryAfterMs = retryAfterSec * 1000;

      // 超过阈值 = 配额耗尽，不再重试
      if (retryAfterMs > stopThreshold) {
        console.error(`配额耗尽，retry-after=${retryAfterSec}s，停止重试`);
        throw err;
      }

      // 指数退避 + 随机抖动
      const backoff = Math.min(baseDelay * 2 ** (attempt - 1), maxDelay);
      const jitter = Math.random() * 500;
      const delay = retryAfterMs > 0 ? retryAfterMs : backoff + jitter;

      console.warn(`[重试 ${attempt}/${maxRetries}] 429 限流，等待 ${Math.round(delay / 1000)}s...`);
      await new Promise((r) => setTimeout(r, delay));
    }
  }

  throw new Error("超过最大重试次数");
}

// 使用：包裹任何 API 调用
const response = await withRetry(() =>
  client.chat.completions.create({
    model: "Qwen/Qwen2.5-7B-Instruct",
    messages: [{ role: "user", content: "你好" }],
  })
);

3.2 Agentic Loop 中的重试（中途 429 不丢上下文）

async function runAgentWithRetry(userInput: string): Promise<string> {
  const messages: OpenAI.Chat.ChatCompletionMessageParam[] = [
    { role: "user", content: userInput },
  ];

  for (let step = 0; step < 10; step++) {
    // 每次 API 调用都包裹重试逻辑
    const response = await withRetry(() =>
      client.chat.completions.create({
        model: "deepseek-ai/DeepSeek-V4-Flash",
        messages, // messages 完整保留，重试时上下文不丢失
        tools,
      })
    );

    const message = response.choices[0].message;
    messages.push(message);

    if (!message.tool_calls?.length) return message.content ?? "";

    for (const toolCall of message.tool_calls) {
      const args = JSON.parse(toolCall.function.arguments);
      const result = toolHandlers[toolCall.function.name]?.(args) ?? "error";
      messages.push({ role: "tool", tool_call_id: toolCall.id, content: result });
    }
  }
  return "步骤数超限";
}

四、流式输出（Streaming）

4.1 基础流式输出

async function streamChat(userInput: string) {
  const stream = await client.chat.completions.stream({
    model: "deepseek-ai/DeepSeek-V4-Flash",
    messages: [{ role: "user", content: userInput }],
  });

  for await (const chunk of stream) {
    const delta = chunk.choices[0]?.delta?.content;
    if (delta) process.stdout.write(delta); // 逐 token 打印
  }

  const finalMessage = await stream.finalMessage();
  return finalMessage.choices[0].message.content;
}

4.2 在 Express API 中返回流（SSE）

import express from "express";

const app = express();

app.post("/chat/stream", async (req, res) => {
  res.setHeader("Content-Type", "text/event-stream");
  res.setHeader("Cache-Control", "no-cache");
  res.setHeader("Connection", "keep-alive");

  const { message } = req.body;

  const stream = await client.chat.completions.stream({
    model: "deepseek-ai/DeepSeek-V4-Flash",
    messages: [{ role: "user", content: message }],
  });

  for await (const chunk of stream) {
    const delta = chunk.choices[0]?.delta?.content;
    if (delta) {
      res.write(`data: ${JSON.stringify({ text: delta })}\n\n`);
    }
  }

  res.write("data: [DONE]\n\n");
  res.end();
});

五、MCP（Model Context Protocol）

5.1 什么是 MCP？

MCP 是 Anthropic 于 2024 年发布的开放标准，统一了 Agent ↔ 工具 之间的通信协议：

没有 MCP：每个 Agent 框架有自己的工具调用格式，互不兼容
有了 MCP：工具（MCP Server）和 Agent（MCP Client）遵循统一协议，可以自由组合

类比：MCP 之于 AI Agent，相当于 USB 之于硬件设备——统一接口，即插即用。

5.2 MCP 架构

MCP Client（AI IDE / Agent）
    │
    │  JSON-RPC over stdio / HTTP
    │
MCP Server（工具提供方）
    ├── tools/list    → 列出所有工具
    ├── tools/call    → 执行工具
    ├── resources/list → 列出资源（文件、数据库等）
    └── prompts/list  → 列出预设 Prompt 模板

5.3 用 TypeScript 实现一个 MCP Server

import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({ name: "my-tools", version: "1.0.0" });

// 注册工具
server.tool(
  "get_weather",
  "获取指定城市的天气",
  { city: z.string().describe("城市名称，如：北京") },
  async ({ city }) => ({
    content: [{ type: "text", text: `${city}：晴天，25°C` }],
  })
);

server.tool(
  "read_file",
  "读取本地文件内容",
  { path: z.string().describe("文件路径") },
  async ({ path }) => {
    const fs = await import("fs/promises");
    const content = await fs.readFile(path, "utf-8");
    return { content: [{ type: "text", text: content }] };
  }
);

// 启动（通过 stdio 与 MCP Client 通信）
const transport = new StdioServerTransport();
await server.connect(transport);

5.4 MCP vs 直接 Function Calling 对比

维度 直接 Function Calling MCP
工具定义位置 代码里硬编码 MCP Server（独立进程）
复用性 每个项目重复写 一次实现，所有支持 MCP 的 IDE/Agent 通用
语言限制 与 Agent 同语言 任意语言实现 Server
适合场景 简单、一次性工具 通用工具、团队共享

六、工具设计最佳实践

6.1 好的工具描述 = 更准确的工具调用

LLM 靠 description 决定是否调用以及如何调用工具，描述要清晰准确：

// ❌ 差的描述
{ name: "search", description: "搜索" }

// ✅ 好的描述
{
  name: "search_web",
  description: "在互联网上搜索实时信息。当需要查找最新资讯、新闻、价格或 LLM 训练数据截止日期后的信息时使用。",
  parameters: {
    type: "object",
    properties: {
      query: {
        type: "string",
        description: "搜索关键词，用英文效果更好"
      },
      max_results: {
        type: "number",
        description: "返回结果数量，默认 5，最多 10",
        default: 5
      }
    },
    required: ["query"]
  }
}

6.2 工具返回格式

// 工具返回要简洁，避免塞入过多 token

七、生产级成本控制

7.1 模型路由策略

type TaskType = "simple" | "coding" | "complex";

const MODEL_ROUTER: Record<TaskType, string> = {
  simple:  "Qwen/Qwen2.5-7B-Instruct",       // 免费，简单问答
  coding:  "deepseek-ai/DeepSeek-V4-Flash",   // ¥1/M，代码任务
  complex: "deepseek-ai/DeepSeek-V4-Pro",     // ¥3/M，复杂推理
};

function selectModel(userInput: string): string {
  if (userInput.length < 50 && !userInput.includes("代码")) {
    return MODEL_ROUTER.simple;
  }
  if (/代码|函数|组件|接口|bug|error/i.test(userInput)) {
    return MODEL_ROUTER.coding;
  }
  return MODEL_ROUTER.complex;
}

7.2 Token 消耗监控

let totalTokensUsed = 0;
const MONTHLY_BUDGET_TOKENS = 5_000_000; // 500 万 token ≈ ¥5

async function chatWithBudget(messages: any[]) {
  if (totalTokensUsed > MONTHLY_BUDGET_TOKENS) {
    throw new Error("本月 Token 预算已用完");
  }

  const response = await client.chat.completions.create({
    model: "deepseek-ai/DeepSeek-V4-Flash",
    messages,
  });

  totalTokensUsed += response.usage?.total_tokens ?? 0;
  console.log(`本次消耗: ${response.usage?.total_tokens} tokens | 累计: ${totalTokensUsed}`);

  return response;
}

八、面试高频问题

Q1: 手写一个支持工具调用的 Agent，不用框架

见第一节的最小 Agentic Loop 实现。核心是：while 循环 + messages 数组 + tool_calls 判断。

Q2: 如何防止 Agent 无限循环？

  • 设置 MAX_STEPS 最大步骤数
  • 检测重复工具调用（相同参数调用超过 N 次则中断）
  • 设置超时（整体任务不超过 X 秒）

Q3: 多轮对话 context 越来越长怎么处理？

  • 滑动窗口：只保留最近 N 轮对话
  • 摘要压缩：用 LLM 将历史摘要成一段话，替换原始历史
  • Prompt Caching：固定前缀（系统提示、文档）缓存在服务端，只有新消息收费

Q4: Agent 在 Agentic Loop 中途遇到 429 怎么处理？

  • 每次 API 调用外层包裹 withRetry
  • retry 时携带完整的 messages 数组（包含已执行的工具结果）
  • LLM 能看到前面的上下文，从断点继续，不会"失忆"
  • 若 retry-after > 5 分钟（配额耗尽），立即报错而非等待

Q5: Streaming 和普通请求的区别？何时用 Streaming？

  • 普通：等全部生成完才返回，用户等待体验差
  • Streaming：逐 token 返回，用户看到"实时打字"效果
  • 使用场景：用户直接交互的聊天界面用 Streaming；后台批处理任务用普通请求

Q6: MCP 是什么？为什么要有它？

见第五节。核心：统一 Agent ↔ 工具 的通信协议，解决工具复用和跨框架互操作问题。一个 MCP Server 可以被 Cline、Continue.dev、Claude Desktop 等所有支持 MCP 的 Agent 直接使用。

Q7: Function Calling 和 MCP Tool 的区别？

  • Function Calling：每个项目代码里写死，不可复用
  • MCP Tool：独立进程，标准协议，任何 MCP Client 都能调用

Q8: 如何设计工具让 LLM 更精准地调用？

  • description 要清晰说明何时用、不该何时用
  • 参数的 description 要给出具体格式示例
  • 工具数量不要太多（超过 20 个性能下降），按场景精选
  • 工具返回结果要简洁，不要超过 500 tokens
