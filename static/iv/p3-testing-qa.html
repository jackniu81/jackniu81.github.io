﻿# 前端测试 常见题目（附答案）

测试基础

1. 为什么需要写测试？

答案：
① 捕获回归问题：修改代码时自动发现破坏的功能；② 提升重构信心：有测试保障才敢大胆重构；③ 活文档：测试用例本身就是对代码行为的描述；④ 强迫好设计：可测试的代码往往设计更解耦；⑤ 减少手动测试成本：CI 自动运行，节省 QA 时间。

2. 测试金字塔是什么？

答案：
从下到上：① 单元测试（最多，最快，成本最低）：测试单个函数/模块的独立逻辑；② 集成测试（中等）：测试多个模块协作，如组件+API 的交互；③ E2E 测试（最少，最慢，成本最高）：模拟真实用户操作整个应用流程。金字塔原则：多写单元测试，少写 E2E 测试，适量集成测试。

3. 什么是 TDD（测试驱动开发）？

答案：
TDD 遵循 Red-Green-Refactor 循环：① Red：先写一个会失败的测试；② Green：写最少代码让测试通过；③ Refactor：在测试保护下重构代码。好处：强制明确需求、避免过度设计、测试覆盖率高。挑战：初期效率较低，需要团队纪律。

单元测试

4. Vitest 和 Jest 的区别是什么？

答案：
Jest 是 Meta 出品的成熟测试框架，生态最丰富，配置复杂度较高，Vite 项目需要额外配置（ESM/TS 转换）。Vitest 是专为 Vite 设计的测试框架，复用 Vite 配置，开箱即用（无需额外 Babel/Transform 配置），速度更快（利用 Vite 的 HMR），API 与 Jest 兼容（迁移成本低）。新 Vite 项目推荐 Vitest，现有 Jest 项目迁移成本较低。

5. 测试的基本结构是什么？

答案：

// 使用 Vitest / Jest
import { describe, it, expect, beforeEach, afterEach } from 'vitest';

describe('UserService', () => {
  let service;

  beforeEach(() => {
    service = new UserService(mockDb);
  });

  afterEach(() => {
    vi.clearAllMocks();
  });

  it('should return user by id', async () => {
    // Arrange
    mockDb.findById.mockResolvedValue({ id: 1, name: 'Alice' });
    // Act
    const user = await service.getUser(1);
    // Assert
    expect(user).toEqual({ id: 1, name: 'Alice' });
  });

  it('should throw when user not found', async () => {
    mockDb.findById.mockResolvedValue(null);
    await expect(service.getUser(999)).rejects.toThrow('User not found');
  });
});

6. 什么是 Mock？有哪些类型？

答案：
Mock 是测试替身，替换真实依赖（如 API、数据库、定时器）使测试可控、快速、隔离。类型：
- Stub：返回预设数据，不关心调用方式
- Mock：验证调用方式（是否被调用、调用参数、调用次数）
- Spy：包装真实函数，同时记录调用信息
- Fake：轻量实现（如 in-memory 数据库替代真实 DB）

// Vitest Mock
const mockFetch = vi.fn().mockResolvedValue({ data: [] });
vi.spyOn(axios, 'get').mockResolvedValue({ data: [] });
vi.mock('./userService', () => ({ getUser: vi.fn() }));

7. 如何测试异步代码？

答案：

// 1. async/await（推荐）
it('fetches user', async () => {
  const user = await fetchUser(1);
  expect(user.name).toBe('Alice');
});

// 2. 返回 Promise
it('fetches user', () => {
  return fetchUser(1).then(user => expect(user.name).toBe('Alice'));
});

// 3. 测试 reject
it('throws on error', async () => {
  await expect(fetchUser(-1)).rejects.toThrow('Invalid ID');
});

// 4. 模拟定时器
it('debounce fires after delay', () => {
  vi.useFakeTimers();
  const fn = vi.fn();
  const debounced = debounce(fn, 300);
  debounced();
  vi.advanceTimersByTime(300);
  expect(fn).toHaveBeenCalledTimes(1);
  vi.useRealTimers();
});

8. 什么是测试覆盖率？各维度含义是什么？

答案：
- Line Coverage：代码行覆盖率（最基础）
- Statement Coverage：语句覆盖率
- Branch Coverage：分支覆盖率（if/else 每个分支）
- Function Coverage：函数覆盖率

覆盖率不等于质量，100% 覆盖率不代表没有 Bug（测试断言可能不够）。合理目标：核心业务逻辑 >80%，工具函数 >90%，不强追 100%（边际收益递减）。

组件测试

9. 什么是 React Testing Library？它的设计理念是什么？

答案：
React Testing Library（RTL）是以用户角度测试组件的库，核心理念："测试你的软件像用户使用它一样"，即通过用户可见的元素和行为（而非内部实现细节）来测试。提倡：用 getByRole/getByText/getByLabelText 而非 getByTestId（前者更接近用户视角）；测试组件的输出和副作用，不测试组件内部状态。

10. RTL 的常用查询方法有什么区别？

答案：
- getBy*：必须存在，不存在抛错（同步）
- queryBy*：可以不存在，不存在返回 null（用于断言元素不存在）
- findBy*：等待元素出现（异步，返回 Promise，适合异步渲染后的元素）
- getAllBy*/queryAllBy*/findAllBy*：以上的多元素版本

优先级（从高到低）：ByRole > ByLabelText > ByPlaceholderText > ByText > ByDisplayValue > ByAltText > ByTitle > ByTestId。

12. 什么是 MSW（Mock Service Worker）？

答案：
MSW 通过 Service Worker 在网络层拦截 API 请求，返回 Mock 数据，无需修改业务代码中的请求逻辑：

// handlers.js
import { http, HttpResponse } from 'msw';

export const handlers = [
  http.get('/api/users', () => {
    return HttpResponse.json([{ id: 1, name: 'Alice' }]);
  }),
  http.post('/api/login', async ({ request }) => {
    const body = await request.json();
    if (body.password !== 'correct') return HttpResponse.json({}, { status: 401 });
    return HttpResponse.json({ token: 'abc123' });
  }),
];

优势：同一套 handler 可用于开发环境和测试环境，真实模拟网络行为，不依赖具体请求库（axios/fetch 都拦截）。

E2E 测试

13. Playwright 和 Cypress 有什么区别？

答案：
Playwright：Microsoft 出品，支持 Chrome/Firefox/Safari/WebKit 多浏览器，速度快（并发执行），支持移动端模拟，API 更底层灵活，适合复杂多浏览器测试。Cypress：专注 Chrome（新版支持 Firefox/Edge），有实时可视化 UI（开发调试友好），API 简洁，自动等待，生态成熟，更适合前端团队快速上手。新项目可优先考虑 Playwright（跨浏览器支持更全，性能更好）。

14. 如何用 Playwright 写 E2E 测试？

答案：

import { test, expect } from '@playwright/test';

test.describe('用户登录流程', () => {
  test('成功登录后跳转到首页', async ({ page }) => {
    await page.goto('/login');

    await page.getByLabel('邮箱').fill('user@example.com');
    await page.getByLabel('密码').fill('password123');
    await page.getByRole('button', { name: '登录' }).click();

    await expect(page).toHaveURL('/dashboard');
    await expect(page.getByText('欢迎回来')).toBeVisible();
  });

  test('密码错误显示错误提示', async ({ page }) => {
    await page.goto('/login');
    await page.getByLabel('密码').fill('wrongpassword');
    await page.getByRole('button', { name: '登录' }).click();
    await expect(page.getByText('邮箱或密码错误')).toBeVisible();
  });
});

15. E2E 测试如何处理测试数据隔离？

答案：
① 每个测试独立准备数据：test.beforeEach 中调用 API 创建测试用户，afterEach 清理；② 使用唯一前缀/ID：测试数据用时间戳或 UUID 标记，避免冲突；③ 测试数据库：E2E 测试连接独立的测试数据库，测试后重置；④ 数据快照：每次测试前恢复数据库到固定快照；⑤ Mock API：E2E 层也可以用 MSW 拦截 API，不真实请求后端（牺牲一些真实性换取稳定）。
