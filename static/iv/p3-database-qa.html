数据库 常见面试题（附答案）

SQL 基础

1. 什么是关系型数据库？

答案： 关系型数据库以表（行列结构）组织数据，表间通过主键/外键关联，使用 SQL 查询，遵循 ACID 事务特性。常见：MySQL、PostgreSQL、SQL Server、SQLite（轻量）。适合结构化数据、需要事务和复杂关联查询的场景。

2. 常见的 SQL 语句类型有哪些？

答案：

  • DDL（数据定义）：CREATE TABLE、ALTER TABLE、DROP TABLE
  • DML（数据操作）：INSERT、UPDATE、DELETE
  • DQL（数据查询）：SELECT
  • DCL（数据控制）：GRANT、REVOKE
  • TCL（事务控制）：BEGIN、COMMIT、ROLLBACK

3. INNER JOIN、LEFT JOIN、RIGHT JOIN 的区别？

答案：

-- INNER JOIN：只返回两表都有匹配的行
SELECT u.name, o.amount FROM users u INNER JOIN orders o ON u.id = o.user_id;

-- LEFT JOIN：返回左表所有行，右表无匹配则 NULL
SELECT u.name, o.amount FROM users u LEFT JOIN orders o ON u.id = o.user_id;
-- 可用来查找"没有订单的用户"：WHERE o.id IS NULL

-- RIGHT JOIN：返回右表所有行（可以用 LEFT JOIN 反写）
-- FULL JOIN：两表所有行（MySQL 不支持，需 UNION 模拟）

4. 什么是子查询？和 JOIN 如何选择？

答案： 子查询是嵌套在另一个查询中的 SELECT。相关子查询（依赖外层）每行执行一次，性能差；非相关子查询执行一次，可被优化器转为 JOIN。一般优先用 JOIN（优化器更容易优化），但子查询语义更清晰时也可用。复杂场景可用 CTE（公共表表达式）WITH 提升可读性。

5. 什么是聚合函数和 GROUP BY？

答案：

-- 聚合函数：COUNT、SUM、AVG、MAX、MIN
SELECT department, COUNT(*) as count, AVG(salary) as avg_salary
FROM employees
GROUP BY department
HAVING AVG(salary) > 5000  -- HAVING 过滤分组结果（WHERE 过滤行，HAVING 过滤组）
ORDER BY avg_salary DESC;

WHERE 在分组前过滤行，HAVING 在分组后过滤组，不可混用。

6. 什么是索引？有哪些类型？

答案： 索引是加速查询的数据结构（通常是 B-Tree），以额外存储和写入成本换取读取速度。类型：① 主键索引（唯一、非空）；② 唯一索引；③ 普通索引；④ 联合索引（多列）；⑤ 全文索引（FULLTEXT，搜索文本）；⑥ 覆盖索引（查询的所有列都在索引中，无需回表）。索引不是越多越好——过多索引增加写入开销和存储。

7. 什么时候索引会失效？

答案： ① 对索引列做函数运算（WHERE YEAR(created_at) = 2024，应改为范围查询）；② 隐式类型转换（列是 int，查询用字符串 WHERE id = '1'）；③ LIKE 以通配符开头（LIKE '%keyword'，改为 LIKE 'keyword%' 可用索引）；④ OR 连接非索引列；⑤ 联合索引违反最左前缀（(a,b,c) 索引，查询只有 b=? 不走索引）；⑥ 优化器认为全表扫描更快时（小表、选择性低的列）。

8. 什么是事务？ACID 是什么？

答案： 事务是一组操作的逻辑单元，要么全部成功，要么全部失败。ACID：

  • A（原子性）：事务中操作要么全做，要么全不做
  • C（一致性）：事务前后数据库从一个一致状态变为另一个一致状态
  • I（隔离性）：并发事务互不干扰
  • D（持久性）：事务提交后修改永久保存
BEGIN TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT; -- 或 ROLLBACK;

9. 什么是事务隔离级别？

答案：

隔离级别 脏读 不可重复读 幻读
READ UNCOMMITTED ✓ ✓ ✓
READ COMMITTED ✗ ✓ ✓
REPEATABLE READ（MySQL 默认） ✗ ✗ ✓（MySQL 通过 MVCC 解决）
SERIALIZABLE ✗ ✗ ✗

脏读：读到未提交的数据；不可重复读：同一事务两次读结果不同；幻读：同一事务两次查询行数不同。

10. 什么是数据库锁？乐观锁和悲观锁？

答案： 悲观锁：认为冲突概率高，操作前加锁（SELECT ... FOR UPDATE），其他事务等待。适合写多读少、冲突频繁场景。乐观锁：认为冲突概率低，不加锁，提交时检查数据是否被修改（通常通过版本号 version 字段）：

UPDATE orders SET status='shipped', version=version+1
WHERE id=1 AND version=5; -- 若影响行数=0则冲突，重试

适合读多写少、冲突少场景，性能更好。

NoSQL

11. Redis 是什么？有哪些数据结构？

答案： Redis 是内存数据库，支持持久化，以高性能键值存储为核心。数据结构：

  • String：最基础，计数器、缓存、分布式锁（SET key value NX EX 30）
  • Hash：对象存储（HSET user:1 name Alice age 25）
  • List：消息队列、最近记录（LPUSH/RPOP）
  • Set：去重集合、共同好友（SADD/SMEMBERS/SINTER）
  • Sorted Set：排行榜（ZADD，按分数排序，ZRANGE/ZRANK）
  • Bitmap/HyperLogLog/Stream：特殊用途（统计日活、流式日志）

12. Redis 的缓存策略有哪些？

答案： 缓存击穿（热点 key 过期，大量请求直击 DB）：互斥锁（只允许一个请求重建缓存）或不设过期时间+主动更新。缓存穿透（查询不存在的数据，缓存永远不命中）：布隆过滤器拦截、缓存空值（短 TTL）。缓存雪崩（大量 key 同时过期）：过期时间加随机抖动、Redis 集群高可用。缓存更新策略：Cache-Aside（读缓存、缓存未命中查 DB 并写入）、Write-Through、Write-Behind。

13. MongoDB 和 MySQL 如何选择？

答案： MongoDB（文档型 NoSQL）适合：数据结构多变（Schema 灵活）、嵌套文档（评论、标签等）、大量非结构化数据、快速迭代原型、需要水平扩展。MySQL（关系型）适合：数据结构稳定、需要复杂关联查询、严格事务（金融）、数据一致性要求高。混合使用也很常见：MySQL 存核心业务数据，MongoDB 存日志/用户行为，Redis 做缓存。

14. 什么是 ORM？常见 Node.js ORM 有哪些？

答案： ORM（对象关系映射）允许用面向对象的方式操作数据库，自动生成 SQL，避免手写 SQL。常见 Node.js ORM：

  • Prisma：类型安全、自动生成 TypeScript 类型、Schema 优先、现代项目首选
  • TypeORM：装饰器风格、适合 NestJS
  • Sequelize：老牌，支持多数据库
  • Drizzle ORM：轻量、类型安全、更接近 SQL 语法

Prisma 示例：

const users = await prisma.user.findMany({
  where: { age: { gt: 18 } },
  include: { orders: true },
  orderBy: { createdAt: 'desc' },
  take: 10,
});

15. 什么是数据库连接池？

答案： 连接池预先创建并维护一定数量的数据库连接，请求时从池中借用，用完归还，避免每次操作都建立/断开连接（建立连接开销大）。关键参数：最小连接数、最大连接数（超过则等待或报错）、空闲超时。Node.js 中 Prisma/TypeORM/Sequelize 都内置连接池管理。生产环境需根据数据库和服务器性能调整池大小。
