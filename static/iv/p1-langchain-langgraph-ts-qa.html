一、LangChain 基础

1. LangChain 的核心抽象有哪些？

答案：

抽象 作用 TypeScript 导入
ChatModel 封装各种 LLM @langchain/openai
PromptTemplate 管理和复用 Prompt @langchain/core/prompts
OutputParser 解析 LLM 输出 @langchain/core/output_parsers
Retriever 从向量库检索文档 @langchain/core/retrievers
Tool 封装外部能力 @langchain/core/tools
Runnable 所有组件的基类，支持 .pipe() 串联 @langchain/core/runnables

2. 什么是 LCEL（LangChain Expression Language）？

答案：
LCEL 是 LangChain 的链式组合语法，用 .pipe() 将组件串联，每个组件的输出作为下一个组件的输入：

import { ChatOpenAI } from "@langchain/openai";
import { ChatPromptTemplate } from "@langchain/core/prompts";
import { StringOutputParser } from "@langchain/core/output_parsers";

const model = new ChatOpenAI({ model: "gpt-4o" });
const parser = new StringOutputParser();

// prompt → model → parser 串联成一条链
const chain = ChatPromptTemplate.fromMessages([
  ["system", "你是一个技术助手"],
  ["human", "{question}"],
]).pipe(model).pipe(parser);

const result = await chain.invoke({ question: "什么是 LangGraph？" });
console.log(result);

LCEL 的优势：
- 所有组件实现 Runnable 接口，可以自由组合
- 原生支持流式输出（.stream()）
- 支持并行执行（RunnableParallel）
- 支持透传（RunnablePassthrough）

3. RunnableParallel 和 RunnablePassthrough 有什么用？

答案：

RunnableParallel（并行执行）：

import { RunnableParallel, RunnablePassthrough } from "@langchain/core/runnables";

// 同时执行多个分支，结果合并为对象
const parallel = RunnableParallel.from({
  context: retriever.pipe(formatDocs),   // 检索文档
  question: new RunnablePassthrough(),   // 原样透传问题
});

// 输入：字符串问题
// 输出：{ context: "...", question: "..." }
const chain = parallel.pipe(ragPrompt).pipe(model).pipe(parser);

RunnablePassthrough（透传）：

// 不对输入做任何处理，直接传递给下一步
const chain = RunnableSequence.from([
  {
    context: retriever.pipe(formatDocs),
    question: new RunnablePassthrough(),  // ← 原样传递
  },
  ragPrompt,
  model,
  parser,
]);

4. 如何定义 LangChain 工具（Tool）？

答案：
使用 tool() 函数 + Zod schema 定义工具：

import { tool } from "@langchain/core/tools";
import { z } from "zod";

// 定义计算器工具
const calculatorTool = tool(
  async ({ a, b, op }) => {
    const ops = {
      add: a + b,
      subtract: a - b,
      multiply: a * b,
      divide: b !== 0 ? a / b : "除数不能为 0",
    };
    return `${a} ${op} ${b} = ${ops[op]}`;
  },
  {
    name: "calculator",
    description: "执行四则运算，当需要精确计算时使用",
    schema: z.object({
      a: z.number().describe("第一个数字"),
      b: z.number().describe("第二个数字"),
      op: z.enum(["add", "subtract", "multiply", "divide"]).describe("运算类型"),
    }),
  }
);

// 直接调用（不经过 LLM）
const result = await calculatorTool.invoke({ a: 10, b: 3, op: "multiply" });
console.log(result); // "10 multiply 3 = 30"

5. LangChain 如何实现流式输出？

答案：

import { ChatOpenAI } from "@langchain/openai";
import { ChatPromptTemplate } from "@langchain/core/prompts";
import { StringOutputParser } from "@langchain/core/output_parsers";

const chain = ChatPromptTemplate.fromMessages([
  ["human", "{question}"],
]).pipe(new ChatOpenAI({ model: "gpt-4o" })).pipe(new StringOutputParser());

// 方式 1：stream() - 逐 token 输出
const stream = await chain.stream({ question: "解释 LangGraph" });
for await (const chunk of stream) {
  process.stdout.write(chunk);  // 实时打印每个 token
}

// 方式 2：streamEvents() - 详细事件流
const eventStream = chain.streamEvents({ question: "解释 LangGraph" }, { version: "v2" });
for await (const event of eventStream) {
  if (event.event === "on_chat_model_stream") {
    process.stdout.write(event.data.chunk.content);
  }
}

二、RAG（检索增强生成）

6. 如何用 LangChain 构建完整的 RAG 链？

答案：

import { MemoryVectorStore } from "langchain/vectorstores/memory";
import { OpenAIEmbeddings } from "@langchain/openai";
import { Document } from "@langchain/core/documents";
import { ChatPromptTemplate } from "@langchain/core/prompts";
import { RunnablePassthrough, RunnableSequence } from "@langchain/core/runnables";
import { StringOutputParser } from "@langchain/core/output_parsers";
import { ChatOpenAI } from "@langchain/openai";

// 1. 创建向量库
const vectorStore = await MemoryVectorStore.fromDocuments(
  [
    new Document({ pageContent: "LangGraph 是图编排框架", metadata: { source: "docs" } }),
    new Document({ pageContent: "RAG 流程包括检索和生成", metadata: { source: "docs" } }),
  ],
  new OpenAIEmbeddings()
);

// 2. 创建检索器
const retriever = vectorStore.asRetriever({ k: 2 });

// 3. 格式化文档
function formatDocs(docs: Document[]) {
  return docs.map((d, i) => `[${i + 1}] ${d.pageContent}`).join("\n");
}

// 4. RAG Prompt
const ragPrompt = ChatPromptTemplate.fromMessages([
  ["system", "仅根据以下上下文回答问题：\n\n{context}"],
  ["human", "{question}"],
]);

// 5. 组装 RAG 链
const ragChain = RunnableSequence.from([
  {
    context: retriever.pipe(formatDocs),
    question: new RunnablePassthrough(),
  },
  ragPrompt,
  new ChatOpenAI({ model: "gpt-4o" }),
  new StringOutputParser(),
]);

const answer = await ragChain.invoke("LangGraph 是什么？");

7. RAG 如何保留对话历史？

答案：
手动管理历史消息，每轮追加到 messages：

const chatHistory: { role: string; content: string }[] = [];

async function chatWithRAG(question: string): Promise<string> {
  // 检索相关文档
  const docs = await retriever.invoke(question);
  const context = formatDocs(docs);

  // 构建包含历史的 prompt
  const historyStr = chatHistory
    .map(m => `${m.role === "human" ? "用户" : "助手"}: ${m.content}`)
    .join("\n");

  const prompt = ChatPromptTemplate.fromMessages([
    ["system", `你是助手，根据上下文回答：\n${context}\n${historyStr ? `对话历史：\n${historyStr}` : ""}`],
    ["human", "{question}"],
  ]);

  const chain = prompt.pipe(model).pipe(new StringOutputParser());
  const answer = await chain.invoke({ question });

  // 更新历史
  chatHistory.push({ role: "human", content: question });
  chatHistory.push({ role: "assistant", content: answer });

  return answer;
}

三、LangGraph 基础

8. LangGraph 的核心概念是什么？

答案：

概念 说明 代码
StateGraph 有向状态图，整个工作流的容器 new StateGraph({ channels: state })
State 节点间共享的数据结构，每个字段有 reducer { messages: { value: (x,y) => [...x,...y] } }
Node 执行具体逻辑的函数，接收 state 返回部分更新 workflow.addNode("agent", agentFn)
Edge 节点间的连接，控制执行顺序 workflow.addEdge("a", "b")
Conditional Edge 根据 state 动态决定下一节点 workflow.addConditionalEdges("a", routeFn, {...})
EntryPoint 图的起始节点 workflow.setEntryPoint("agent") 
import { StateGraph, END } from "@langchain/langgraph";

const state = {
  question: { value: (_, y) => y ?? _, default: () => "" },
  answer: { value: (_, y) => y ?? _, default: () => "" },
  steps: { value: (x, y) => [...x, ...y], default: () => [] },
};

const workflow = new StateGraph({ channels: state });
workflow.addNode("analyze", analyzeNode);
workflow.addNode("generate", generateNode);
workflow.setEntryPoint("analyze");
workflow.addEdge("analyze", "generate");
workflow.addEdge("generate", END);

const app = workflow.compile();
const result = await app.invoke({ question: "什么是 LangGraph？" });

9. State 中的 reducer 函数有什么作用？

答案：
Reducer 定义当节点返回新值时，如何将新值与旧值合并：

const state = {
  // 新值覆盖旧值（忽略旧值）
  answer: { value: (_, y) => y, default: () => "" },

  // 保留旧值（如果新值为 null/undefined）
  question: { value: (x, y) => y ?? x, default: () => "" },

  // 数组追加合并（消息历史）
  messages: { value: (x, y) => [...x, ...y], default: () => [] },

  // 对象合并（Worker 输出）
  workerOutputs: { value: (x, y) => ({ ...x, ...y }), default: () => ({}) },

  // 计数器累加
  iteration: { value: (x, y) => y ?? x, default: () => 0 },
};

注意： 节点名称不能与 State 字段名称相同，否则会报错：

Error: answer is already being used as a state attribute, cannot also be used as a node name.

10. 如何构建 Agent 循环（ReAct 模式）？

答案：
核心是两个节点（agent + tools）+ 条件边 + tools→agent 的回环：

import { StateGraph, END } from "@langchain/langgraph";
import { ToolNode } from "@langchain/langgraph/prebuilt";
import { HumanMessage } from "@langchain/core/messages";
import { ChatOpenAI } from "@langchain/openai";

const tools = [calculatorTool, weatherTool];
const toolNode = new ToolNode(tools);
const model = new ChatOpenAI({ model: "gpt-4o" }).bindTools(tools);

const agentState = {
  messages: { value: (x, y) => x.concat(y), default: () => [] },
  iteration: { value: (_, y) => y ?? _, default: () => 0 },
};

// Agent 节点：调用 LLM 决策
async function agentNode(state) {
  const iter = state.iteration + 1;
  const response = await model.invoke(state.messages);
  return { messages: [response], iteration: iter };
}

// 路由函数：根据 LLM 输出决定下一步
function routeAfterAgent(state) {
  if (state.iteration >= 10) return END;  // 防止无限循环
  const lastMsg = state.messages.at(-1);
  return lastMsg.tool_calls?.length ? "tools" : END;
}

const workflow = new StateGraph({ channels: agentState });
workflow.addNode("agent", agentNode);
workflow.addNode("tools", toolNode);
workflow.setEntryPoint("agent");
workflow.addConditionalEdges("agent", routeAfterAgent, {
  tools: "tools",
  [END]: END,
});
workflow.addEdge("tools", "agent");  // tools 完成后回到 agent（循环）

const app = workflow.compile();
const result = await app.invoke({
  messages: [new HumanMessage("计算 123 × 456")],
});

11. 如何实现条件边（Conditional Edges）？

答案：
addConditionalEdges 接受三个参数：源节点、路由函数、路由映射表：

// 场景：智能客服根据用户意图路由到不同处理节点
function routeByIntent(state) {
  const intent = state.intent;
  const routes = {
    technical: "technical_support",
    billing: "billing",
    complaint: "complaint",
    other: "general",
  };
  return routes[intent] ?? "general";
}

workflow.addConditionalEdges("classify", routeByIntent, {
  // 路由函数返回值 → 目标节点名称
  technical_support: "technical_support",
  billing: "billing",
  complaint: "complaint",
  general: "general",
});

路由函数返回值与映射表的关系：

// 左边（key）：路由函数的返回值
// 右边（value）：实际执行的节点名
{
  "report": "report",   // 返回 "report" → 执行 report 节点
  [END]: END,           // 返回 END → 结束图
}

四、高级模式

13. 什么是 Reflection Agent？如何实现？

答案：
Reflection Agent（反思智能体）= 生成 → 批评 → 改进的迭代循环，通过自我批评提升输出质量：

const state = {
  task: { value: (_, y) => y, default: () => "" },
  draft: { value: (_, y) => y, default: () => "" },
  critique: { value: (_, y) => y, default: () => "" },
  iteration: { value: (_, y) => y, default: () => 0 },
  maxIterations: { value: (_, y) => y, default: () => 3 },
  accepted: { value: (_, y) => y, default: () => false },
};

// 节点 1：生成内容
async function generateNode(state) {
  const isFirst = state.iteration === 0;
  const prompt = isFirst
    ? ChatPromptTemplate.fromMessages([["human", "完成任务：{task}"]])
    : ChatPromptTemplate.fromMessages([
        ["human", "任务：{task}\n\n上一版：{draft}\n\n批评：{critique}\n\n请改进："],
      ]);

  const draft = await prompt.pipe(model).pipe(parser).invoke(state);
  return { draft, iteration: state.iteration + 1 };
}

// 节点 2：批评/评估
async function critiqueNode(state) {
  const prompt = ChatPromptTemplate.fromMessages([
    ["system", "你是严格的评审员，最后必须写'决定：接受'或'决定：需要改进'"],
    ["human", "任务：{task}\n\n内容：{draft}"],
  ]);
  const critique = await prompt.pipe(model).pipe(parser).invoke(state);
  const accepted = critique.includes("接受") || state.iteration >= state.maxIterations;
  return { critique, accepted };
}

// 路由：是否继续迭代
function routeAfterCritique(state) {
  return state.accepted ? END : "generate";
}

const workflow = new StateGraph({ channels: state });
workflow.addNode("generate", generateNode);
workflow.addNode("critique", critiqueNode);
workflow.setEntryPoint("generate");
workflow.addEdge("generate", "critique");
workflow.addConditionalEdges("critique", routeAfterCritique, {
  generate: "generate",
  [END]: END,
});

14. 什么是 Supervisor Agent 模式？

答案：
一个主管 LLM 协调多个专业 Worker Agent，按序分配任务，最终聚合输出：

const workers = {
  researcher: { systemPrompt: "你是技术研究员..." },
  writer: { systemPrompt: "你是技术写作专家..." },
  coder: { systemPrompt: "你是资深工程师..." },
};

// Supervisor 节点：决定下一个 Worker
async function supervisorNode(state) {
  const done = Object.keys(state.workerOutputs);
  const remaining = Object.keys(workers).filter(w => !done.includes(w));

  if (remaining.length === 0) return { currentWorker: "FINISH" };
  return { currentWorker: remaining[0] };
}

// Worker 节点工厂（动态创建）
function createWorkerNode(workerName: string) {
  return async (state) => {
    const worker = workers[workerName];
    const output = await prompt.pipe(model).pipe(parser).invoke({ task: state.task });
    return { workerOutputs: { [workerName]: output } };
  };
}

// 路由：根据 Supervisor 的决定路由到对应 Worker
function routeBySupervisor(state) {
  if (state.currentWorker === "FINISH") return "report";
  return state.currentWorker in workers ? state.currentWorker : "report";
}

// 注册所有 Worker 节点
for (const name of Object.keys(workers)) {
  workflow.addNode(name, createWorkerNode(name));
  workflow.addEdge(name, "supervisor");  // 每个 Worker 完成后回到 Supervisor
}

async function parallelReviewNode(state) {
  const start = Date.now();

  const [secResult, perfResult, styleResult] = await Promise.all([
    securityAgent(state),     // 安全审查
    performanceAgent(state),  // 性能审查
    styleAgent(state),        // 代码风格审查
  ]);

  console.log(`并行完成，耗时 ${Date.now() - start}ms`);

  return {
    securityResult: secResult.securityResult,
    performanceResult: perfResult.performanceResult,
    styleResult: styleResult.styleResult,
    severity: secResult.severity,
  };
}

// 串行 vs 并行时间对比：
// 串行：3 × 2s = 6s
// 并行：max(2s, 2s, 2s) = 2s ← 节省 2/3 时间

18. LangGraph 如何实现持久化（Checkpointing）？

答案：
Checkpointing 允许图在任意节点暂停并恢复，支持长期对话和 Human-in-the-Loop：

import { MemorySaver } from "@langchain/langgraph";

// 使用内存 Checkpointer（生产环境用 PostgresSaver 或 RedisSaver）
const checkpointer = new MemorySaver();
const app = workflow.compile({ checkpointer });

// 运行时提供 thread_id（会话 ID）
const config = { configurable: { thread_id: "user-123-session-1" } };

// 第一轮对话
await app.invoke(

  { messages: [new HumanMessage("我叫什么名字？")] },

);

19. 如何实现 Human-in-the-Loop（人机协同）？

答案：
使用 LangGraph 的 interrupt 在关键节点暂停，等待人工确认：

import { interrupt, MemorySaver } from "@langchain/langgraph";

// 在高风险操作前插入人工确认
async function deleteNode(state) {
  const { targetFile } = state;

  // 暂停图执行，等待人工确认
  const approval = interrupt({
    question: `确认删除文件：${targetFile}？`,
    data: { targetFile },
  });

  if (approval !== "yes") {
    return { result: "操作已取消" };
  }

  // 执行实际删除
  await deleteFile(targetFile);
  return { result: `已删除 ${targetFile}` };
}

// 恢复执行（提供人工确认结果）
const config = { configurable: { thread_id: "session-1" } };

// 第一次运行，会在 deleteNode 暂停
await app.invoke({ targetFile: "data.json" }, config);

// 人工审查后，传入确认结果恢复
await app.invoke(new Command({ resume: "yes" }), config);

六、常见题目对比

21. invoke() vs stream() vs streamEvents() 的区别？

方法 返回 适用场景
invoke() 最终结果（一次性） 等待完整输出
stream() 异步迭代器，逐步推送 流式展示给用户
streamEvents() 详细事件流（token 级别） 需要精细控制每个事件 
// invoke：等待全部完成
const result = await chain.invoke({ question: "..." });

// stream：逐步输出
for await (const chunk of await chain.stream({ question: "..." })) {
  process.stdout.write(chunk);
}

// streamEvents：细粒度事件
for await (const event of chain.streamEvents({ question: "..." }, { version: "v2" })) {
  if (event.event === "on_chat_model_stream") {
    process.stdout.write(event.data.chunk.content);
  }
}

22. addEdge() vs addConditionalEdges() 的区别？

方法 说明 使用场景
addEdge(from, to) 固定边，无条件执行 顺序固定的流程
addConditionalEdges(from, routeFn, map) 条件边，根据路由函数动态决定 需要分支逻辑的流程 
// 固定边：analyze 总是连接到 generate
workflow.addEdge("analyze", "generate");

// 条件边：根据 state.intent 动态路由
workflow.addConditionalEdges("classify", routeByIntent, {
  technical: "technical_node",
  billing: "billing_node",
  [END]: END,
});

23. LangChain Chain 和 LangGraph Graph 如何选择？

维度 LangChain Chain LangGraph Graph
执行流程 线性，固定顺序 有向图，支持循环/分支
状态管理 隐式，每步传递 显式 State，节点共享
适合场景 RAG、简单问答、文档摘要 Agent 循环、多 Agent、Human-in-the-Loop
调试难度 简单 较复杂，需要图可视化工具
持久化 不支持 原生支持 Checkpointing
学习曲线 低 中等

选择原则：
- 流程固定、无循环 → LangChain Chain
- 需要动态决策、循环、暂停恢复 → LangGraph
- 生产级复杂 Agent → LangGraph
