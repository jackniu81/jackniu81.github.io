﻿# Axios 常见题目（50道）

基础概念

1. 什么是 Axios？

答案：
Axios 是一个基于 Promise 的 HTTP 客户端，可运行在浏览器和 Node.js 环境中。

2. Axios 的核心特点有哪些？

答案：
它支持拦截器、实例化、超时控制、取消请求、自动 JSON 转换和统一错误处理。

3. Axios 和 fetch 的主要区别是什么？

答案：
Axios 内置拦截器和更一致的错误处理；fetch 是原生 API，更轻量，但很多能力需要自行封装。

4. 为什么很多项目会选择 Axios？

答案：
因为它适合做统一请求层封装，便于鉴权、错误治理、接口复用和工程化维护。

5. Axios 支持哪些常见请求方法？

答案：
常见有 get、post、put、patch、delete、head 和 options。

6. 如何安装 Axios？

答案：
一般通过 npm install axios 或 pnpm add axios 安装。

7. Axios 的基本返回值是什么？

答案：
它返回一个 Promise，成功时得到响应对象，失败时进入 rejected 状态。

8. 响应对象通常包含哪些字段？

答案：
常见字段有 data、status、statusText、headers、config 和 request。

9. response.data 表示什么？

答案：
它通常表示服务端真正返回的业务数据，也是业务代码最常读取的部分。

10. Axios 是否可以在 Node.js 中使用？

答案：
可以，Axios 同时支持浏览器和 Node.js，因此也常用于 SSR 或脚本请求场景。

请求配置

11. Axios 配置对象常见字段有哪些？

答案：
常见包括 url、method、baseURL、headers、params、data、timeout、responseType、withCredentials 等。

12. baseURL 的作用是什么？

答案：
用于统一配置接口前缀，减少重复书写，并方便在不同环境间切换。

13. params 和 data 的区别是什么？

答案：
params 一般用于 URL 查询参数，data 一般用于请求体。

14. headers 有什么作用？

答案：
它用于设置请求头，比如 Authorization、Content-Type、语言信息和 traceId。

15. timeout 有什么作用？

答案：
它用于限制请求等待时间，超过设定值会抛出超时错误。

16. withCredentials 在什么场景下使用？

答案：
当跨域请求需要携带 Cookie 或其他凭证时使用，但前后端都要正确配置。

17. responseType 常见取值有哪些？

答案：
常见有 json、text、blob、arraybuffer、document 等。

18. 如何设置 Axios 的全局默认配置？

答案：
可以通过 axios.defaults 设置全局 baseURL、公共请求头、超时时间等。

19. 为什么推荐创建 Axios 实例？

答案：
因为不同业务模块往往需要不同配置，实例化可以隔离拦截器和默认参数。

20. 如何创建 Axios 实例？

答案：
使用 axios.create() 传入配置对象即可创建独立实例。

拦截器

21. 什么是 Axios 拦截器？

答案：
拦截器是在请求发送前或响应返回后统一处理逻辑的机制。

22. 请求拦截器常见用途有哪些？

答案：
常用于追加 token、统一参数、签名、日志和 loading 控制。

23. 响应拦截器常见用途有哪些？

答案：
常用于统一解包数据、处理错误码、登录失效跳转和消息提示。

24. 为什么很多项目会在响应拦截器里直接返回 response.data？

答案：
因为这样可以简化业务层调用，减少每次都写 response.data 的重复代码。

25. 如何移除拦截器？

答案：
注册拦截器后会得到一个 id，可通过 eject(id) 移除。

26. 使用拦截器时有哪些风险？

答案：
风险包括重复注册、循环请求、错误被吞掉以及多个实例逻辑混乱。

27. 为什么不要把所有逻辑都塞进拦截器？

答案：
因为拦截器应该只放通用治理逻辑，过多业务逻辑会让调试和维护变困难。

28. 请求拦截器里如何添加 token？

答案：
通常读取本地存储或状态管理中的 token，再写入 config.headers.Authorization。

29. 响应拦截器如何统一处理业务错误码？

答案：
可以根据后端返回的 code 或 success 字段决定提示、跳转或抛出错误。

30. 为什么实例级拦截器通常优于全局拦截器？

答案：
因为实例级更容易按业务域隔离，避免不同系统之间互相污染。

错误处理

31. Axios 如何处理 HTTP 4xx/5xx 状态码？

答案：
默认会把这类响应当作 Promise reject，让你在 catch 或响应拦截器中处理。

32. Axios 的错误对象通常包含什么？

答案：
常见包括 message、code、config、request 和 response。

33. 如何区分接口错误和网络错误？

答案：
有 error.response 通常表示服务端返回了错误状态；只有 error.request 通常表示未收到响应。

34. 如何统一处理 401 未授权？

答案：
一般在响应拦截器中清理登录态并跳转登录页，或进入刷新 token 流程。

35. 如何统一处理 500 服务异常？

答案：
可以在拦截器中统一记录日志、提示用户稍后重试，并按需上报监控。

36. 什么是 validateStatus？

答案：
它用于自定义哪些 HTTP 状态码应被视为成功响应。

37. 为什么统一错误处理很重要？

答案：
因为它能减少重复代码，提升用户体验一致性，并方便监控与排障。

38. 如何避免在每个接口调用处都写重复的 try/catch？

答案：
可以把通用错误治理放到 Axios 封装层或拦截器中，业务层只处理特殊场景。

39. Axios 超时报错如何识别？

答案：
一般可以根据错误 code、错误消息或配置项判断是否为超时场景。

40. 为什么不能简单把所有错误都提示给用户？

答案：
因为有些错误适合静默处理或自动重试，全部直接提示会造成糟糕的交互体验。

并发、取消与高级能力

41. Axios 如何发送并发请求？

答案：
一般结合 Promise.all 或 Promise.allSettled 发起多个请求并统一处理结果。

42. Promise.all 和 Promise.allSettled 在并发请求中有什么区别？

答案：
前者只要有一个失败就整体失败，后者会返回每个请求各自的成功或失败结果。

43. Axios 如何取消请求？

答案：
现在更推荐使用 AbortController 传入 signal 来取消请求。

44. 哪些场景特别适合取消请求？

答案：
搜索联想、组件卸载、路由切换、条件快速切换和重复提交都是典型场景。

45. 什么是重复请求去重？

答案：
指对同一时间内相同接口和参数的请求进行取消、忽略或复用，避免资源浪费。

46. Axios 如何实现文件上传？

答案：
使用 FormData 组装文件后发起请求，并可结合 onUploadProgress 监听进度。

47. Axios 如何实现文件下载？

答案：
一般设置 responseType: 'blob'，再将返回的二进制数据转成可下载链接。

48. 什么是请求重试机制？

答案：
指请求失败后按规则重新发起请求，常用于瞬时网络抖动或临时性错误。

49. 请求重试时要注意什么？

答案：
要控制次数、间隔和适用请求类型，尤其要谨慎处理非幂等请求。

50. 面试中如何总结 Axios 的核心价值？

答案：
Axios 不只是发请求的工具，更是前端做统一接口治理、鉴权、错误处理和请求封装的基础设施。关键在于如何结合拦截器、实例化、类型封装将其融入工程体系，而不是简单地 import axios from 'axios' 就直接调用。

工程化与进阶实践

51. 多个拦截器的执行顺序是怎样的？

答案：
请求拦截器按注册的逆序执行（后注册的先执行），响应拦截器按注册的顺序执行（先注册的先执行）。因此全局基础逻辑建议先注册，业务特定逻辑后注册叠加，可以在基础行为之上逐层增强。

52. 如何实现 Token 自动刷新（无感刷新）？

答案：
核心思路：① 响应拦截器检测到 401 时，将当前请求挂起到队列；② 发起刷新 Token 请求（用一个标志位保证只发一次）；③ 刷新成功后将队列中的请求重新发出，失败则跳转登录页。关键点：用 Promise 包装队列请求，刷新期间所有新请求等待，刷新完毕后统一 resolve 或 reject。

53. 如何实现请求指数退避重试？

答案：
在响应拦截器中判断是否符合重试条件（如 5xx 错误、超时、特定网络错误），记录当前重试次数于 config，延迟时间按 delay = baseDelay * 2^retryCount 计算，通过 setTimeout 配合返回新的 axios(config) Promise 实现重试。注意设置最大次数和最大延迟上限，且非幂等请求（POST 写操作）需谨慎开启。

54. 如何在 TypeScript 中为 Axios 封装类型？

答案：
① 泛型声明响应类型：axios.get<User[]>('/users') 或封装 request<T>(config): Promise<T>；② 扩展 AxiosRequestConfig 接口添加自定义字段（如 skipAuth?: boolean）；③ 用 AxiosResponse<T> 约束拦截器返回值。建议统一封装一个类型化的 request 函数，避免每个调用处都写泛型。

55. 如何处理接口不同环境的 baseURL 切换？

答案：
常见方案：① 通过 .env 文件定义环境变量（VITE_API_BASE），Axios 实例读取 import.meta.env.VITE_API_BASE；② 结合打包工具的代理配置（如 Vite server.proxy）在开发环境代理接口，生产环境直接使用真实域名；③ 多实例方案：不同 API 域对应不同实例，各自配置 baseURL。

56. 如何实现接口级别的缓存？

答案：
在请求拦截器中根据 URL + 参数生成 key，检查内存缓存（Map）；命中缓存则直接返回缓存结果（通过取消请求并在响应拦截器中注入缓存数据，或用 Adapter 拦截）。设置 TTL 过期时间控制缓存有效期。更完整的方案可使用 React Query / SWR 等库。

57. Axios 的 transformRequest 和 transformResponse 有什么用？

答案：
transformRequest 在请求发出前对请求数据做转换（如序列化、加密），是数组可叠加多个处理函数；transformResponse 在响应数据进入拦截器前做转换（如解密、格式标准化）。与拦截器的区别：transform 更底层，在序列化/反序列化层面操作，拦截器在 Promise 层操作。

58. 如何在 Axios 请求中统一注入 traceId？

答案：
在请求拦截器中生成或读取当前请求的 traceId（如 UUID），写入请求头（如 X-Trace-Id）。同时在响应拦截器中读取服务端返回的 traceId（如 x-request-id）并挂到日志上下文。这样前后端日志可通过同一 traceId 串联，方便排查问题。

总结

这些题目覆盖了 Axios 的基础概念、配置、拦截器、错误处理、并发控制、取消请求与工程化封装（类型、刷新、重试、缓存、traceId），适合作为系统复习资料。
