计算机网络 / HTTP 常见面试题（附答案）

网络基础

1. OSI 七层模型和 TCP/IP 四层模型分别是什么？

答案：
OSI 七层（从下到上）：物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。TCP/IP 四层：网络接口层（链路层）、网络层（IP）、传输层（TCP/UDP）、应用层（HTTP/DNS/FTP）。实际应用中通常用 TCP/IP 模型，OSI 更多用于理论分析和排障分层。

2. TCP 和 UDP 的区别是什么？

答案：
TCP（传输控制协议）：面向连接、可靠传输、有序、流量/拥塞控制、全双工、速度较慢。UDP（用户数据报协议）：无连接、不可靠、无序、无拥塞控制、速度快。TCP 适合文件传输、HTTP、数据库；UDP 适合实时视频/音频、DNS 查询、游戏（延迟敏感场景）。

3. TCP 三次握手的过程是什么？

答案：
① 客户端发 SYN（seq=x），进入 SYN_SENT；② 服务端收到后发 SYN+ACK（seq=y, ack=x+1），进入 SYN_RCVD；③ 客户端发 ACK（ack=y+1），双方进入 ESTABLISHED。三次握手的原因：确认双方发送和接收能力正常，同步序列号，防止历史连接请求混淆。

4. TCP 四次挥手的过程是什么？

答案：
① 主动方发 FIN，进入 FIN_WAIT_1；② 被动方发 ACK，进入 CLOSE_WAIT，主动方进入 FIN_WAIT_2；③ 被动方发 FIN，进入 LAST_ACK；④ 主动方发 ACK，进入 TIME_WAIT（等待 2MSL），被动方收到后 CLOSED，主动方超时后 CLOSED。四次挥手原因：TCP 是全双工，两个方向关闭各需一次 FIN+ACK。

5. 为什么需要 TIME_WAIT 状态？

答案：
① 确保被动方收到最后的 ACK（若丢失，被动方重发 FIN，主动方在 TIME_WAIT 内可重发 ACK）；② 防止旧连接的延迟报文影响新连接（等待 2MSL 让网络中旧报文消散）。TIME_WAIT 过多会占用端口资源，可通过 SO_REUSEADDR、调整内核参数等方式缓解。

6. 什么是 DNS？解析过程是什么？

答案：
DNS（域名系统）将域名解析为 IP 地址。解析过程：① 查浏览器缓存；② 查操作系统缓存（hosts 文件）；③ 查本地 DNS 服务器（ISP/公司内网）；④ 递归查询：根域名服务器 → 顶级域名服务器（.com/.cn）→ 权威域名服务器，返回最终 IP。结果按 TTL 缓存。

7. 什么是 CDN？它的工作原理是什么？

答案：
CDN（内容分发网络）通过在全球部署边缘节点，将静态资源缓存到距用户最近的节点，减少延迟和源站压力。用户请求时 DNS 返回最近节点 IP（通过 GSLB 智能调度）；节点缓存命中直接返回，未命中则回源拉取并缓存。适合图片、CSS/JS、视频等静态资源。

HTTP 协议

8. HTTP 和 HTTPS 的区别是什么？

答案：
HTTP 是明文传输协议，不加密，默认端口 80；HTTPS 在 HTTP 下加入 TLS/SSL 加密层，提供数据加密、身份认证和完整性校验，默认端口 443。HTTPS 会有握手开销，但现代 TLS 1.3 大幅减少握手次数，配合 HTTP/2 性能不逊色 HTTP。

9. HTTPS 的 TLS 握手过程是什么？

答案：
TLS 1.3 握手（1-RTT）：① 客户端发 ClientHello（支持的加密套件、密钥交换参数）；② 服务端发 ServerHello（选定套件、证书、密钥参数）；③ 双方根据密钥参数计算会话密钥；④ 后续通信使用对称加密。0-RTT 模式支持会话复用，首次握手后可零往返恢复。

10. HTTP/1.0、HTTP/1.1、HTTP/2、HTTP/3 的主要区别？

答案：
- HTTP/1.0：每次请求重新建立 TCP 连接，无持久连接
- HTTP/1.1：持久连接（keep-alive），管道化（有队头阻塞），分块传输，Host 头
- HTTP/2：二进制分帧、多路复用（解决应用层队头阻塞）、头部压缩（HPACK）、服务端推送
- HTTP/3：基于 QUIC（UDP 上实现可靠传输），彻底解决传输层队头阻塞，连接迁移（切换 Wi-Fi 不断连），更快的握手

11. 什么是 HTTP 的队头阻塞（Head-of-Line Blocking）？

答案：
HTTP/1.1 管道化中，同一连接多个请求必须按序响应，前一个响应未完成会阻塞后续请求（应用层队头阻塞）。HTTP/2 多路复用在同一 TCP 连接上用帧解决了应用层阻塞，但仍有 TCP 层队头阻塞（TCP 丢包时整个连接阻塞）。HTTP/3 使用 QUIC（基于 UDP）从根本上解决了传输层的队头阻塞。

12. 常见 HTTP 状态码及含义？

答案：
- 2xx 成功：200 OK、201 Created、204 No Content
- 3xx 重定向：301 永久重定向、302 临时重定向、304 Not Modified（协商缓存命中）
- 4xx 客户端错误：400 Bad Request、401 Unauthorized、403 Forbidden、404 Not Found、405 Method Not Allowed、429 Too Many Requests
- 5xx 服务端错误：500 Internal Server Error、502 Bad Gateway、503 Service Unavailable、504 Gateway Timeout

13. GET 和 POST 的区别是什么？

答案：
GET：语义为获取资源，参数在 URL 中（受浏览器/服务器长度限制），幂等，可缓存，不适合敏感数据。POST：语义为提交数据，数据在请求体，无长度限制，不幂等，不被默认缓存。技术上 GET 也可有请求体，POST 也可用 URL 参数，但应遵循语义约定。RESTful API 中还有 PUT（替换）、PATCH（部分更新）、DELETE（删除）。

14. HTTP 请求头/响应头有哪些常见字段？

答案：
请求头：Content-Type、Authorization、Accept、Cookie、User-Agent、Referer、Origin、Cache-Control、If-None-Match、If-Modified-Since。响应头：Content-Type、Set-Cookie、ETag、Last-Modified、Cache-Control、Access-Control-Allow-Origin、Location（重定向）、Strict-Transport-Security（HSTS）。

15. 什么是 Content-Type？常见值有哪些？

答案：
Content-Type 声明请求体或响应体的 MIME 类型。常见值：application/json（JSON 数据）、application/x-www-form-urlencoded（表单编码）、multipart/form-data（文件上传）、text/html、text/plain、image/png、application/octet-stream（二进制流）。前端发 POST 请求时注意 Content-Type 与实际数据格式一致。

HTTP 缓存

16. 什么是强缓存？

答案：
强缓存命中时浏览器直接从本地读取资源，不发请求到服务器。控制字段：Cache-Control: max-age=3600（相对时间，优先）和 Expires: Wed, 21 Oct 2025 07:28:00 GMT（绝对时间，旧方式）。命中强缓存状态码为 200（from disk cache / from memory cache）。

17. 什么是协商缓存？

答案：
强缓存失效后，浏览器携带验证信息向服务器确认资源是否变更。验证机制：① ETag/If-None-Match（资源内容哈希，精确）；② Last-Modified/If-Modified-Since（修改时间，秒级精度）。服务器对比后若未变化返回 304 Not Modified（无响应体，节省带宽），否则返回 200 + 新资源。ETag 优先级高于 Last-Modified。

18. Cache-Control 常见指令有哪些？

答案：
- max-age=N：N 秒内使用缓存（相对时间）
- no-cache：每次需向服务器验证（走协商缓存），不是"不缓存"
- no-store：不缓存任何内容（真正的不缓存）
- private：只允许浏览器缓存，不允许 CDN/代理缓存
- public：允许 CDN/代理缓存
- s-maxage：CDN/代理缓存时间
- must-revalidate：过期后必须向服务器验证

19. 如何设计一个最优的缓存策略？

答案：
① HTML 文件：Cache-Control: no-cache（每次验证，保证拿到最新入口）；② JS/CSS/图片（带 hash 指纹，如 main.abc123.js）：Cache-Control: max-age=31536000, immutable（一年强缓存，内容变化时文件名变化）；③ API 接口：视业务决定，一般 no-store 或短 max-age。

跨域

20. 什么是同源策略？

答案：
同源策略规定浏览器限制非同源（协议+域名+端口均相同为同源）的脚本发起跨域请求、访问对方的 DOM 和 Cookie 等资源。这是浏览器安全的基础防线，防止恶意网站读取其他站点的敏感数据。

21. 什么是 CORS？如何配置？

答案：
CORS（跨域资源共享）通过 HTTP 头告诉浏览器允许跨域访问。关键响应头：Access-Control-Allow-Origin（允许的源）、Access-Control-Allow-Methods（允许的方法）、Access-Control-Allow-Headers（允许的请求头）、Access-Control-Allow-Credentials（是否允许携带凭证）。预检请求（OPTIONS）在实际请求前发出，检查权限。

22. 什么是简单请求和预检请求？

答案：
简单请求：方法为 GET/HEAD/POST，Content-Type 为 text/plain/multipart/form-data/application/x-www-form-urlencoded，无自定义请求头，浏览器直接发并在响应中检查 Access-Control-Allow-Origin。不满足条件则先发 OPTIONS 预检请求，服务器返回允许的配置后再发真正的请求。

23. 跨域解决方案有哪些？

答案：
① CORS（推荐，服务端配置）；② 代理（开发时 Vite/webpack dev server 代理，生产时 Nginx 反向代理）；③ JSONP（只支持 GET，利用 <script> 不受同源限制，已不推荐）；④ postMessage（跨窗口通信）；⑤ WebSocket（本身不受同源策略限制）；⑥ document.domain（限同主域子域，已废弃）。

24. withCredentials 跨域携带 Cookie 有什么要求？

答案：
前端：axios 设置 withCredentials: true；后端：Access-Control-Allow-Origin 不能为 *，必须指定具体源；Access-Control-Allow-Credentials: true；Access-Control-Allow-Origin 必须与请求的 Origin 完全匹配。缺一不可，否则 Cookie 不会被携带或响应被浏览器拦截。

Cookie、Session 与 Token

25. Cookie、Session 和 Token 分别是什么？

答案：
Cookie：浏览器端存储的小型文本，每次请求自动携带，可设置过期时间、域、路径、HttpOnly、Secure 等属性。Session：服务端存储用户状态，SessionId 存在 Cookie 中，服务端根据 ID 查找对应会话数据，有扩展性问题。Token（JWT）：服务端签发的令牌，包含用户信息，客户端存储，每次请求携带，服务端验证签名，无状态，易于横向扩展。

26. JWT 的结构和验证原理是什么？

答案：
JWT 由三部分组成（. 分隔）：① Header（算法+类型，Base64编码）；② Payload（声明/用户数据，Base64编码，不加密！）；③ Signature（Header + Payload + 密钥 用算法签名）。验证时重新计算签名对比，不可篡改（无私钥无法伪造签名）。注意 Payload 是明文，不能存敏感信息；Token 无法主动失效，需配合黑名单或短过期时间。

27. Cookie 的 HttpOnly、Secure、SameSite 属性有什么作用？

答案：
HttpOnly：禁止 JavaScript 读取，防止 XSS 窃取 Cookie；Secure：只在 HTTPS 连接中发送，防止中间人窃取；SameSite：控制跨站请求时是否携带 Cookie（Strict=完全禁止跨站、Lax=导航请求允许、None=全部允许但需 Secure），防止 CSRF 攻击。三者组合是 Cookie 安全的最佳实践。

安全

28. 什么是 XSS？如何防御？

答案：
XSS（跨站脚本攻击）：攻击者将恶意脚本注入页面，在受害者浏览器执行，窃取 Cookie、伪造操作。类型：存储型（注入数据库）、反射型（URL 参数回显）、DOM 型（前端拼接 HTML）。防御：① 输出编码（转义 <>&"'）；② CSP（Content Security Policy，限制脚本来源）；③ Cookie 设 HttpOnly；④ 富文本用白名单过滤（DOMPurify）；⑤ Vue/React 避免使用 dangerouslySetInnerHTML/v-html。

29. 什么是 CSRF？如何防御？

答案：
CSRF（跨站请求伪造）：攻击者诱导用户访问恶意页面，该页面自动发送携带用户 Cookie 的请求到目标站点，执行恶意操作。防御：① CSRF Token（表单/请求头中附带随机 token，服务端验证）；② SameSite=Strict/Lax Cookie；③ 验证 Origin/Referer 请求头；④ 敏感操作需要二次验证。

30. 什么是 CSP（内容安全策略）？

答案：
CSP 通过 HTTP 响应头 Content-Security-Policy 声明页面可以加载资源的白名单，限制脚本来源、样式来源、图片来源等。如 script-src 'self' cdn.example.com 只允许本域和指定 CDN 的脚本。能有效缓解 XSS 攻击（禁止内联脚本、限制外部脚本源）。违规行为会被浏览器阻止并可配置上报。

WebSocket 与实时通信

31. WebSocket 是什么？与 HTTP 有什么区别？

答案：
WebSocket 是基于 TCP 的全双工通信协议，建立一次握手（通过 HTTP 升级）后保持持久连接，服务端可主动推送数据。与 HTTP 比较：HTTP 是请求-响应模式（客户端主动），WebSocket 双向实时通信；WebSocket 更低延迟，无须每次请求携带 Header，适合聊天、实时协作、股价推送、游戏等场景。

32. 什么是 Server-Sent Events（SSE）？

答案：
SSE 是基于 HTTP 的服务端单向推送技术，服务端通过 Content-Type: text/event-stream 持续发送数据，客户端用 EventSource API 接收。优点：基于 HTTP（穿透代理/防火墙更容易）、自动重连、原生支持。适合：通知推送、新闻推流、大模型流式输出。与 WebSocket 区别：SSE 单向、只能文本，WS 双向、支持二进制。

33. 什么是长轮询（Long Polling）？

答案：
长轮询是实现服务端推送的 HTTP 方案：客户端发请求，服务端不立即响应，而是等有新数据时才返回；客户端收到响应后立即发下一次请求，形成持续连接效果。比短轮询（定时发请求）更高效，但依然有较高延迟和连接开销。现代项目优先选 WebSocket 或 SSE，长轮询已较少使用。
