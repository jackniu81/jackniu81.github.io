React 常见面试题 100 道（附答案）

1. 什么是 React？

答案：
React 是一个用于构建用户界面的 JavaScript 库，核心思想是组件化开发和声明式编程。它通过虚拟 DOM 提升更新效率，常用于构建单页应用。

2. React 的核心特点有哪些？

答案：
- 组件化
- 声明式 UI
- 虚拟 DOM
- 单向数据流
- JSX 语法

3. 什么是 JSX？

答案：
JSX 是 JavaScript 的语法扩展，允许你在 JavaScript 中编写类似 HTML 的代码。浏览器不能直接识别 JSX，需要通过 Babel 等工具编译成普通 JavaScript。

4. 为什么 React 使用虚拟 DOM？

答案：
虚拟 DOM 是真实 DOM 的 JavaScript 表示。React 先比较新旧虚拟 DOM 的差异，再最小化更新真实 DOM，从而减少直接操作 DOM 的开销，提高性能。

5. 什么是组件？

答案：
组件是 React 应用的基本构建单元。它把 UI 拆分成独立、可复用的部分，每个组件负责自己的结构和逻辑。

6. 函数组件和类组件的区别是什么？

答案：
函数组件本质上是普通函数，使用 Hook 管理状态和副作用；类组件使用 class 定义，通过 this.state 和生命周期方法管理逻辑。现在实际开发中函数组件更常用。

7. 什么是 Props？

答案：
Props 是父组件向子组件传递数据的方式，是只读的。子组件不能直接修改 Props。

8. 什么是 State？

答案：
State 是组件内部维护的数据，状态变化会触发组件重新渲染。函数组件一般通过 useState 管理状态。

9. Props 和 State 的区别是什么？

答案：
- Props：由父组件传入，只读
- State：组件自身维护，可变
- Props 主要用于组件通信，State 主要用于组件内部数据管理

10. 什么是单向数据流？

答案：
React 中数据通常从父组件流向子组件，子组件通过 Props 接收数据，不能反向直接修改父组件状态。这让数据变化路径更清晰，更容易维护。

11. 什么是受控组件？

答案：
受控组件是指表单元素的值由 React 状态控制。例如输入框的 value 来自 state，onChange 负责更新 state。

12. 什么是非受控组件？

答案：
非受控组件是指表单数据由 DOM 本身管理，通常通过 ref 获取输入值。适合简单场景，但不如受控组件易管理。

13. React 中 key 有什么作用？

答案：
key 用于帮助 React 识别列表中哪些元素发生了变化，从而更高效地进行 diff 和更新。key 应该稳定且唯一，不推荐直接使用数组索引，除非列表不会变化。

14. 为什么不推荐把数组下标作为 key？

答案：
如果列表顺序发生变化，使用索引会导致 React 错误复用组件，可能引发状态错乱和渲染异常。

15. 什么是事件绑定？

答案：
React 中通过驼峰命名方式绑定事件，例如 onClick、onChange。事件处理函数通常写成函数引用，而不是直接执行。

16. React 中为什么要用 className 而不是 class？

答案：
因为 class 是 JavaScript 保留关键字，所以 JSX 中使用 className 表示 HTML 的类名。

17. 什么是条件渲染？

答案：
条件渲染是根据条件决定渲染不同内容。常见写法有 if、三元表达式、逻辑与 &&。

18. 什么是列表渲染？

答案：
列表渲染是通过 map() 遍历数组并返回一组 JSX 元素，通常需要配合 key 使用。

19. useState 是做什么的？

答案：
useState 是 React Hook，用于在函数组件中声明和更新状态。

20. setState 或 setXxx 为什么是异步/批量的？

答案：
React 为了性能会合并多次状态更新，减少不必要的重复渲染，因此状态更新通常不是立即同步反映到界面上的。

21. useEffect 是做什么的？

答案：
useEffect 用于处理副作用逻辑，例如请求数据、订阅事件、操作定时器、手动修改 DOM 等。

22. useEffect 的依赖数组有什么作用？

答案：
依赖数组用于控制副作用执行时机：
- 不传：每次渲染后都执行
- 空数组 []：只在首次挂载后执行一次
- [a, b]：当 a 或 b 变化时执行

23. useEffect 的清理函数有什么用？

答案：
清理函数用于在组件卸载前或下一次 effect 执行前清理副作用，如移除事件监听、清除定时器、取消订阅，防止内存泄漏。

24. useLayoutEffect 和 useEffect 的区别是什么？

答案：
useLayoutEffect 在 DOM 更新后、浏览器重绘前同步执行；useEffect 在页面重绘后异步执行。前者适合读取布局和避免闪烁，后者更常用。

25. 什么是 useRef？

答案：
useRef 用于保存一个可变引用，它的值在多次渲染之间保持不变。常见用途是获取 DOM 元素，或者保存不会触发重新渲染的数据。

26. useMemo 的作用是什么？

答案：
useMemo 用于记忆化计算结果，避免在每次渲染时重复执行昂贵计算。

27. useCallback 的作用是什么？

答案：
useCallback 用于记忆化函数本身，避免每次渲染都创建新的函数引用，常用于优化子组件渲染。

28. useMemo 和 useCallback 的区别是什么？

答案：
- useMemo 缓存的是计算结果
- useCallback 缓存的是函数本身
本质上 useCallback(fn, deps) 可以看作 useMemo(() => fn, deps)。

29. 什么是 React.memo？

答案：
React.memo 是高阶组件，用于缓存函数组件。当组件的 Props 没有变化时，React 可以跳过重新渲染。

30. 什么情况下需要做记忆化优化？

答案：
当组件渲染频繁、计算昂贵、或者因为函数和对象引用变化导致子组件重复渲染时，可以考虑使用 React.memo、useMemo、useCallback。

31. 什么是高阶组件（HOC）？

答案：
高阶组件是一个函数，接收组件作为参数并返回一个新组件，用于复用组件逻辑，例如权限控制、日志埋点等。

32. 什么是 Render Props？

答案：
Render Props 是一种通过函数作为 Props 传递渲染逻辑的模式，用于实现逻辑复用。

33. 什么是 Context？

答案：
Context 提供了一种跨组件层级共享数据的方式，适合主题、语言、登录态等全局数据，避免层层 Props 传递。

34. useContext 的作用是什么？

答案：
useContext 用于在函数组件中读取 Context 提供的值。

35. 什么是 React Fragment？

答案：
Fragment 用于在不增加额外 DOM 节点的情况下返回多个元素，写法有 <React.Fragment> 或 <>...</>。

36. React 中如何进行父子组件通信？

答案：
- 父传子：通过 Props
- 子传父：父组件传函数给子组件，子组件调用该函数
- 跨层级通信：通过 Context 或状态管理库

37. 什么是提升状态（Lifting State Up）？

答案：
当多个组件需要共享同一份数据时，把状态提到它们最近的共同父组件中进行统一管理，这就是状态提升。

38. React 中如何实现表单处理？

答案：
一般通过受控组件实现：输入框的值绑定到 state，onChange 事件更新 state。复杂场景可结合表单库，如 React Hook Form。

39. 什么是合成事件（SyntheticEvent）？

答案：
React 对原生浏览器事件进行了封装，形成跨浏览器兼容的合成事件。开发者通常直接使用 React 提供的事件对象即可。

40. React 中如何防止组件重复渲染？

答案：
常见方法：
- 使用 React.memo
- 使用 useMemo / useCallback
- 合理拆分组件
- 避免每次渲染创建新对象和新函数
- 减少不必要的状态更新

41. 什么是受控输入延迟问题，怎么优化？

答案：
当输入框绑定的状态更新引发大量组件重渲染时，可能出现输入卡顿。可通过拆分组件、降低状态提升范围、使用 useDeferredValue、memo 等方式优化。

42. 什么是 React Router？

答案：
React Router 是 React 常用的路由库，用于实现前端页面切换、嵌套路由、动态路由、导航守卫等。

43. React 中什么是懒加载（Lazy Loading）？

答案：
懒加载是指按需加载组件，而不是一次性加载全部代码。React 中常用 React.lazy 和 Suspense 实现。

44. React.lazy 和 Suspense 怎么配合使用？

答案：
React.lazy 用于动态导入组件，Suspense 用于在组件加载完成前显示 fallback 内容。

45. 什么是错误边界（Error Boundary）？

答案：
错误边界用于捕获其子组件树中的 JavaScript 渲染错误，并显示降级 UI。传统上通过类组件中的 componentDidCatch 和 getDerivedStateFromError 实现。

46. React 的生命周期有哪些？

答案：
类组件常见生命周期包括：
- 挂载：constructor、render、componentDidMount
- 更新：render、componentDidUpdate
- 卸载：componentWillUnmount
函数组件一般通过 Hook 模拟这些能力。

47. React 18 有哪些重要特性？

答案：
React 18 引入了并发渲染相关能力，例如自动批处理、startTransition、useDeferredValue、新的 createRoot API 等。

48. 什么是 startTransition？

答案：
startTransition 用于标记某些更新为“低优先级更新”，让 React 优先处理更重要的交互更新，提高用户体验。

49. React 中为什么强调不可变数据？

答案：
React 通常通过引用变化判断数据是否更新。如果直接修改原对象，React 可能无法正确识别变化；使用不可变更新更利于性能优化和状态追踪。

50. React 项目中常见的性能优化手段有哪些？

答案：
- 合理拆分组件
- 使用 key
- 使用 React.memo、useMemo、useCallback
- 路由和组件懒加载
- 减少不必要的状态提升
- 避免重复请求
- 虚拟列表优化长列表
- 使用 Profiler 分析性能瓶颈

51. 什么是 Portal？

答案：
Portal 允许把子组件渲染到父组件 DOM 层级之外的节点中，常用于弹窗、提示框、抽屉等浮层场景。

52. 什么是 StrictMode？

答案：
StrictMode 是开发环境下的辅助工具，用于提示潜在问题，例如不安全生命周期、重复副作用等，不会影响生产环境渲染结果。

53. 为什么开发环境下 useEffect 可能执行两次？

答案：
在 React 18 的严格模式下，开发环境会故意重复执行部分生命周期和副作用，用来帮助你发现副作用不纯或清理不完整的问题。

54. 什么是受控和非受控表单的取舍原则？

答案：
需要统一校验、联动和状态管理时优先使用受控组件；表单简单、只在提交时读取值时可以考虑非受控组件。

55. 什么是状态提升的缺点？

答案：
状态提升会让父组件承担更多职责，导致 Props 传递链变长、组件耦合增强，过度使用会降低可维护性。

56. React 中如何复用逻辑？

答案：
常见方式有自定义 Hook、Context、组合模式、Render Props 和 HOC。当前最主流的是自定义 Hook。

57. 什么是自定义 Hook？

答案：
自定义 Hook 是把可复用的状态逻辑和副作用逻辑抽取到以 use 开头的函数中，便于多个组件共享逻辑。

58. 自定义 Hook 和普通函数有什么区别？

答案：
自定义 Hook 可以调用其他 Hook，并遵守 Hook 规则；普通函数不能随意调用 Hook，也不参与 React 的状态管理流程。

59. Hook 使用时有哪些规则？

答案：
Hook 只能在函数组件或自定义 Hook 顶层调用，不能放在条件、循环、嵌套函数中，以保证调用顺序稳定。

60. 为什么 Hook 不能放在条件语句中？

答案：
因为 React 依赖 Hook 的调用顺序来关联状态。如果条件分支导致调用顺序变化，就会出现状态错位。

61. React 中什么是闭包陷阱？

答案：
在函数组件中，事件处理器或副作用可能捕获旧的状态值，导致读取到过期数据。这类问题通常与依赖项不完整或异步回调有关。

62. 如何解决闭包导致的旧值问题？

答案：
可以补全依赖数组、使用函数式更新、使用 useRef 保存最新值，或重构代码避免在旧闭包中读取状态。

63. 什么是函数式更新？

答案：
函数式更新是把更新函数传给 setState，例如 setCount(prev => prev + 1)，适合依赖前一个状态值的场景。

64. React 中如何共享全局状态？

答案：
小型应用可以用 Context，中大型应用通常结合 Zustand、Redux Toolkit、Jotai 等状态管理库。

65. Context 是否适合所有全局状态？

答案：
不适合。Context 更适合低频更新的共享数据；高频更新状态如果直接放入 Context，容易导致大量消费者重复渲染。

66. 什么是 Props Drilling？

答案：
Props Drilling 指数据必须层层通过中间组件传递给深层子组件，即使中间组件本身并不使用这些数据。

67. 如何避免 Props Drilling？

答案：
可以使用 Context、状态管理库、组合模式，或者重新设计组件层级，减少不必要的数据穿透。

68. 什么是组合优于继承？

答案：
React 更推荐通过组件组合来复用 UI 和行为，而不是像传统 OOP 那样依赖继承层级，这样更灵活、更易维护。

69. React 中什么是受控副作用？

答案：
指副作用的触发时机、依赖关系和清理逻辑都明确可控，避免无序请求、重复订阅和资源泄漏。

70. 何时应该拆分组件？

答案：
当一个组件职责过多、状态复杂、复用性差或渲染范围过大时，应考虑拆分为更小、更清晰的组件。

71. React 中什么是渲染阶段和提交阶段？

答案：
渲染阶段负责计算新 UI；提交阶段才真正修改 DOM。理解这两个阶段有助于判断副作用和性能问题。

72. 为什么不能在渲染阶段做副作用？

答案：
因为渲染阶段应该保持纯函数特性，可能被中断或重复执行；副作用应放在 useEffect 等提交后阶段处理。

73. React 中什么是批处理更新？

答案：
批处理更新指 React 会把同一轮事件中的多个状态更新合并处理，从而减少重复渲染，提升性能。

74. React 18 自动批处理有什么变化？

答案：
React 18 将自动批处理扩展到更多异步场景，比如 Promise、setTimeout 和原生事件回调中。

75. 什么是 flushSync？

答案：
flushSync 用于强制 React 立即同步刷新更新。只有在确实需要立刻拿到更新后 DOM 结果时才应谨慎使用。

76. 什么是 useDeferredValue？

答案：
useDeferredValue 用于把某个值的更新延后为低优先级更新，常用于优化搜索输入、大列表过滤等场景。

77. startTransition 和 useDeferredValue 的区别是什么？

答案：
startTransition 用于把一段状态更新标记为低优先级；useDeferredValue 用于延后某个值的消费，二者都服务于交互流畅性优化。

78. 什么是服务端渲染（SSR）？

答案：
SSR 是指先在服务端生成 HTML，再返回给浏览器。它有助于首屏速度、SEO 和弱网场景体验。

79. SSR 的优缺点是什么？

答案：
优点是首屏快、SEO 友好；缺点是服务端压力更高、开发复杂度更大，还要处理水合一致性问题。

80. 什么是 Hydration？

答案：
Hydration 指浏览器在拿到服务端渲染的 HTML 后，把 React 事件和状态系统“挂载”到已有 DOM 上的过程。

81. 什么是 Hydration Mismatch？

答案：
指服务端输出和客户端首次渲染结果不一致，React 会报警告甚至重新渲染，常见原因是时间、随机数和环境差异。

82. React 中如何处理长列表性能问题？

答案：
可以使用虚拟列表、分页、懒加载、稳定的 key 和减少单项渲染复杂度等方式优化。

83. 什么是虚拟列表？

答案：
虚拟列表只渲染可视区域附近的列表项，而不是一次性渲染全部数据，从而显著降低 DOM 数量和渲染开销。

84. React 中为什么要保持组件纯净？

答案：
纯组件更容易预测、测试和优化。相同输入应产生相同输出，避免在渲染函数中偷偷修改外部状态。

85. 什么是不可变更新？

答案：
不可变更新指不直接修改原对象或数组，而是创建新引用返回，例如使用展开运算符、map、filter 等。

86. React 中如何更新对象状态？

答案：
通常使用浅拷贝创建新对象，例如 setUser(prev => ({ ...prev, name: 'Tom' }))，避免直接修改原对象。

87. React 中如何更新数组状态？

答案：
使用 map、filter、concat、展开运算符等返回新数组，而不是直接 push、splice 修改原数组。

88. 什么是 key 冲突？

答案：
当兄弟节点之间的 key 不唯一时，React 无法准确识别节点身份，可能导致错误复用和渲染异常。

89. React 中受控组件为什么更适合复杂表单？

答案：
因为数据、校验、联动和提交都由 React 状态统一管理，更容易实现规则校验、格式转换和业务逻辑组合。

90. React 中如何做代码分割？

答案：
可以通过动态导入、React.lazy、路由级懒加载和构建工具分包策略来减少首屏加载体积。

91. 什么是 Suspense 的常见使用场景？

答案：
常见于懒加载组件的加载占位，也可用于配合特定数据获取方案展示统一 fallback。

92. React 中什么是错误恢复边界？

答案：
它本质上还是 Error Boundary 的一种使用思路：当局部 UI 报错时，只让局部降级，而不是整个应用白屏。

93. React 中如何优化 Context 性能？

答案：
可以拆分多个 Context、稳定 value 引用、减少无关数据放入同一个 Provider，必要时引入外部状态库。

94. 为什么内联对象和函数可能影响性能？

答案：
因为它们每次渲染都会生成新引用，可能导致依赖比较失败，让子组件或副作用不必要地重新执行。

95. 什么是受控渲染范围？

答案：
指通过组件拆分、局部状态、记忆化和上下文隔离，把状态变化影响限制在尽可能小的组件范围内。

96. React 中如何排查性能问题？

答案：

97. React 项目中常见反模式有哪些？

98. 什么是 React 的声明式编程？

你只需要描述在某个状态下 UI 应该是什么样子，React 会负责把状态变化映射为界面更新，而不是手动操作 DOM。

进阶与新特性

101. 什么是 useReducer？

答案：
useReducer 是管理复杂状态逻辑的 Hook，接收 (state, action) => newState 的 reducer 函数和初始状态，返回当前状态和 dispatch。适合多个子值相互依赖、状态变化逻辑复杂、需要集中管理的场景，比多个 useState 更清晰。本质上 useState 是 useReducer 的简化版。

102. 什么是 useId？

答案：
useId 是 React 18 新增的 Hook，用于生成在服务端和客户端之间稳定一致的唯一 ID，解决 SSR 水合时 ID 不匹配的问题。常用于 aria 属性（如 aria-labelledby）或表单 label 与控件的关联，不要用它生成列表 key。

103. 什么是 forwardRef？

答案：
forwardRef 允许函数组件将接收到的 ref 转发给其内部的 DOM 节点或子组件。语法为 React.forwardRef((props, ref) => <input ref={ref} />)。常用于封装表单控件库、需要父组件直接控制子组件 DOM（如聚焦、滚动）的场景。

104. 什么是 useImperativeHandle？

答案：
useImperativeHandle 配合 forwardRef 使用，允许自定义暴露给父组件 ref 的实例值，而不是暴露整个 DOM 节点。例如只暴露 { focus, reset } 方法，隐藏其他 DOM 接口，实现更好的封装性。

105. 什么是 React Server Components（RSC）？

答案：
RSC 是 React 18+ 引入的新模式，允许在服务端渲染组件，不把相应的 JavaScript 发送到客户端，减少 bundle 体积。Server Components 可以直接访问数据库、文件系统、后端服务，但不能使用 state、effect 和浏览器 API。交互逻辑仍由 Client Components（加 "use client" 指令）承担，两者可以组合使用。

106. React diff 算法的核心规则是什么？

答案：
React diff（协调算法）基于三个假设：① 跨层级移动忽略不计，只做同层比较；② 不同类型的元素生成不同树，直接替换；③ 通过 key 标识稳定的子元素身份。这使复杂度从 O(n³) 降到 O(n)。所以 key 的稳定性对性能至关重要，随机或索引 key 会破坏 diff 优化。

107. 什么是 React 中的受控与非受控的对比？

答案：
受控组件：值由 React state 驱动，通过 onChange 同步，易于校验和联动，但代码量较多。非受控组件：值由 DOM 自身维护，通过 ref 读取，适合简单场景或集成第三方库。复杂表单（校验、联动、提交控制）推荐受控；简单表单或文件上传等场景可用非受控。

108. 什么是 use Hook（React 19）？

答案：
use 是 React 19 新增的 Hook，可以读取 Promise 或 Context 的值。读取 Promise 时，若未 resolve 会触发最近的 <Suspense> fallback；读取 Context 类似 useContext。与其他 Hook 不同，use 可以在条件语句中调用，使异步数据处理更灵活。

109. React 中如何避免 useEffect 中的竞态条件？

答案：
竞态条件发生在快速切换时多个请求并发，后发出的先返回导致数据错误。解决方案：① 在 useEffect 清理函数中用 AbortController 取消请求；② 设置 let isCancelled = false 标志，在回调中判断后再 setState；③ 使用 React Query、SWR 等数据获取库，它们内置了竞态处理。

110. 什么是 React Query / SWR？

答案：
它们是专注于服务端状态管理的库。核心能力包括：自动缓存和去重请求、窗口聚焦时自动重新验证、后台刷新、加载/错误状态管理、分页和无限滚动支持。相比 useEffect + useState，大大减少数据获取的样板代码，并解决了竞态条件、请求重复等问题。

111. 什么是 Zustand？与 Redux 的区别是什么？

答案：
Zustand 是轻量级状态管理库，API 极简：通过 create 定义 store，直接在组件中 useStore(state => state.count) 使用。无需 Provider 包裹、无需 action/reducer 样板、支持订阅局部状态避免不必要渲染。Redux（Toolkit）更适合大型项目，有 devtools、时间旅行调试、严格的单向数据流。

112. 什么是 React 中的 Compound Components 模式？

答案：
复合组件模式是将多个相关组件组合使用，通过 Context 共享内部状态，对外提供灵活的组合 API。例如 <Select> 和 <Select.Option> 的关系。优点是 API 灵活，调用方可以自由排列子组件、插入自定义内容，而不需要通过大量 props 控制内部细节。
