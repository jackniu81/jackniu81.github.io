AI Agent 工程师面试题（附答案）

基础概念

1. 什么是 AI Agent？

答案：
AI Agent（智能体）是一种能够感知环境、自主规划、调用工具并执行动作以实现目标的 AI 系统。与普通 LLM 聊天不同，Agent 具备自主决策、多步执行、工具调用的能力，能够完成复杂的、需要多个步骤的任务。

2. AI Agent 与普通 LLM 有什么区别？

答案：

对比维度 普通 LLM AI Agent
交互方式 单轮/多轮对话 自主规划、多步执行
工具使用 无 可调用外部工具、API、数据库
记忆能力 有限上下文窗口 持久记忆（短期+长期）
自主性 被动回答 主动规划和行动
任务复杂度 简单、单步 复杂、多步、长周期

3. AI Agent 的四大核心组件是什么？

答案：
- 感知（Perception）：接收用户输入、环境状态、工具返回结果
- 规划（Planning）：分解任务、制定执行计划（如 ReAct、Chain-of-Thought）
- 记忆（Memory）：存储上下文（短期）和知识（长期），支持跨步骤推理
- 行动（Action）：调用工具、执行代码、调用 API、操作文件等

4. 什么是 ReAct 架构？

答案：
ReAct（Reasoning + Acting）是一种 Agent 推理框架，让 LLM 交替进行思考（Thought）和行动（Action）：

Thought: 我需要搜索今天的天气
Action: search_web("今天北京天气")
Observation: 晴天，25°C
Thought: 已获得结果，整理回答
Action: 返回结果给用户

这种模式使 LLM 的推理过程透明、可调试，是目前最主流的 Agent 模式之一。

5. Agent 的规划模式有哪些？

答案：
- ReAct：思考与行动交替，动态规划，适合未知环境
- Plan-and-Execute：先整体规划，再逐步执行，适合复杂任务
- Reflection：执行后自我反思，迭代改进，提升输出质量
- Self-Ask：将复杂问题分解为子问题逐步回答
- Tree of Thoughts（ToT）：并行探索多个推理路径，选最优解

记忆系统

6. Agent 的记忆系统如何设计？

答案：
Agent 记忆分为三类：
- 短期记忆（In-context Memory）：当前对话的上下文，存在 LLM 的 context window 中，不持久
- 长期记忆（External Memory）：持久化存储，通过向量数据库（RAG）或数据库检索，跨会话保留
- 工作记忆（Working Memory）：当前任务执行中的中间状态、变量、步骤结果

7. 什么是 RAG？与 Agent 有何关系？

答案：
RAG（Retrieval-Augmented Generation，检索增强生成）是将外部知识库与 LLM 结合的技术：
1. 将文档分块，向量化后存入向量数据库
2. 用户提问时，检索相关文档片段
3. 将检索结果注入 LLM prompt 生成回答

在 Agent 中，RAG 通常作为长期记忆工具，Agent 可以决定是否调用 RAG 检索来补充知识。

8. 常见向量数据库有哪些？

答案：
- Chroma：轻量级，本地部署，适合原型和小型项目
- Pinecone：云托管，高性能，适合生产环境
- Milvus：开源，高性能，支持大规模向量检索
- Weaviate：开源，支持混合检索（语义+关键词）
- FAISS：Facebook 出品，纯本地，适合离线场景

工具调用

9. 什么是 Function Calling / Tool Use？

答案：
Function Calling 是让 LLM 能够决定"调用哪个工具、传入什么参数"的能力：
1. 开发者定义工具的名称、描述和参数 schema（通常是 JSON Schema）
2. LLM 根据用户意图选择合适的工具并生成调用参数
3. 代码执行实际的工具调用，将结果返回给 LLM
4. LLM 基于结果继续推理或生成最终回答

tools = [{
    "name": "get_weather",
    "description": "获取指定城市的天气",
    "parameters": {
        "type": "object",
        "properties": {
            "city": {"type": "string", "description": "城市名称"}
        },
        "required": ["city"]
    }
}]

10. Agent 常见的工具类型有哪些？

答案：
- 搜索工具：Google Search、Bing、SerpAPI、Tavily
- 代码执行：Python Interpreter、Node.js 运行环境
- 文件操作：读写文件、解析 PDF/Excel/Word
- 数据库查询：SQL 查询、向量数据库检索
- API 调用：REST API、GraphQL、第三方服务
- 浏览器控制：Playwright、Puppeteer（用于 Web 自动化）
- 计算器：数学计算，避免 LLM 幻觉

常用框架

11. LangChain 是什么？核心概念有哪些？

答案：
LangChain 是最主流的 AI Agent 开发框架，提供构建 LLM 应用的标准化组件：
- Chain：将多个组件串联成工作流
- Agent：基于 LLM 决策，动态选择工具和步骤
- Tool：封装外部能力供 Agent 调用
- Memory：管理对话上下文
- Retriever：从知识库检索相关文档
- Prompt Template：管理和复用 prompt

12. LangGraph 与 LangChain 有什么区别？

答案：
- LangChain：基于线性 Chain，适合顺序执行的工作流
- LangGraph：基于有向图（DAG），支持循环、条件分支、并行执行，适合复杂 Agent 工作流

LangGraph 核心概念：
- State：贯穿整个图的共享状态
- Node：图中的执行节点（函数或 Agent）
- Edge：节点之间的连接，支持条件路由
- Checkpointer：持久化状态，支持暂停/恢复

13. AutoGen 是什么？与 LangChain 有何不同？

答案：
AutoGen（微软出品）专注于多智能体对话协作，让多个 Agent 相互交流完成任务：
- 每个 Agent 有独立角色（如 Planner、Coder、Reviewer）
- Agent 之间通过消息传递协作
- 支持人机混合（Human-in-the-loop）

与 LangChain 的区别：
- LangChain 更侧重工作流编排和工具调用
- AutoGen 更侧重多 Agent 角色扮演和对话协作

14. CrewAI 是什么？

答案：
CrewAI 是基于角色的多智能体框架，用船员（Crew）来比喻多个 Agent 分工协作：
- Agent：有 role、goal、backstory，定义具体角色
- Task：分配给某个 Agent 的具体任务
- Crew：管理所有 Agent 和 Task 的编排器
- Process：顺序或层级执行模式

适合需要多个专业化角色协作的场景，如"研究员 + 写作者 + 审核员"。

15. 如何选择合适的 Agent 框架？

答案：

场景 推荐框架
快速原型、简单 RAG LangChain
复杂工作流、有循环/条件 LangGraph
多角色对话协作 AutoGen / CrewAI
生产级、高可控 LangGraph + 自定义
轻量、无框架依赖 纯 SDK（OpenAI / Anthropic）

多智能体（Multi-Agent）

16. 什么是多智能体系统？

答案：
多智能体系统由多个 AI Agent 组成，每个 Agent 有独立的角色和职责，通过协作完成复杂任务：
- 分工：每个 Agent 专注于特定任务（规划、编码、测试、审查）
- 并行：多个 Agent 同时处理不同子任务，提升效率
- 检验：一个 Agent 验证另一个 Agent 的输出，减少错误

17. 多智能体的常见架构模式有哪些？

答案：
- Supervisor（监督者模式）：一个主 Agent 负责协调分配任务给子 Agent
- Peer-to-Peer（点对点）：Agent 之间直接通信，无中心节点
- Pipeline（流水线）：Agent 串行执行，上一个的输出是下一个的输入
- Hierarchical（层级）：树形结构，高层 Agent 管理低层 Agent

18. 多智能体通信如何实现？

答案：
- 消息传递：Agent 发送/接收结构化消息（如 JSON）
- 共享状态：通过共享数据库或内存（如 LangGraph State）交换信息
- 工具调用：一个 Agent 以"工具"形式调用另一个 Agent
- 事件驱动：通过消息队列（如 Kafka、RabbitMQ）异步通信

评估与工程化

19. 如何评估 Agent 的质量？

答案：
- 任务完成率：Agent 成功完成任务的比例
- 步骤效率：完成任务所需的工具调用次数（越少越好）
- 幻觉率：Agent 输出的错误信息比例
- 工具调用准确率：选择正确工具的比例
- 延迟与成本：Token 消耗、API 调用次数、响应时间
- 人工评估（LLM-as-Judge）：用另一个 LLM 评估输出质量

常用评估框架：LangSmith、Ragas、TruLens

20. Agent 的常见问题有哪些？如何处理？

答案：
- 幻觉（Hallucination）：LLM 编造信息 → 引入 RAG、增加验证步骤
- 无限循环：Agent 在某步骤反复失败 → 设置最大步骤数限制
- 工具滥用：调用不必要的工具 → 优化工具描述，精简工具集
- 上下文丢失：多步骤后忘记早期信息 → 增强记忆管理
- 成本失控：Token 消耗过多 → 控制 context window，压缩历史

21. 什么是 Human-in-the-Loop（人机协同）？

答案：
Human-in-the-Loop 是在 Agent 工作流中加入人工干预的机制：
- 在关键决策节点暂停，等待人工确认后再继续
- 防止 Agent 执行高风险操作（如删除数据、发送邮件）
- 支持人工修正 Agent 的中间输出

LangGraph 原生支持 breakpoint（断点）和 interrupt 实现此功能。

23. 如何设计一个高质量的 Prompt？

答案：
好的 Prompt 应包含以下要素：

1. 角色定义（Role）：You are an expert ...
2. 任务描述（Task）：Your goal is to ...
3. 上下文（Context）：Given the following information ...
4. 约束条件（Constraints）：You must only ..., avoid ...
5. 输出格式（Output Format）：Respond in JSON with fields ...
6. 示例（Few-shot）：Example input/output

常用技巧：
- Chain-of-Thought：要求模型"step by step"思考
- Self-consistency：多次采样取最优
- Structured Output：要求 JSON 格式输出减少解析错误

传统 AI Agentic AI

适应性 固定流程 动态适应环境变化
工具使用 无或固定 动态选择和调用工具
代表 图像识别、推荐系统 AutoGPT、Devin、Manus

2025-2026 前沿热点

26. 什么是 OpenAI Agents SDK？

答案：
OpenAI Agents SDK（2025 年发布）是 OpenAI 官方推出的轻量级 Agent 开发框架，前身为 Swarm。

核心概念：
- Agent：有 instructions（角色描述）和 tools（工具列表）的 LLM 执行单元
- Handoff（移交）：一个 Agent 将任务移交给另一个更专业的 Agent
- Guardrails（护栏）：对 Agent 输入/输出进行验证的过滤器
- Runner：协调 Agent 执行循环的调度器

代码示例：

from openai import OpenAI
from agents import Agent, Runner, tool

@tool
def get_weather(city: str) -> str:
    return f"{city} 今天晴天，25°C"

weather_agent = Agent(
    name="天气助手",
    instructions="你是一个天气查询助手，帮用户查询城市天气。",
    tools=[get_weather]
)

result = Runner.run_sync(weather_agent, "北京今天天气怎么样？")
print(result.final_output)

与 LangChain 的区别：
- OpenAI Agents SDK 更轻量、官方支持
- 原生支持 Handoff 多 Agent 协作
- 不依赖 LangChain 的复杂抽象，学习曲线更低

27. 什么是 Google ADK（Agent Development Kit）？

答案：
Google ADK（Agent Development Kit）是 Google 于 2025 年发布的开源 Agent 框架，专为构建可互操作的 AI Agent 设计。

核心特点：
- 多 Agent 编排：原生支持层级化多 Agent 系统
- A2A 原生集成：内置 Agent2Agent 协议支持
- MCP 集成：与 Model Context Protocol 无缝对接
- 流式事件：基于事件驱动的 Agent 执行模型

基础架构：

from google.genai.adk import Agent, Tool, Orchestrator

search_tool = Tool(name="search", function=google_search)

researcher = Agent(
    name="research_agent",
    model="gemini-2.5-pro",
    tools=[search_tool],
    instruction="负责收集和分析信息"
)

writer = Agent(
    name="writer_agent",
    model="gemini-2.5-flash",
    instruction="负责将信息整理成报告"
)

orchestrator = Orchestrator(agents=[researcher, writer])
result = orchestrator.run("分析 2025 年 AI 编程工具市场趋势")

部署选项：Google Agent Engine、Cloud Run、GKE

与 LangGraph 对比：ADK 更紧密集成 Google 生态（Gemini、Vertex AI），LangGraph 更通用、更成熟。

28. 什么是 A2A 协议（Agent2Agent Protocol）？

答案：
A2A（Agent2Agent）协议是 Google 于 2025 年 4 月发布的开放标准，解决不同框架、不同厂商的 AI Agent 之间的互操作问题。

核心理念：
- MCP：解决 Agent ↔ 工具 的通信（Agent 如何调用工具）
- A2A：解决 Agent ↔ Agent 的通信（Agent 如何委托另一个 Agent）

MCP vs A2A 对比：

维度 MCP A2A
通信对象 Agent ↔ Tool（工具） Agent ↔ Agent（智能体）
发起方 Agent 主动调用工具 Agent 委托另一个 Agent
标准化内容 工具 schema、资源接口 Agent 发现、任务委托、结果返回
发起方 Anthropic Google（50+ 合作伙伴）

A2A 工作流程：

用户请求
    ↓
Orchestrator Agent（协调者）
    ↓ A2A 委托
Research Agent（研究者）  ←→  Writing Agent（写作者）
    ↓ 通过 MCP 调用工具
搜索工具、数据库、文件系统

支持伙伴：Langchain、Salesforce、SAP、ServiceNow 等 50+ 企业。

意义：A2A + MCP 构成了 AI Agent 的完整协议栈，类比于 HTTP（应用层）+ TCP（传输层）。

29. 什么是 Prompt Caching（提示词缓存）？

答案：
Prompt Caching 是大模型 API 的一项重要优化特性，将重复使用的上下文缓存在服务器端，显著降低成本和延迟。

工作原理：
1. 首次请求：完整处理系统提示和文档上下文（正常计费）
2. 后续请求：相同前缀部分从缓存读取（仅收取少量缓存读取费用）
3. 缓存TTL：通常 5 分钟（Anthropic）

成本对比（Anthropic）：
| 类型 | 价格 |
|---|---|
| 普通输入 Token | $3 / 1M tokens |
| 缓存写入 | $3.75 / 1M tokens（首次） |
| 缓存读取 | $0.30 / 1M tokens（后续）节省 90% |

使用场景：
- 系统提示较长（1000+ tokens）的 Agent
- RAG 检索结果作为固定上下文
- 代码库分析（将代码文件缓存，多次查询）

代码示例（Anthropic）：

client.messages.create(
    model="claude-opus-4-5",
    system=[{
        "type": "text",
        "text": "你是代码审查专家...",
        "cache_control": {"type": "ephemeral"}  # 标记缓存
    }],
    messages=[{"role": "user", "content": "审查这段代码"}]
)

OpenAI 缓存：GPT-4o 自动缓存超过 1024 tokens 的前缀，无需手动标记。

30. Agent 可观测性（Observability）如何实现？

答案：
Agent 可观测性是生产环境中监控、调试和评估 Agent 行为的关键能力。

三大核心维度：
- 追踪（Tracing）：记录 Agent 的每一步执行（工具调用、LLM 请求、决策链路）
- 评估（Evaluation）：自动或人工评估 Agent 输出质量
- 监控（Monitoring）：实时监控延迟、错误率、Token 消耗、成本

主流工具对比：

工具 厂商 特点
LangSmith LangChain 与 LangChain/LangGraph 深度集成，功能全面
Langfuse 开源 开源可自部署，支持多框架，成本低
Arize Phoenix Arize AI 专注 AI 评估，支持 RAG 质量分析
Braintrust Braintrust 专注 Eval，团队协作友好
Helicone Helicone 轻量级 API 代理，快速接入

LangSmith 接入示例：

import os
os.environ["LANGCHAIN_TRACING_V2"] = "true"
os.environ["LANGCHAIN_API_KEY"] = "your-key"
os.environ["LANGCHAIN_PROJECT"] = "my-agent"

# 之后所有 LangChain/LangGraph 调用自动追踪

关键指标：
- Token 消耗：监控每次 Agent 运行的 token 数
- 工具调用成功率：工具执行成功的比例
- 任务完成率：Agent 成功完成目标任务的比例
- 延迟分布：P50/P95/P99 响应时间

31. 什么是 Computer Use（计算机使用）Agent？

答案：
Computer Use 是 Anthropic 于 2024 年底推出的突破性能力，允许 AI Agent 直接控制计算机桌面（鼠标、键盘、屏幕截图）来完成任务。

工作原理：

截图 → 视觉理解 → 决策（点击/输入/滚动）→ 执行 → 截图（下一步）

支持的操作：
- 鼠标点击、拖拽
- 键盘输入
- 滚动页面
- 截图分析
- 文件操作

当前主要产品：
- Claude Computer Use：Anthropic API，开发者可集成
- OpenAI Operator：面向消费者，操作网页完成任务（预约、购物等）
- Google Project Mariner：Chrome 插件形态的浏览器 Agent

与 Playwright/Selenium 的区别：
| 维度 | 传统 Web 自动化 | Computer Use |
|---|---|---|
| 依赖 | DOM 结构、CSS 选择器 | 屏幕截图（像素级） |
| 适用范围 | 仅 Web 应用 | 任何桌面/Web 应用 |
| 维护成本 | UI 变化后需更新脚本 | 自适应，无需维护 |
| 稳定性 | 高 | 仍在改善中 |

当前局限：
- 速度较慢（每步需截图+推理）
- 成本较高
- 复杂界面下错误率仍偏高

32. 什么是结构化输出（Structured Output）？

答案：
Structured Output 是让 LLM 严格按照预定义的 JSON Schema 输出结果，确保 100% 可解析、可靠。

传统 JSON 模式 vs 结构化输出：

OpenAI 结构化输出示例：

from pydantic import BaseModel
from openai import OpenAI

class UserInfo(BaseModel):
    name: str
    age: int
    skills: list[str]

response = client.beta.chat.completions.parse(
    model="gpt-5",
    messages=[{"role": "user", "content": "提取：张三，28岁，擅长 Python 和 React"}],
    response_format=UserInfo,
)
user = response.choices[0].message.parsed
print(user.name, user.age)  # 张三 28
