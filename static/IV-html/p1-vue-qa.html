Vue 常见面试题 100 道（附答案）

基础概念

1. 什么是 Vue？

答案：
Vue 是一个渐进式 JavaScript 框架，主要用于构建用户界面，特点是上手快、响应式强、生态完整。

2. 什么是渐进式框架？

答案：
渐进式指你可以按需使用 Vue 的能力，既能只用视图层，也能结合路由、状态管理和工程化方案构建大型应用。

3. Vue 的核心特点有哪些？

答案：
核心特点包括响应式系统、组件化开发、模板语法、指令系统、生态完善和学习成本较低。

4. Vue 2 和 Vue 3 的主要区别是什么？

答案：
Vue 3 在性能、Tree Shaking、TypeScript 支持、Composition API 和源码架构上都有明显提升。

5. 什么是 MVVM？

答案：
MVVM 是一种分层思想，Model 表示数据，View 表示视图，ViewModel 负责把数据和视图绑定起来。

6. Vue 为什么适合中后台和中小型项目？

答案：
因为它语法直观、文档完善、开发效率高，适合快速搭建可维护的业务系统。

7. 什么是单文件组件？

答案：
单文件组件即 .vue 文件，通常由 template、script 和 style 三部分组成。

8. template 的作用是什么？

答案：
template 用于描述组件最终渲染出来的视图结构。

9. script setup 是什么？

答案：
script setup 是 Vue 3 的语法糖，能更简洁地编写 Composition API 组件。

10. style scoped 有什么作用？

答案：
它可以让当前组件的样式默认只作用于本组件，减少样式污染。

11. Vue 模板语法中的插值表达式是什么？

答案：
插值表达式通常写作 {{ message }}，用于把数据渲染到模板中。

12. Vue 指令是什么？

答案：
指令是带有 v- 前缀的特殊语法，用于给 DOM 添加响应式行为。

13. 常见的内置指令有哪些？

答案：
常见有 v-bind、v-model、v-if、v-show、v-for、v-on、v-html 等。

14. v-bind 的作用是什么？

答案：
v-bind 用于动态绑定属性，简写形式是 :。

15. v-on 的作用是什么？

答案：
v-on 用于绑定事件，简写形式是 @。

16. v-model 是做什么的？

答案：
v-model 用于实现表单控件和数据之间的双向绑定。

17. v-if 和 v-show 的区别是什么？

答案：
v-if 是真正的条件渲染，会销毁和重建节点；v-show 只是切换 display 样式。

18. v-for 需要注意什么？

答案：
使用 v-for 渲染列表时应提供稳定且唯一的 key，避免错误复用。

19. key 在 Vue 中的作用是什么？

答案：
key 用于帮助 Vue 识别节点身份，从而更准确地进行 diff 和复用。

20. Vue 中如何绑定 class 和 style？

答案：
可以绑定字符串、对象或数组，实现条件样式和动态样式控制。

响应式原理

21. Vue 的响应式是什么？

答案：
响应式是指当数据发生变化时，依赖这些数据的视图会自动更新。

22. Vue 2 的响应式原理是什么？

答案：
Vue 2 主要通过 Object.defineProperty 劫持对象属性，实现依赖收集和派发更新。

23. Vue 3 的响应式原理是什么？

答案：
Vue 3 主要使用 Proxy 实现响应式，能够更完整地拦截对象操作，性能和能力都更好。

24. 为什么 Vue 3 使用 Proxy 更好？

答案：
因为它能监听属性新增、删除、数组索引变化等更多场景，且不需要递归遍历所有属性。

25. 什么是依赖收集？

答案：
依赖收集就是在读取响应式数据时记录当前副作用函数，方便数据变化时通知它重新执行。

26. 什么是派发更新？

答案：
派发更新是指当响应式数据变化后，通知相关依赖重新运行，从而刷新视图。

27. reactive 的作用是什么？

答案：
reactive 用于把对象转换成响应式代理对象。

28. ref 的作用是什么？

答案：
ref 用于创建响应式基本类型或对象包装值，读取时通常通过 .value。

29. ref 和 reactive 的区别是什么？

答案：
ref 更适合基本类型和单值场景，reactive 更适合对象类型；两者都可用于响应式状态管理。

30. 什么是自动解包？

答案：
在模板中使用 ref 时，Vue 会自动读取其 .value，这就是自动解包。

31. computed 是什么？

答案：
computed 是基于依赖自动缓存的计算属性，适合从已有状态推导新值。

32. computed 和方法的区别是什么？

答案：
computed 有缓存，依赖不变时不会重复计算；方法每次渲染都会重新执行。

33. watch 的作用是什么？

答案：
watch 用于监听特定数据源变化，并在变化时执行副作用逻辑。

34. watchEffect 和 watch 的区别是什么？

答案：
watchEffect 会自动收集依赖并立即执行，watch 需要显式指定监听源，更适合精确控制。

35. 什么是深度监听？

答案：
深度监听是指监听对象内部嵌套属性的变化，通常通过 deep: true 开启。

36. 深度监听有什么代价？

答案：
它会增加遍历和依赖追踪成本，在大对象上可能影响性能。

37. readonly 的作用是什么？

答案：
readonly 可以把响应式对象包装成只读版本，防止外部修改。

38. shallowRef 和 ref 的区别是什么？

答案：
shallowRef 只跟踪最外层值变化，不会深度响应式处理内部对象。

39. shallowReactive 的作用是什么？

答案：
它只让对象第一层属性具备响应式，适合性能敏感或外部对象管理场景。

40. 什么时候适合用 computed 而不是 watch？

答案：
当你只是从已有状态推导新状态时优先用 computed，副作用场景再考虑 watch。

组件通信

41. Vue 组件通信的常见方式有哪些？

答案：
常见方式有 props、emit、provide/inject、状态管理库和事件总线等。

42. props 的作用是什么？

答案：
props 用于父组件向子组件传递数据。

43. 为什么 props 是单向数据流？

答案：
因为子组件不应直接修改父组件传入的数据，这能让数据流更清晰、更易维护。

44. 子组件如何通知父组件？

答案：
通常通过 emit 触发自定义事件，把变化通知给父组件。

45. emits 选项有什么意义？

答案：
它用于显式声明组件会触发哪些事件，便于约束和维护。

46. 什么是 provide/inject？

答案：
它是一种跨层级传值机制，适合祖先组件向深层子孙组件提供共享数据。

47. provide/inject 适合替代全局状态管理吗？

答案：
不完全适合，它更适合局部依赖注入，不如 Pinia/Vuex 那样擅长统一全局状态治理。

48. 什么是事件总线？

答案：
事件总线是通过统一事件中心在非父子组件间通信的一种方式，但大型项目中不推荐滥用。

49. 为什么不推荐滥用事件总线？

答案：
因为它会让组件关系变隐式，事件来源和流向不清晰，调试困难。

50. 什么是插槽？

答案：
插槽允许父组件向子组件指定位置传入模板内容，提升组件复用能力。

51. 默认插槽和具名插槽的区别是什么？

答案：
默认插槽用于单一区域内容分发，具名插槽适合组件中存在多个插槽区域的场景。

52. 什么是作用域插槽？

答案：
作用域插槽允许子组件把数据暴露给父组件插槽内容，从而实现更灵活的渲染控制。

53. 组件通信中什么时候适合用 Pinia？

答案：
当多个页面或多个不相关组件需要共享状态，并且状态更新逻辑较复杂时适合使用 Pinia。

54. 什么是受控组件思想在 Vue 中的体现？

答案：
父组件通过 modelValue 等属性控制子组件状态，子组件通过事件把变更通知回去。

55. Vue 3 中自定义 v-model 是如何工作的？

答案：
默认使用 modelValue 作为 prop，update:modelValue 作为更新事件。

生命周期与组合式 API

56. Vue 生命周期有哪些常见阶段？

答案：
常见包括创建、挂载、更新和卸载阶段，对应不同的生命周期钩子。

57. onMounted 适合做什么？

答案：
适合在组件挂载后执行 DOM 相关操作、发起初始化请求或注册浏览器事件。

58. onUpdated 何时触发？

答案：
当组件因为响应式数据变化而完成视图更新后触发。

59. onUnmounted 适合做什么？

答案：
适合清理定时器、事件监听、订阅和第三方实例，避免内存泄漏。

60. 为什么不要在 onUpdated 中随意修改状态？

答案：
因为这可能再次触发更新，导致不必要的循环渲染。

61. Composition API 的优势是什么？

答案：
它能按逻辑组织代码，更利于复杂组件拆分、复用和 TypeScript 支持。

62. Options API 和 Composition API 的区别是什么？

答案：
Options API 按选项类型组织代码，Composition API 按业务逻辑组织代码，更适合复杂场景。

63. 什么是组合式函数？

答案：
组合式函数是对可复用状态逻辑的抽取，类似 Vue 生态中的自定义 Hook。

64. 为什么复杂组件更适合 Composition API？

答案：
因为同一功能相关的状态、计算和副作用可以放在一起，维护成本更低。

65. setup 函数的作用是什么？

答案：
setup 是 Composition API 的入口，用于声明响应式状态、方法、计算属性和副作用逻辑。

66. setup 中为什么不能直接使用 this？

答案：
因为 setup 执行时组件实例尚未完全建立，它强调使用闭包而不是实例 this。

67. nextTick 的作用是什么？

答案：
nextTick 用于等待 DOM 更新完成后再执行逻辑，常用于读取最新 DOM 状态。

68. 什么是副作用清理？

答案：
副作用清理指在组件卸载或依赖变化前，释放订阅、监听器和异步任务等资源。

69. 什么情况下会使用 onBeforeUnmount？

答案：
当你需要在组件真正卸载前做收尾工作时可以使用它，比如提前停止某些任务。

70. keep-alive 有什么作用？

答案：
keep-alive 可以缓存动态组件实例，避免切换时重复销毁和重建。

路由与状态管理

71. Vue Router 的作用是什么？

答案：
Vue Router 用于管理单页应用中的页面切换、嵌套路由、参数路由和导航流程。

72. 路由模式有哪些？

答案：
常见有 hash 模式和 history 模式，后者更美观但通常需要服务端配合。

73. 动态路由是什么？

答案：
动态路由是指路径中包含参数，如 /user/:id，可用于匹配不同资源详情页。

74. 什么是导航守卫？

答案：
导航守卫是在路由跳转前后执行的钩子，常用于权限校验和埋点。

75. 全局前置守卫常用于什么场景？

答案：
常用于登录校验、角色权限控制、页面白名单和动态标题设置。

76. 什么是路由懒加载？

答案：
路由懒加载是按需加载页面组件，从而减少首屏包体积。

77. Pinia 是什么？

答案：
Pinia 是 Vue 官方推荐的状态管理库，设计更简洁，TypeScript 支持也更友好。

78. Pinia 相比 Vuex 有什么优势？

答案：
Pinia API 更简单、模块天然独立、类型推导更好，不再强制使用 mutation。

79. Pinia 中的 state、getters、actions 分别是什么？

答案：
state 表示状态，getters 表示派生状态，actions 表示更新状态和封装业务逻辑的方法。

80. 什么时候不需要状态管理库？

答案：
当状态只在单个组件或少量父子组件间使用时，本地状态和 props/emit 通常就足够。

性能优化与工程化

81. Vue 中常见性能优化手段有哪些？

答案：
包括组件拆分、稳定 key、懒加载、合理使用 computed、减少深度监听和列表虚拟化等。

82. 为什么不要在模板里写复杂表达式？

答案：
复杂表达式会降低可读性，也可能在每次渲染时重复计算，影响维护和性能。

83. 什么是异步组件？

答案：
异步组件是按需动态加载的组件，适合大组件或低频页面场景。

84. 什么是虚拟 DOM？

答案：
虚拟 DOM 是对真实 DOM 的 JavaScript 抽象，框架通过比较新旧虚拟 DOM 来优化更新。

85. Vue 中长列表如何优化？

答案：
可以使用分页、虚拟列表、懒渲染和减少单项组件复杂度等方式优化。

86. 为什么 key 不建议用数组索引？

答案：
因为列表顺序变化时会导致错误复用节点，可能出现状态错乱。

87. 什么是防抖和节流？

答案：
防抖是高频触发后只执行最后一次，节流是在一定时间内最多执行一次。

88. Vue 项目中常见的打包工具有哪些？

答案：
当前主流是 Vite，历史上也常见 Webpack。

89. 为什么 Vue 3 项目常用 Vite？

答案：
因为 Vite 启动快、热更新快、配置更轻量，开发体验更好。

90. 什么是 Tree Shaking？

答案：
Tree Shaking 是构建时删除未使用代码的优化手段，有助于减小打包体积。

91. 什么是 SSR？

答案：
SSR 是服务端先渲染 HTML 再返回给浏览器，有助于首屏速度和 SEO。

92. 什么是 Hydration？

答案：
Hydration 是客户端把交互能力挂载到服务端渲染结果上的过程。

93. 什么是 <Suspense>？

答案：
<Suspense> 用于在异步依赖尚未就绪时展示占位内容，改善异步组件体验。

94. Vue 中如何做权限控制？

答案：
通常结合路由守卫、角色信息、菜单配置和按钮级权限指令实现。

95. 什么是自定义指令？

答案：
自定义指令用于封装底层 DOM 操作行为，如聚焦、权限隐藏和拖拽。

96. 什么时候适合写自定义指令？

答案：
当你需要复用面向 DOM 的底层行为，而不是单纯的业务逻辑时适合使用。

97. Vue 中常见反模式有哪些？

答案：
包括直接修改 props、滥用深度监听、事件总线泛滥、模板过重和组件职责过大等。

98. 为什么说组件设计比框架 API 更重要？

答案：
因为真正决定可维护性的往往是组件职责划分、状态边界和通信方式，而不只是语法本身。

99. 面试中如何系统回答 Vue 问题？

答案：
可以按概念、原理、使用场景、优缺点和性能注意点几个层次来组织答案。

100. 如何总结 Vue 的核心价值？

答案：
Vue 的核心价值是以较低学习成本提供高效、清晰、可扩展的前端开发体验，适合从简单页面到复杂应用的多种场景。

进阶特性

101. 什么是 toRef 和 toRefs？

答案：
toRef 为响应式对象的某个属性创建一个保持响应性的 ref，修改该 ref 会同步到原对象；toRefs 把整个响应式对象的所有属性都转成 ref 对象。常用于解构 reactive 对象后仍保持响应性，如 const { name, age } = toRefs(state)，避免解构后失去响应。

102. 什么是 Teleport？

答案：
<Teleport to="body"> 可以把组件的 DOM 渲染到指定目标节点，但组件仍保留在当前组件树的逻辑位置（props、context 不变）。常用于弹窗、Toast、抽屉等浮层，避免因 overflow: hidden 或 z-index 层叠上下文带来的显示问题。

103. defineProps 和 defineEmits 在 <script setup> 中如何使用？

答案：
在 <script setup> 中，两者都是编译器宏，无需 import。defineProps<{ title: string }>() 声明接收的 props 类型；defineEmits<{ (e: 'change', value: string): void }>() 声明触发的事件。返回值分别是 props 对象和 emit 函数，TypeScript 泛型写法能提供完整的类型推导。

104. 什么是 <Transition> 和 <TransitionGroup>？

答案：
<Transition> 用于单个元素/组件进入或离开时的过渡效果，通过自动添加 -enter-active、-leave-to 等 CSS 类名与动画配合；<TransitionGroup> 用于列表元素的增删过渡，支持 v-move 实现 FLIP 动画。两者也支持 JavaScript 钩子实现精细控制。

105. v-model 在 Vue 3 中有哪些变化？

答案：
Vue 3 中 v-model 默认 prop 从 value 改为 modelValue，事件从 input 改为 update:modelValue；支持自定义参数名 v-model:title；支持多个 v-model（v-model:title + v-model:content）替代 Vue 2 的 .sync 修饰符，语义更统一。

106. 什么是 defineExpose？

答案：
在 <script setup> 中，组件内部所有变量默认不对外暴露。defineExpose({ method, data }) 用于显式声明父组件通过 ref 可访问的属性和方法，提供精确的封装控制，相当于 Options API 中手动 return 的作用。

107. Vue 3 中 markRaw 的作用是什么？

答案：
markRaw 标记一个对象，使其永远不被 Vue 转换为响应式代理。适合第三方库实例（如地图、图表实例）或不需要响应式追踪的大型对象，避免 Proxy 包装带来的性能开销和意外副作用。

108. 什么是 Vue 3 的 app.use 和插件机制？

答案：
app.use(plugin) 安装插件，插件可以是有 install 方法的对象或函数。插件通常用于：注册全局组件、添加全局指令、通过 provide 注入全局服务、挂载 app.config.globalProperties。常见插件有 Vue Router、Pinia、Element Plus 等。

109. Vue 3 相比 Vue 2 在性能上有哪些提升？

答案：
① 响应式系统用 Proxy 替代 Object.defineProperty，支持数组索引和属性新增监听，无需 Vue.set；② 编译器优化：静态节点提升（hoisting）、Block Tree 跳过静态子树；③ 更好的 Tree Shaking，未使用的内置功能不会打包；④ Fragment、Teleport、Suspense 等新能力；⑤ 更小的核心体积。

110. 什么是 Vue 的 watchEffect vs watch 的最佳实践选择？

答案：
watchEffect 适合：自动追踪依赖、逻辑和依赖紧耦合、立即执行的场景，代码更简洁。watch 适合：需要访问变化前后的值（oldVal、newVal）、精确控制监听来源、避免首次执行的场景，控制更精确。两者都支持 onCleanup 做副作用清理。
