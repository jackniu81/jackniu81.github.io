TypeScript 常见面试题（附答案）

基础类型与类型系统

1. TypeScript 和 JavaScript 的主要区别是什么？

答案：
TypeScript 是 JavaScript 的超集，增加了静态类型系统、接口、泛型、枚举、装饰器等特性。TS 在编译期进行类型检查，捕获潜在错误；JS 是动态类型，错误只在运行时暴露。TS 最终编译为 JS 运行，不改变运行时行为，只提升开发阶段的安全性和可维护性。

2. TypeScript 的基础类型有哪些？

答案：
基本类型：string、number、boolean、null、undefined、symbol、bigint；特殊类型：any（放弃类型检查）、unknown（安全的 any，使用前必须收窄）、never（不可能有值）、void（无返回值函数）；引用类型：object、数组 T[]、元组 [T, U]、枚举 enum。

3. any 和 unknown 的区别是什么？

答案：
any 完全跳过类型检查，可以赋值给任何类型并执行任何操作，危险性高；unknown 是类型安全的 any，接收任何值，但使用前必须通过类型守卫收窄到具体类型才能操作。推荐用 unknown 处理不确定类型的输入（如 API 响应、catch 的错误对象）。

4. never 类型有什么用？

答案：
never 表示"永远不会发生"的值类型。常见场景：① 抛出异常的函数返回类型；② 无限循环函数；③ 穷举检查（exhaustive check）——在 switch 末尾用 const x: never = value 确保所有 case 都被处理，新增联合类型成员时编译器自动报错，是防止遗漏分支的利器。

5. type 和 interface 的区别是什么？

答案：
主要区别：① interface 支持声明合并（多次声明同名接口自动合并），type 不行；② type 可以表示联合类型、交叉类型、元组、基本类型别名等，interface 只能描述对象形状；③ 扩展语法：interface 用 extends，type 用 & 交叉类型。实践建议：公共 API / 对象形状用 interface，复杂类型操作用 type。

6. 什么是联合类型和交叉类型？

答案：
联合类型 A | B：值可以是 A 或 B 之一，只能访问两者共有属性，需类型守卫收窄后访问特有属性；交叉类型 A & B：合并多个类型所有属性，值必须同时满足所有类型，常用于 Mixin 和扩展对象类型。

7. 什么是类型断言？和类型转换有什么区别？

答案：
类型断言（as 关键字）告诉编译器"我知道这个值的类型"，只在编译期生效，不做运行时转换，若断言错误运行时仍会报错。与强制类型转换不同，断言不改变运行时值。双重断言 as unknown as T 可绕过不相关类型限制，应谨慎使用。非空断言 value! 告诉编译器值一定不为 null/undefined。

8. 什么是类型守卫？

答案：
类型守卫在运行时检查类型并缩小联合类型范围。常见形式：① typeof（基本类型）；② instanceof（类实例）；③ in 操作符（检查属性存在）；④ 自定义守卫函数（返回 value is Type 谓词，如 function isUser(v: any): v is User { return 'name' in v }）。使用后 TS 自动收窄类型，无需额外断言。

9. 什么是字面量类型和 as const？

答案：
字面量类型把具体值作为类型，如 type Dir = 'left' | 'right'，比字符串更精确。as const 把对象/数组所有属性推导为字面量类型且变为 readonly，如 const colors = ['red', 'blue'] as const 使 colors 类型为 readonly ['red', 'blue']，可用 typeof colors[number] 提取精确联合类型。

10. 什么是可辨识联合类型（Discriminated Union）？

答案：
也叫标签联合，每个联合成员有一个共同的字面量类型字段（标签），通过标签收窄类型。例如 type Shape = { kind: 'circle'; radius: number } | { kind: 'rect'; width: number }，在 switch(shape.kind) 中 TS 自动推导每个分支的具体类型。是处理多态数据的最佳模式。

泛型

11. 什么是泛型？为什么比 any 好？

答案：
泛型用 <T> 声明类型参数，延迟确定具体类型到调用时，保持类型信息传递。function identity<T>(arg: T): T { return arg } 调用时 TS 自动推导 T，返回值和输入保持同一类型。比 any 好在：不丢失类型信息，调用方仍有完整的类型提示和检查。

12. 泛型约束如何使用？

答案：
<T extends SomeType> 限制泛型范围，确保 T 具有特定属性。如 <T extends { length: number }> 保证 T 有 length；<K extends keyof T> 保证 K 是 T 的合法键；多重约束 <T extends A & B>；约束默认值 <T = string> 不传类型参数时使用 string。

13. 什么是条件类型？

答案：
条件类型形如 T extends U ? X : Y，根据类型关系动态推导结果类型。在分布式上下文中（T 为裸类型参数时），联合类型会被分别处理。常配合 infer 提取子类型：type Awaited<T> = T extends Promise<infer R> ? R : T，type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never。

14. 什么是映射类型？

答案：
映射类型通过 { [K in keyof T]: ... } 遍历并转换对象类型的属性，可修改修饰符（-? 移除可选、+readonly 添加只读）。内置工具类型如 Partial、Readonly、Required、Pick 都是映射类型实现的，也是自定义工具类型的核心语法。

15. 什么是模板字面量类型？

答案：
TS 4.1 引入，在类型层面做字符串拼接：type EventName<T extends string> = `on${Capitalize<T>}`。可将联合类型和字符串模板组合批量生成新联合类型，如 type CSSProp = `margin-${Side}`。内置字符串工具类型：Uppercase、Lowercase、Capitalize、Uncapitalize。

工具类型

16. 常用工具类型有哪些，分别有什么用？

答案：
- Partial<T> / Required<T>：全部属性变可选 / 必填
- Readonly<T>：全部属性变只读
- Pick<T, K> / Omit<T, K>：选取 / 排除指定属性
- Record<K, V>：构建键值映射类型
- Exclude<T, U> / Extract<T, U>：联合类型排除 / 提取
- NonNullable<T>：排除 null 和 undefined
- ReturnType<T> / Parameters<T>：提取函数返回类型 / 参数类型元组
- Awaited<T>：提取 Promise 展开后的类型

17. 如何实现 DeepPartial（深层可选）？

答案：

type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K];
};

通过递归映射类型：对每个属性若为对象则继续递归 DeepPartial，否则直接保留类型。同理可实现 DeepReadonly、DeepRequired 等变体。

18. keyof 和 typeof 在类型中的用法？

答案：
keyof T 提取类型 T 所有键的联合类型（'name' | 'age'），常用于约束键名参数如 function get<T, K extends keyof T>(obj: T, key: K): T[K]。typeof variable 在类型上下文中获取变量的推导类型，常用于 type Config = typeof defaultConfig 从值推导类型。组合 keyof typeof obj 是提取对象字面量键联合类型的常见模式。

19. 什么是索引签名和索引访问类型？

答案：
索引签名 { [key: string]: number } 描述动态属性名的对象，键类型只能为 string、number 或 symbol。索引访问类型 T[K]（查找类型）获取 T 类型在键 K 下的值类型，如 type AgeType = Person['age']，可与联合键组合 Person['name' | 'age']。

20. 如何从函数重载中提取类型？

答案：
Parameters<typeof fn> 提取最后一个重载的参数类型，ReturnType<typeof fn> 提取最后一个重载的返回类型。若需要提取特定重载的类型，可以用条件类型和函数类型匹配。更复杂的情况建议手动定义独立的类型而不是依赖提取。

类与装饰器

21. TypeScript 类中的访问修饰符有哪些？

答案：
- public（默认）：任何地方可访问
- private：只能类内部访问（编译期检查，运行时不受限）
- protected：类内部和子类可访问
- readonly：只读（必须在声明或构造函数中初始化）
- #field：ES 私有字段（运行时真正私有）
- abstract：声明抽象类/方法
- override（TS 4.3+）：显式标记覆盖父类方法，防止拼写错误

22. 什么是装饰器？有哪些常见类型？

答案：
装饰器是 TS 实验性特性（需开启 experimentalDecorators），语法 @decorator，本质是高阶函数，在不修改原代码的情况下增强行为。类型：① 类装饰器（修改/替换类）；② 方法装饰器（修改方法描述符）；③ 属性装饰器；④ 参数装饰器。常用于 NestJS（路由、注入、验证）、Angular、ORM（TypeORM 实体定义）。

23. 什么是抽象类？和接口的区别？

答案：
抽象类（abstract class）不能实例化，只能继承；可包含抽象方法（无实现，子类必须实现）和普通方法（有实现）；一个类只能继承一个抽象类。接口只声明形状，无实现；一个类可实现多个接口。选择依据：需要共享实现代码用抽象类，只需规范形状/多重实现用接口。

模块与配置

24. tsconfig.json 的关键配置项有哪些？

答案：
- strict：开启所有严格检查（强烈推荐）
- target：编译目标 JS 版本（ES2020/ESNext）
- module：输出模块格式（commonjs/ESNext）
- moduleResolution：模块解析策略（bundler 适合 Vite 等现代工具）
- paths：路径别名（@/* → src/*）
- baseUrl：路径解析基准目录
- noEmit：只做类型检查不输出文件（配合打包工具使用）
- lib：包含的类型定义库（["ESNext", "DOM"]）
- strict 下包含：noImplicitAny、strictNullChecks、strictFunctionTypes 等

25. 什么是声明文件（.d.ts）？

答案：
声明文件只包含类型声明，不含实现，用于为 JS 库提供类型信息。通过 declare 关键字声明模块、全局变量、函数类型。使用方式：① 安装 @types/xxx（DefinitelyTyped 社区维护）；② 库自带 .d.ts（package.json 中 types 字段）；③ 自建 custom.d.ts 为无类型的本地模块声明。

26. 什么是可空引用类型（strictNullChecks）？

答案：
开启 strictNullChecks 后，null 和 undefined 不再是所有类型的子类型，必须显式声明 string | null。这强制开发者在使用可能为空的值前做判断，在编译期消灭大量潜在的空指针错误。可选链 ?. 和非空断言 ! 是与之配套的常用语法。

TypeScript 实战

27. 如何在 React + TypeScript 中定义组件 Props？

答案：

interface ButtonProps {
  label: string;
  onClick?: () => void;
  variant?: 'primary' | 'secondary';
  children?: React.ReactNode;
}
// 推荐普通函数声明（比 FC 更精确）
function Button({ label, onClick, variant = 'primary' }: ButtonProps) { ... }

事件类型：React.MouseEvent<HTMLButtonElement>、React.ChangeEvent<HTMLInputElement>。Ref 类型：React.RefObject<HTMLDivElement>。

28. 如何类型安全地封装 API 请求？

答案：

interface ApiResponse<T> {
  code: number;
  message: string;
  data: T;
}
async function get<T>(url: string): Promise<ApiResponse<T>> {
  const res = await axios.get<ApiResponse<T>>(url);
  return res.data;
}
// 调用
const result = await get<User[]>('/users');
// result.data 类型为 User[]

对于运行时验证，可配合 zod 同时生成类型和运行时校验 schema。

29. 什么是协变和逆变？

答案：
协变（covariant）：子类型可赋值给父类型的位置（返回值是协变的）。逆变（contravariant）：父类型可赋值给子类型的位置（函数参数是逆变的）。开启 strictFunctionTypes 后，函数参数变为严格逆变。理解变型有助于理解为何某些函数类型赋值会报错：(x: Dog) => void 不可赋值给 (x: Animal) => void，但反过来可以。

30. 如何处理第三方库没有类型定义的情况？

答案：
① 安装 @types/xxx（优先）；② 创建 src/types/xxx.d.ts，用 declare module 'xxx' 声明最简类型（至少避免编译错误）；③ 精确声明需要用到的 API 形状；④ 临时方案可用 // @ts-ignore 或 // @ts-expect-error 忽略单行错误；⑤ 考虑向 DefinitelyTyped 贡献类型定义。

进阶特性

31. 什么是 satisfies 运算符（TS 4.9）？

答案：
satisfies 验证表达式符合某类型，但不改变推导类型（不像 : Type 注解会拓宽类型）。例如：

const config = { port: 3000, host: 'localhost' } satisfies Record<string, string | number>;
// config.port 类型仍为 3000（字面量），而非 string | number

既保留精确的字面量类型推导，又做类型约束验证，是两全其美的方案。

32. 什么是 using 关键字（TS 5.2）？

答案：
基于 ECMAScript 的显式资源管理提案，using 声明的变量在离开作用域时自动调用 [Symbol.dispose]()，await using 对应异步版本 [Symbol.asyncDispose]()。类似 C# 的 using 语句，可用于自动清理文件句柄、数据库连接、定时器等资源，避免遗忘 finally 中的清理代码。

33. 如何实现类型安全的事件发射器？

答案：

type EventMap = {
  'user:login': { userId: string };
  'user:logout': void;
};
class TypedEmitter<T extends Record<string, any>> {
  on<K extends keyof T>(event: K, handler: (data: T[K]) => void): void { ... }
  emit<K extends keyof T>(event: K, data: T[K]): void { ... }
}
const emitter = new TypedEmitter<EventMap>();
emitter.on('user:login', ({ userId }) => console.log(userId)); // 完整类型推导

34. 什么是 const 类型参数（TS 5.0）？

答案：
在泛型中用 <const T> 声明，类似对类型参数隐式应用 as const，函数调用时自动将字面量推导为精确类型，无需在调用处手动加 as const。如：

function createConfig<const T>(config: T): T { return config; }
const c = createConfig({ port: 3000 }); // port: 3000 而非 number

35. 如何用 TypeScript 实现安全的对象深路径访问？

答案：

type DeepGet<T, P extends string> =
  P extends `${infer K}.${infer Rest}`
    ? K extends keyof T ? DeepGet<T[K], Rest> : never
    : P extends keyof T ? T[P] : never;

function deepGet<T, P extends string>(obj: T, path: P): DeepGet<T, P> {
  return path.split('.').reduce((acc: any, key) => acc?.[key], obj);
}

利用模板字面量类型递归解析路径字符串，实现编译期类型安全的深路径访问。
