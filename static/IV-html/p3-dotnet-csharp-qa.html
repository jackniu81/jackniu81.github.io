.NET / C# 常见面试题 100 道（附答案）

C# 基础

1. 什么是 C#？

答案：
C# 是由微软推出的现代面向对象编程语言，运行在 .NET 平台上，广泛用于 Web、桌面、服务端和云原生开发。

2. 什么是 .NET？

答案：
.NET 是微软提供的开发平台和运行时生态，包含运行时、基础类库、工具链和多种应用开发框架。

3. .NET Framework、.NET Core 和 .NET 的关系是什么？

答案：
.NET Framework 是早期 Windows 平台实现；.NET Core 是跨平台重构版本；现在统一演进为 .NET。

4. CLR 是什么？

答案：
CLR 是公共语言运行时，负责内存管理、垃圾回收、异常处理、JIT 编译和安全控制。

5. CTS 和 CLS 分别是什么？

答案：
CTS 定义公共类型系统，CLS 定义不同 .NET 语言之间互操作应遵守的最小规范集合。

6. 什么是值类型和引用类型？

答案：
值类型直接存储值本身，引用类型存储对象地址引用，二者在内存和复制行为上不同。

7. 常见值类型有哪些？

答案：
常见有 int、double、bool、char、decimal、struct、enum 等。

8. 常见引用类型有哪些？

答案：
常见有 class、string、数组、委托、接口实现对象等。

9. string 为什么是引用类型却表现得像不可变值？

答案：
因为 string 底层是引用类型，但设计为不可变对象，每次修改本质上都会创建新实例。

10. var 是什么？

答案：
var 是编译器的隐式类型推断，变量类型在编译期确定，并不是动态类型。

11. dynamic 和 var 的区别是什么？

答案：
var 是编译期推断，dynamic 则把成员解析推迟到运行时。

12. 什么是装箱和拆箱？

答案：
装箱是把值类型转换为 object 或接口引用；拆箱是把装箱对象再还原成值类型。

13. 为什么装箱拆箱有性能开销？

答案：
因为它涉及堆分配、类型转换和额外复制，会增加 GC 压力。

14. 什么是可空类型？

答案：
可空值类型允许值类型表示 null，写法如 int?。

15. ?? 和 ?. 运算符的作用是什么？

答案：
?? 提供空值合并默认值，?. 用于空条件访问，避免空引用异常。

16. 什么是枚举？

答案：
枚举用于定义一组具名常量，提升代码可读性。

17. 什么是结构体？

答案：
结构体是值类型，适合表示小型、轻量、不可继承的数据聚合对象。

18. 结构体和类的区别是什么？

答案：
结构体是值类型，默认按值复制；类是引用类型，支持继承和多态。

19. 什么是只读字段和常量？

答案：
const 是编译期常量；readonly 可以在声明处或构造函数中赋值。

20. 什么是属性？

答案：
属性是对字段访问的封装语法，便于控制读写逻辑。

面向对象与语言特性

21. 面向对象的三大特性是什么？

答案：
封装、继承、多态。

22. 什么是封装？

答案：
封装是把数据和行为组合在一起，并通过访问控制隐藏内部实现细节。

23. 什么是继承？

答案：
继承允许子类复用父类已有的字段、属性和方法。

24. 什么是多态？

答案：
多态指同一个调用入口在不同对象上表现出不同行为。

25. virtual、override、abstract 的区别是什么？

答案：
virtual 表示可重写，override 表示重写父类虚成员，abstract 表示必须由派生类实现。

26. 抽象类和接口的区别是什么？

答案：
抽象类可包含状态和实现；接口更强调能力契约，支持多实现。

27. 什么时候用抽象类，什么时候用接口？

答案：
有共享实现和公共状态时优先考虑抽象类；需要解耦能力契约时优先接口。

28. 什么是方法重载？

答案：
同一个类型中方法名相同但参数列表不同，称为方法重载。

29. 什么是方法重写？

答案：
子类重新实现父类的可重写成员，称为方法重写。

30. sealed 的作用是什么？

答案：
sealed 用于禁止类被继承，或禁止方法继续被重写。

31. 什么是访问修饰符？

答案：
访问修饰符用于控制成员可见性，如 public、private、protected、internal。

32. public 和 internal 的区别是什么？

答案：
public 可被任何程序集访问，internal 仅当前程序集内可见。

33. 什么是静态成员？

答案：
静态成员属于类型本身，而不是某个实例。

34. 什么是扩展方法？

答案：
扩展方法允许在不修改原类型源码的前提下，为其增加看似实例方法的调用方式。

35. 什么是索引器？

答案：
索引器允许对象像数组一样通过下标访问内部数据。

36. 什么是运算符重载？

答案：
运算符重载允许自定义类型重新定义 +、== 等运算符行为。

37. 什么是记录类型 record？

答案：
record 是更适合表示不可变数据模型的引用类型，默认强调值相等语义。

38. record 和 class 的区别是什么？

答案：
record 默认更适合数据载体和值比较；class 更适合一般业务对象与行为封装。

39. 什么是模式匹配？

答案：
模式匹配允许通过更直观的方式对类型和结构进行判断与解构。

40. switch 表达式相比传统 switch 有什么优势？

答案：
写法更简洁、更偏表达式风格，也更适合结合模式匹配使用。

泛型、集合与 LINQ

41. 什么是泛型？

答案：
泛型允许把类型参数化，提升复用性、类型安全和性能。

42. 为什么泛型优于 object？

答案：
因为泛型避免频繁装箱拆箱，并在编译期提供类型检查。

43. 常见泛型集合有哪些？

答案：
常见有 List<T>、Dictionary<TKey, TValue>、HashSet<T>、Queue<T>、Stack<T>。

44. List<T> 和数组的区别是什么？

答案：
数组长度固定；List<T> 可动态扩容，API 更丰富。

45. Dictionary 和 Hashtable 的区别是什么？

答案：
Dictionary 是泛型集合，类型安全且性能更好；Hashtable 是早期非泛型实现。

46. HashSet<T> 适合什么场景？

答案：
适合去重和高效判断元素是否存在的场景。

47. 什么是 LINQ？

答案：
LINQ 是 .NET 提供的统一查询语法，可用于对象、数据库、XML 等数据源。

48. LINQ 的优势是什么？

答案：
它使查询表达更统一、可读，也方便链式组合和延迟执行。

49. 什么是延迟执行？

答案：
延迟执行指查询表达式在真正枚举结果前不会立即执行。

50. IEnumerable<T> 和 IQueryable<T> 的区别是什么？

答案：
IEnumerable<T> 主要用于内存对象枚举；IQueryable<T> 可让查询表达式继续翻译给底层提供程序，如数据库。

51. First 和 FirstOrDefault 的区别是什么？

答案：
First 找不到元素会抛异常，FirstOrDefault 则返回默认值。

52. Single 和 First 的区别是什么？

答案：
Single 要求结果恰好一个，否则抛异常；First 只取第一个匹配项。

53. Select 和 SelectMany 的区别是什么？

答案：
Select 做一对一投影，SelectMany 常用于把多层集合拍平。

54. Where 的作用是什么？

答案：
Where 用于按条件过滤序列元素。

55. Any 和 Count 在判断存在性上如何取舍？

答案：
判断是否存在时优先用 Any，通常更高效也更符合语义。

委托、事件与异步

56. 什么是委托？

答案：
委托是对方法引用的类型安全封装，可用于回调、事件和策略传递。

57. Action 和 Func 的区别是什么？

答案：
Action 表示无返回值委托；Func 表示有返回值委托。

58. 什么是 Lambda 表达式？

答案：
Lambda 是用于快速定义匿名函数的简洁语法。

59. 什么是事件？

答案：
事件是在委托基础上构建的发布-订阅机制，用于通知状态变化。

60. 为什么事件通常由发布者拥有、订阅者监听？

答案：
这样能保持职责分离，让状态变化通知更加解耦。

61. 什么是异步编程？

答案：
异步编程用于避免阻塞线程，让耗时操作完成后再继续处理结果。

62. async 和 await 的作用是什么？

答案：
它们让异步代码写法更接近同步流程，提高可读性。

63. Task 和 Thread 的区别是什么？

答案：
Task 是更高级的异步抽象，通常建立在线程池之上；Thread 是更底层的线程对象。

64. Task.Run 适合什么场景？

答案：
适合把 CPU 密集型工作放到后台线程执行，不适合滥用于本已异步的 I/O 场景。

65. 为什么不要随意使用 async void？

答案：
因为它难以等待、难以捕获异常，通常只适用于事件处理器。

66. 什么是死锁风险中的 Result 和 Wait() 问题？

答案：
在异步上下文中同步阻塞等待任务结果，可能造成上下文互相等待而死锁。

67. 什么是 CancellationToken？

答案：
它用于向异步操作传递取消信号，实现协作式取消。

68. ConfigureAwait(false) 常用于什么？

答案：
它常用于库代码中，避免不必要地切回原同步上下文。

69. 什么是并发和并行？

答案：
并发强调多个任务交替推进，并行强调多个任务同时执行。

70. 线程安全是什么意思？

答案：
线程安全表示多个线程并发访问时仍能保持数据一致和行为正确。

内存、异常与性能

71. GC 是什么？

答案：
GC 是垃圾回收器，负责自动回收不再使用的托管内存对象。

72. 托管内存和非托管内存的区别是什么？

答案：
托管内存由 CLR 管理；非托管内存需要开发者或外部资源自行控制释放。

73. 什么是终结器？

答案：
终结器是对象被 GC 回收前可能执行的清理逻辑，但时机不确定。

74. 为什么更推荐 IDisposable 而不是依赖终结器？

答案：
因为 Dispose 能显式释放资源，时机可控，性能和可靠性更好。

75. using 语句的作用是什么？

答案：
using 用于确保实现 IDisposable 的对象在使用结束后被及时释放。

76. 什么是异常处理？

答案：
异常处理是通过 try-catch-finally 捕获和管理运行时错误的机制。

77. 什么时候应该捕获异常，什么时候应该抛出异常？

答案：
只有在你能补救、转换或补充上下文时才捕获；否则应让异常继续向上抛。

78. 为什么不要吞掉异常？

答案：
吞掉异常会掩盖真实问题，使排查变困难，甚至造成错误状态持续扩散。

79. throw 和 throw ex 的区别是什么？

答案：
throw 会保留原始堆栈；throw ex 会重置堆栈，通常不推荐。

80. 什么是不可变对象？

答案：
不可变对象在创建后状态不可修改，通常更安全，也更利于并发和缓存。

81. StringBuilder 适合什么场景？

答案：
适合频繁字符串拼接的场景，可减少大量中间字符串对象创建。

82. 什么情况下值类型反而可能更高效？

答案：
小型数据结构、生命周期短、避免堆分配时，值类型可能更高效。

83. 什么是 Span？

答案：
Span<T> 是用于高性能内存切片访问的类型，可减少额外分配。

84. 为什么性能优化要先测量再修改？

答案：
因为很多“优化”只是猜测，先定位瓶颈才能避免无效或有害改动。

ASP.NET Core 与工程实践

85. 什么是 ASP.NET Core？

答案：
ASP.NET Core 是跨平台、高性能的 Web 开发框架，用于构建 API、MVC 和实时应用。

86. 中间件是什么？

答案：
中间件是按顺序处理 HTTP 请求和响应的组件管道。

87. 依赖注入在 ASP.NET Core 中有什么作用？

答案：
依赖注入用于解耦对象创建和依赖关系管理，提升可测试性与可维护性。

88. 常见服务生命周期有哪些？

答案：
常见有 Transient、Scoped 和 Singleton。

89. Scoped 生命周期适合什么场景？

答案：
适合同一个请求内共享状态的服务，如数据库上下文。

90. 什么是配置系统？

答案：
配置系统用于从 appsettings.json、环境变量、命令行等多来源读取配置。

91. 什么是日志系统？

答案：
日志系统用于记录应用运行状态、错误和业务关键事件，便于监控和排障。

92. 什么是最小 API？

答案：
最小 API 是 ASP.NET Core 提供的轻量接口定义方式，适合简单服务和微服务场景。

93. 什么是过滤器？

答案：
过滤器用于在 MVC 或 Web API 执行流程中插入横切逻辑，如鉴权、异常处理和结果包装。

94. 什么是模型绑定？

答案：
模型绑定会把请求中的路由、查询、表单或请求体数据映射到方法参数或模型对象。

95. 什么是 IHostedService？

答案：
IHostedService 用于实现应用后台运行任务，如定时任务或消息消费。

96. 什么是仓储模式？

答案：
仓储模式用于封装数据访问逻辑，但是否需要应结合项目复杂度权衡，避免过度抽象。

97. 什么是单元测试友好的代码？

答案：
通常指依赖清晰、职责单一、外部资源可替换、逻辑可预测的代码。

98. 面试中如何回答 C# 的优势？

答案：
可以从语言现代化、类型系统强、生态成熟、工具链完善和企业级开发能力强几个方面回答。

99. 如何系统回答 .NET 工程问题？

答案：
可以按运行时、语言特性、框架能力、性能、可维护性和工程实践几个维度组织答案。

100. 如何总结 .NET / C# 的核心价值？

答案：
它的核心价值在于以强类型、现代语言特性、成熟运行时和完善生态支持构建稳定、可维护、可扩展的企业级应用。

现代 C# 特性

101. 什么是 yield return？

答案：
yield return 用于迭代器方法（返回 IEnumerable<T>）中，让方法每次 yield return 一个值后暂停执行，调用方通过 foreach 或 MoveNext() 逐步消费。实现惰性求值，不需要一次性生成所有数据。yield break 用于提前结束迭代。适合大集合遍历、流式数据处理和分页生成等场景。

102. ValueTask 和 Task 的区别是什么？

答案：
Task 始终是堆上的引用类型对象；ValueTask 是结构体，在异步操作同步完成（如命中缓存）时可避免堆分配，减少 GC 压力。但 ValueTask 有限制：只能 await 一次，不能调用 .Result 多次，不适合多次等待或存储。适合高频调用且通常同步完成的热路径（如缓存读取、Buffer 操作）。

103. 什么是可空引用类型（Nullable Reference Types）？

答案：
C# 8 引入，通过 #nullable enable 或项目文件配置开启。启用后，普通引用类型（如 string）默认不可为 null，可能为 null 的引用需显式声明为 string?。编译器在可能出现空引用的地方发出警告，帮助在编译期发现潜在的 NullReferenceException，是提升代码健壮性的重要手段。

104. 什么是 init 访问器？

答案：
C# 9 引入，init 属性访问器只允许在对象初始化阶段（构造函数或对象初始化器）赋值，之后变为只读。例如 public string Name { get; init; }。常与 record 类型配合使用，实现不可变对象而不需要复杂的只读构造，比 private set 更严格。

105. 什么是主构造函数（Primary Constructor）？

答案：
C# 12 引入，允许在类或结构体声明处直接定义构造函数参数，参数在整个类体中可用，无需手动声明字段并赋值。语法：class MyService(ILogger<MyService> logger, IOptions<Config> options) { } 。简化了依赖注入场景大量的样板代码，是现代 C# 推荐的简洁写法。

106. 什么是 IAsyncEnumerable<T>？

答案：
IAsyncEnumerable<T> 支持异步枚举，配合 await foreach 使用。适合流式处理异步数据源，如分批从数据库读取（EF Core AsAsyncEnumerable()）、处理消息流、读取大文件，避免一次性加载全部数据到内存。方法中用 yield return 配合 async 声明即可实现。

107. 什么是 Source Generator？

答案：
Source Generator 是 .NET 5+ 引入的编译时代码生成机制，分析器在编译过程中生成额外的 C# 源文件并编入编译。常用于：减少反射开销（如 System.Text.Json 序列化、正则表达式 Regex.GeneratedRegex）、DI 注册代码生成、避免 AOT 兼容性问题。提升运行时性能，减少启动时的动态成本。

108. 什么是 record struct？

答案：
C# 10 引入，record struct 是值类型的记录，结合了 struct 的值语义（栈分配、无堆分配）和 record 的声明简洁性（自动生成 Equals、GetHashCode、ToString、解构等）。record class 是引用类型；record struct 默认可变，readonly record struct 才完全不可变。适合小型数据载体的高性能场景。

109. 什么是模式匹配的常见用法？

答案：
C# 7+ 持续增强的特性。常见模式：类型模式 if (obj is string s)、属性模式 if (p is { Age: > 18 })、位置模式（解构）if (p is (x, y))、列表模式 if (arr is [1, 2, ..])、switch 表达式配合模式。使类型判断和条件分支更简洁直观，避免大量 as/is + 强转组合。

110. Span<T> 和 Memory<T> 的区别是什么？

答案：
Span<T> 是 ref struct，只能在栈上存在，不能存储为字段、不能跨 await、不能装箱；Memory<T> 是普通结构体，可以存储为字段、跨异步使用。两者都表示连续内存片段，零拷贝操作数组/字符串子段，避免 Substring、ToArray 等额外分配。高性能解析、序列化场景常用。

总结
